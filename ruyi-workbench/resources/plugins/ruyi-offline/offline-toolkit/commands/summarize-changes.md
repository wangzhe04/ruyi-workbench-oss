# 总结当前改动

请读取当前工作区状态和差异，输出一份可用于交接或评审的变更摘要。差异三处都要看：`git_status`（未跟踪的新文件显示为 `??`，用 `file_read` 读）、`git_diff`（未暂存）和带 `staged: true` 的 `git_diff`（已暂存；不带时这一侧会被静默漏掉）。

1. 先写用户可感知的变化和解决的问题。
2. 再按模块说明关键实现，不逐行复述 diff。
3. 单列兼容性、数据迁移、安全或性能影响。
4. 列出新增/更新的测试及实际运行结果；未运行的明确标注。
5. 指出与本次目标无关、可能属于用户的改动，不把它们混入结论。

上面点名的是如意工作台 MCP 工具（Claude Code 里叫 `mcp__ruyi__<名>`）；没有这些工具时用等价的 `git status --short`、`git diff`、`git diff --cached` 与 Read。

本任务只读，不提交、不暂存、不修改文件。
