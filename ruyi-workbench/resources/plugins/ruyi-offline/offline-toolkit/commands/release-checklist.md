# 发布前检查

请按当前项目实际脚本完成发布前检查：

1. 核对版本号、变更日志、锁文件和生成产物是否一致。
2. 先找项目写明的发布/检查顺序（CLAUDE.md、CONTRIBUTING.md、README、package.json 的 scripts、CI 配置），运行其中的 lint、类型检查、测试和构建；不自行联网下载依赖。
3. 打包步骤会写入 dist/ 等产物、可能覆盖上一版包：先说明要跑的命令和输出位置，经用户确认再跑。有的打包脚本首次运行会联网（例如缺打包器时先 `npm install`、拉取打包器的基础二进制或 Python wheel）——这只应发生在有网的打包机上；在离线机器上遇到就停下报告，不要设法联网。
4. 检查发行包是否包含运行时、资源、配置模板、许可证和安装/回滚说明。
5. 做最小启动冒烟，记录环境与结果。
6. 输出“通过 / 阻塞 / 未验证”清单，并给每个阻塞项可执行的下一步。

不要发布、上传或推送；除非用户另行明确授权。
