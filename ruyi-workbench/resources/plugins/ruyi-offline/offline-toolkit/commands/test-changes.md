# 验证当前改动

请检查当前未提交改动并做风险相称的验证：

1. 查看状态与差异，三处都要看：`git_status`（未跟踪的新文件显示为 `??`）、`git_diff`（未暂存）和带 `staged: true` 的 `git_diff`（已暂存；不带时这一侧会被静默漏掉）。按功能、测试、文档、配置和生成文件分组。
2. 先找项目自己写明的检查顺序（CLAUDE.md、CONTRIBUTING.md、README、package.json 的 scripts、CI 配置）并照做，从中挑出最贴近改动的测试、lint、类型检查或构建命令。
3. 先跑最窄、最快的相关子集；通过后再决定是否需要更宽回归。耗时很长的全量套件先说明预计耗时，经用户同意再跑。
4. 不修改产品代码；如果验证本身需要改动，先说明并等待确认。
5. 汇总每条命令、退出状态、关键结果和未覆盖风险。

上面点名的是如意工作台 MCP 工具（Claude Code 里叫 `mcp__ruyi__<名>`）；没有这些工具时用等价的 `git status --short`、`git diff`、`git diff --cached`。用 `powershell_run` 跑检查时按预计耗时调大 `timeoutMs`（默认 60 秒）。

不要把“命令能启动”写成“功能已验证”。
