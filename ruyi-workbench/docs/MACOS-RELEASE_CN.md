# Mac 本地／内部试用部署、升级与恢复

适用版本：如意3.0.1，Apple Silicon arm64，本地／内部试用渠道。当前实测主机为macOS27.0.1；macOS14是最低目标，尚未完成实际运行验证。Windows部署沿用原文档。本渠道使用ad-hoc签名，无Developer ID、Apple公证或票据，校验值不证明发布者身份。

## 安装和首次运行

从可信发送方获取同一批DMG及SHA256。核对校验值，打开DMG，将完整的`Ruyi.app`复制到`/Applications`或个人`~/Applications`，等复制结束，推出镜像，再打开安装位置的App。目标机不需要另装Node、Python、Homebrew或Xcode。

下载来源可能触发Gatekeeper。确认来源和校验值后，按系统“隐私与安全性”中实际提供的“仍要打开”流程处理；组织策略不允许时联系设备管理员。不要移除quarantine、关闭Gatekeeper或SIP。当前账号的本地安装成功，不代表真实下载来源首次允许已经验证。

屏幕录制、辅助功能、麦克风等权限由系统与用户控制，按功能需要授予；拒绝时对应功能不可用。不同ad-hoc构建可能重新请求权限或Keychain访问。窗口打开不代表系统授权或所有桌面工具已经就绪。

## 整包升级

1. 保存工作、停止运行中任务，并通过应用退出菜单或Cmd-Q退出所有使用该数据目录的如意实例。默认关窗会继续后台运行，不能以关窗代替退出。使用CLI启动的服务也须正常停止。
2. 记录旧版App、来源清单及校验值。业务数据位于`~/.ruyi-workbench`，或启动时显式设置的`RUYI_HOME`；旧环境变量`WIN_CLAUDE_WORKBENCH_HOME`仅作兼容入口。确认实际数据根，完整复制到独立、受控的备份位置，检查复制结果；不要把备份放入App内部。
3. 使用凭据加密时，另行保存通过现有恢复入口导出的密码保护凭据包及恢复密码。数据目录快照不包含系统Keychain、TCC授权、外部工作区文件或全局CLI配置。备份应按敏感业务数据保护，不发送到公共渠道。
4. 核对新版DMG，先完整复制到新的暂存位置，推出镜像并检查App。保留旧App，例如移入专用的“升级前版本”目录；然后将完整新版App放到原安装位置。中途复制失败时保留旧App重试，不能合并两个App的内部文件。本流程是人工整包替换，不承诺原子替换。
5. 从新版安装位置启动，确认工作台初始化、工作区、会话、配置和所需工具。基础版本号可能相同，应记录`trial-manifest.json`中的应用源码和打包源码，并保留`distribution.json`及`.dmg.sha256`中的DMG校验值。Full/Slim互换会改变依赖能力；旧配置中指向旧包的绝对路径应在迁移中心预览后处理。

管理员可在所有实例退出后使用系统`ditto`完整复制实际数据目录到一个**不存在的新目录**，再核对文件与备份清单。应用运行期间复制不能视为一致性快照。不应对用户目录执行未经核对的自动覆盖恢复。

## 回退和数据恢复

仅换回旧App不会回退业务数据。新版已经写入的数据可能不被旧版理解；不要将“旧App能启动”当作schema回退保证。

先退出新版，完整保留当前数据和新版App，再把升级前的完整备份恢复到一个新的数据目录。管理员可用该目录作为`RUYI_HOME`启动保留的旧App，验证会话、配置与所需能力后再决定切换。恢复时保留升级后数据，升级后新增内容需单独导出或合并；不要让两个实例同时写同一数据根。

当前整包演练覆盖同为3.0.1的不同构建、代表性schema12配置向schema14规范化，以及通过升级前完整快照恢复。没有承诺任意未来schema可直接向后读取。恢复备份时如遇凭据错误，应走密码保护恢复包或重新输入凭据，不能悄悄回退明文存储。

## 从Windows或旧目录迁移

复制工作区到Mac后明确建立映射，例如`D:\Work\项目`对应`/Users/你的账号/Work/项目`。在设置中重新选择真实工作区，并逐项检查MCP的command、args、cwd、环境变量和CLI路径。迁移中心能预览同一相对资源的旧如意包引用改写，保留原文件备份并支持撤销；任意Windows程序路径、盘符和外部脚本不做盲目替换。

Windows DPAPI密文不能在Mac直接解密。迁移前在原Windows环境使用现有密码保护凭据导出，Mac端导入并重新封装到Keychain；无法导出时重新输入凭据。保留原目录，不直接覆盖Mac现有数据。`~/.win-claude-workbench`及旧数据根环境变量兼容不等于Windows路径和密文已经自动转换。

Mac上的旧Windows overlay入口返回明确的平台不支持，不能用force参数绕过；使用上述整包升级流程。

## 清理旧包和保留数据卸载

保留旧包和备份，直至确认不再需要回退。退出App后，在Finder将完整App移到废纸篓，即可保留业务数据卸载。迁移中心的旧包清理在Mac使用原生废纸篓：位于App中的逻辑workbench包会连同整个App移动；仍被引用、仍运行、当前包、包含数据／主目录或无法确认完整结构的目标会被拒绝。废纸篓操作失败不会退化成永久删除。需要恢复时在Finder废纸篓中检查该App并放回；不要提前清空废纸篓。

## 管理与验收边界

转发时保留DMG、`.sha256`、`distribution.json`和`trial-manifest.json`，对应同一变体及构建。许可证、依赖版本和原生依赖清单随App提供。校验、挂载或复制失败应重新获取可信包；不要修改已签名App内部文件。

当前本地试用验收不代替干净标准用户／无开发工具另一台Mac、macOS14、正式签名／公证、真实下载来源Gatekeeper、正式身份Keychain/TCC升级稳定性、Windows同候选回归及P5原未验环境。完整回归的失败、跳过和适用性以该候选的交付记录为准，不能只凭一份说明认定全部通过。
