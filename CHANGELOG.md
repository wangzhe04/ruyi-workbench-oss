### 中文

- **定时任务（第 123 波新增，第 127 波补齐档位与文件夹）**：可以把一件事交给时钟。设置 →「管家」→「定时任务」里点「新建」：只这一次／每天／每周／每月／高级（cron），到点「只提醒我」（不动模型、不花钱）或者「让如意跑一个回合」。每条任务都能**暂停／继续**、**立即运行**（会先二次确认——它不是预演，真的起一个回合、可能花钱）与**删除**（同样二次确认）。安静卡上的「稍后」是真的推迟：它会新建一条 N 分钟后的一次性提醒（分钟数在设置里可改），原来那张卡先收起来。**错过的触发如实显示**：休眠或关机错过了时点，在补跑窗口内按约定补跑一次并标「补跑」，超窗就标「跳过了」并提醒你；进程崩在回合中途时这一次记「结果未知，先核对」——**既不当成功，也不盲目重发**。本版新增两件：每条任务可以单独选**用哪一档模型**（复杂任务 · 强模型／简单任务 · 快速模型／跟随全局主端点），不必为了一条定时任务去改全局引擎；每条任务还会拿到**自己的工作文件夹**，于是两条任务同时到点不再一条等另一条的目录锁。
- **验收说得出「谁说的」（第 124 波）**：线程的每条验收项现在带一枚来源标签——**机器检查**（真跑过你定义的检查并通过，附时间与结果）／**人工复核**（你自己勾的）／**自报完成**（模型说的；机器检查没跑过或没通过会一并写出来）／还没完成。整条线程没有任务账本时显示**未记录验收**，不再显示会被读成「一条都没做完」的 `0/0`。
- **交办原件看得见（第 124 波）**：管家开的线程，线程头下第一条就是**委托书**——目标（你的原话）、验收怎么算、谁在交办、什么时候开始的；点「看原件」跳回管家那一回合的原文。
- **只有回执才算数（第 124 波）**：「已安排／已发送／已建立」这类完成时的话只由处理器回执驱动。系统手上没有回执时说的是「我发起了，但没拿到回执」，**不再替模型把话说圆**。
- **喊停就是喊停（第 125 波）**：你按停过的线程或班组，管家不再自己把它重开——自动重试、自动续跑、自动递话三条路一律降级成一枚按钮。**你自己按那枚按钮仍然照做**：这是「不自动重启」，不是「不许重启」。
- **失败说得出原因（第 125 波）**：线程挂了，管家报的原因与下一步取自工作台自己那张表，不是模型现编的；表从 12 类补到 32 类（`timeout`／`network`／子代理失败这几类最常见的，修前一条都不在表里）。表里没有的类如实说「未知类别」，不许模型补空。
- **旧资料会标出来（第 125 波）**：断网或站点拒答时 `web_fetch` 会回落本地缓存，这种结果的工具卡现在印一枚「缓存 · N 天前抓的」徽标（抓取时间不明时印「缓存 · 抓取时间未知」）。徽标只读结构化字段，模型说什么都改不了它。
- **管家记住的事会过期、也分得清管得着谁（第 126 波）**：管家记忆条目新增**到期日**与**作用域**。过了到期日的条目不再贴进提示词，面板里仍然看得到（标「已过期」，可以改到期日续期，也可以否决）；作用域按**你自己说的话**分「只在这个项目里算」还是「到处都算」，**不拿「它是在哪儿被说的」去猜**。
  **第 107 波补一处漏**：「过了到期日就不再被用上」当时漏了一个地方——管家判断「这句话该递给哪条线程」时**照旧在读过期条目**，于是一条早该过期的关注点会一直把某条线程往上顶。现在这条路也过滤过期了。（作用域**有意**不在这一步过滤：递话预判压根不在任何项目里，它是拿线程标题去记忆文本里找词，不是把记忆当断言用——这一点已用断言钉住，免得以后被当成漏改。）
- **上下文压缩五个新开关（第 126 波，其中三个在本版默认打开）**：L1 蒸发边界改按 token 预算、历史内重复读取去重、摘要 prompt 双语、L2 尾部按完整单元保留、重播种后重附最近读过的文件。真模型配对 A/B 之后，**摘要 prompt 双语（`runtimeSummaryPromptI18nV1`）、历史内重复读取去重（`runtimeHistoryReadDedupV1`）、L2 尾部按完整单元保留（`runtimeReseedTailUnitsV1`）三个翻成默认开**；L1 蒸发边界（`runtimeEvaporateBudgetBoundaryV1`，主指标方向是反的）与重播种重附文件（`runtimeReseedReattachFilesV1`，读数带已知污染、量不出来）**仍然默认关**。每个开关的实测读数写在管理员手册「2.8.0 默认启用清单」一节。
- **语音输入（第 127 波）**：设置 →「模型与服务」→「语音识别（语音输入）」里选一个服务商与模型（只列出模型清单里标了「可语音识别」的模型；没选时输入框根本不画麦克风），**工作台视角与管家视角**的输入框右侧就会出现麦克风：点一下开始说、再点一下结束，转好的文字**插在光标处**、**永不自动发送**，Esc 取消；单次上限 3 分钟，录满自动结束。同时新增：转写端点 `POST /api/audio/transcribe`（本版唯一的新出网面，25 MB 上闸）、**上传音频附件时的尽力转写**（转写失败不挡上传，原文件照旧可下载；转写文本进提示词时带围栏并中和尖括号，当作不可信内容）、以及原生工具 `audio_transcribe`（原生工具数 96 → 97）。
  **这一条要把话说清楚**：如意最初只会说 **OpenAI 形的 `/audio/transcriptions`**，而在开发者自己那台机器上实测的四个候选模型（MiMo `mimo-v2.5-asr`、百炼 `qwen3-asr-flash`／`fun-asr-flash`、混元 `hy-asr-3.0-preview`）**一个都不提供这个端点，四个全部返回 404**。所以本版**补了一个逐服务商的协议开关**：设置 →「模型与服务」→ 展开某个服务商的「协议与能力」→「语音识别协议」，可选 **Whisper 形（`/audio/transcriptions`，缺省）** 或 **对话形（`/chat/completions` ＋ `input_audio`）**。同一台机器上用真 key、经如意自己的转写路由逐个实测：**MiMo `mimo-v2.5-asr` 与百炼 `qwen3-asr-flash` 走对话形都能通、字准确率 100%**；**百炼 `fun-asr-flash` 走对话形仍被拒**（这个模型要走百炼自己的专用转写接口）；**混元走对话形被拒在计费这一步**（账号没给语音识别开通计费；开通后能否转写没验证）。后两个**不承诺**。为了配合对话形只收 wav/mp3 的上游（MiMo 会直接 400 拒收 webm），麦克风录音**上传前一律转成 16 kHz 单声道 WAV**；音频附件与 `audio_transcribe` 工具送的仍是**你给的原文件、不转码**，所以给对话形服务商喂 webm 附件可能被上游拒。**我们仍然不承诺它对任何一家服务商开箱可用**；端点或格式不兼容时界面会明说「转写服务这次没有成功」，输入框一个字不动。
- **服务入口与服务状态（第 127 波）**：内置模板现在各自标明属于哪一类服务——**研究比较／资料整理／产物撰写／代码任务／定时汇总／变化守望**六类（两个纯动作类模板有意留空，**未分类不等于不可用**），并补了一个「定时汇总」模板可直接挂到定时任务上。技能库的搜索框兼做**自然语言入口**：打一句「整理下载」「写代码修 bug」，列表顶部就出一条服务条，说清这一类有几个模板可直接用；需要先配东西时**最多只给一条配置引导**（其余折成「还有 N 项」），这一类真没有模板时如实说「这类还没有模板」；不相关的词零反应，清空即消失。模板状态也从两态改成**四态**：可用／需要配置／不可用（缺网络时给离线的那句人话）／**状态未知**——「这张卡要用的能力还没检测过」以前会被并进「可用」与「不可用」两个相反的方向，现在**未知就说未知**，服务条上的「可直接用」也只数真的可用那几张。
- **`shell_send`／`keyboard_send_keys` 不再被误判成「对外发送」（第 127 波）**：永久豁免的工具名判据以前是裸子串匹配，名字里带 `send` 就中招——于是「往一个已经在跑的本机 shell 里递一行字」被当成「以你的身份对外发帖」，任何档位都得你亲手按，而直接起一条命令的 `run_command` 反而不中招。现在钉的是真正对外发送的那几个整词。**命令正文那道闸一个字没松**（`rm -rf`、`winget uninstall`、`git push` 照旧拦下），而且命中时会告诉你是**哪一类**咬的（删数据／改系统／装卸载／对外发送／推送远端）。
- **管家可以按规则替你批（第 127 波，默认开）**：线程停下来问一个命中永久豁免的动作时，管家现在可以在**十道闸全过**的前提下替你批准：开关开着；这一回合的实效档位是「智能自动」；线程是**管家在看管的**或**定时任务开的**（你自己开着盯的线程照旧问你）；全部命中里**一条底线项都没有**；命令原文完整扫过，且**短到管家能一眼看全**（不超过给它看的那段摘录，300 字——看不见的不准批）；命令里**没有拼接、编码、`iex` 这类间接构造**；删数据类的目标**不含绝对路径**（盘符、根斜杠、`~`、`$env:`、`%变量%` 一律不批，只批相对路径）；管家写下了**理由**；**这一回合（或上一回合而你还没再说话）读过网页时，涉及「对外发送」与「推送远端」的一律不代批**；每小时最多 **6 次**。**永远等你亲手按的底线项**：支付／购买／转账、格式化与分区、关机重启与改启动项、改注册表与防火墙、注册 MCP 服务器、名字本身就是发消息的工具与 `sendmail`，以及把 `/`、`C:\`、家目录整个当删除目标。每一次代批都出**回执**、都记进行动流水（类别、理由、脱敏后的命令摘录），账上说得出这一下是管家批的。**怎么关**：设置 →「管家」→「它可以自己做的事」→ 取消勾选「线程停下来问永久豁免的动作时，管家可以按规则替我批」。**这一项管家自己改不了。**
- **三处本机泄密面与一处「判的与跑的不一致」（第 107 波）**：① 状态路由 `GET /api/status` **只有 host 门、不要 token**，此前明文下发 `modelsApiKey`（Agent CLI 的模型接口密钥）与**全部外部 MCP 服务的 `env`／`headers`／命令行参数**——本机任何一个进程发一次请求就能读到全套凭据。现在这些值一律掩成 `••••后四位`（**键名仍然可见**，你还能看出配了哪几个变量），保存时按「同一个启动目标」还原真值：同一次保存里改过 `command`／`args`／`url` 的条目**不还原**密钥（防「看不见密钥也能把它改接到别的程序或端点上」），要换值就直接填新的明文。② `powershell_run`／`script_run`／`shell_start` 不传工作目录时以前跑在**家目录**，而权限闸判的是**这条线程的工作目录**——模型以为自己在工作夹里，相对路径实际落在家里（一句 `Remove-Item .\tmp -Recurse` 就删到家目录去了）。现在三个工具都只用闸判过的那个目录，**判的就一定是跑的**。③ 脱敏表补齐：`"apiKey": "…"` 这类**带引号的 JSON 键值**以前整把漏网，分段形的 `sk-proj-…`／`sk-ant-api03-…` 也在第一个 `-` 处断掉——这张表同时管着管家看到的命令摘录、审计与会话搜索摘录。
- **第四处泄密面：工作台 MCP 的「读资源」（发布前热修，第 128 波查出）**：工作台自带的 MCP 服务会列出一条「Workbench config」资源，读它时以前把 `config.json` **原样**交出去——明文的服务商 API Key、Agent CLI 的 `modelsApiKey`、外部 MCP 连接器 `env` 里的令牌都在里面。凡是连到工作台 MCP 的模型（Claude 引擎的会话；以及你在 Claude Code 等其他客户端里登记了工作台 MCP 的会话）都能用读资源的工具把它们读走，绕过了上一条的状态路由掩码与文件工具的敏感路径拒读。**这个口子自 v1.4.0（首个开源版）起就在，2.7.0 及更早版本都有。** 现在读到的是与状态路由同一份掩码视图（`••••后四位`，键名仍可见）。**如果你在别的客户端里登记过工作台 MCP，建议轮换那几个密钥**——我们无法知道哪一次会话读过这条资源。
- **首次启动误报「连不上」（发布前热修，用户首启走查）**：首次启动时界面说「无法连接本地服务」，其实服务是通的，新开个线程就好了。查出六处，一并修掉：① 启动时的联网探测会在服务忙着做首启准备（Full 包检测本机 Python 那一段要好几秒）时**把在线的机器判成离线**并记住 60 秒——这期间要联网的工具被隐藏、提示词里告诉模型「当前离线」；现在量不准就记「未知」、只记 5 秒。② 桌面版窗口可能**一直停在转圈页**，标题栏却写着「已连接」（服务比内嵌浏览器组件先就绪时那次打开被跳过、之后再没补上）。③ 启动故障卡以前画在工作台视角的对话区里，**出厂默认的管家视角里根本看不见**，只剩一个两秒的提示；而且不管哪一步出错都说「连不上」，一出错界面此后还不再自动刷新。现在卡浮在最上层、两个视角都看得见；真连不上才说连不上，服务是通的、只是某一步出错时如实说，给「重新加载」与「先继续用」，并且不影响后续的自动刷新。④ 「查看诊断」以前**只有一句话**（服务端的真实原因被翻成一句「服务发生内部错误。」吞掉）；现在写明是哪一步、状态码与请求路径、服务端原话、错误码、调用栈与时刻，能一键复制发给开发者；别处遇到这类内部错误时提示里也带上原话。⑤ 点「重试」后状态栏原样显示「已尝试 {n} 次」、智能体角色设置里显示「已保存：{value}」这类没替换的占位符——已修。⑥ 服务内部没接住的出错以前**不进日志**，应用内「看日志」也找不到；现在会记一条（请求内容不入日志）。
- **撤回点了就是真撤回（第 107 波）**：以前递话后立刻点「撤回」，有概率显示「✓ 已撤回」、那句话其实还在线程里（机器忙的时候更容易撞上）。原因是撤回落盘之后，一份**在撤回之前读出来的**会话副本才落盘，把撤回整份盖了回去。现在这种旧副本写不回去了；同一时刻顺手落盘的线程名、回合结果这类小改动会在撤回之后的新副本上重做一遍，不跟着丢。工作台的「回溯」、线程抽屉的「整单回退」和行动流水里的「撤销」走的是同一处，一并修好。
- **拆分不再建出重复的空事项、刚归类的线程不再闪回「未归类」（第 107 波）**：把线程拆到新事项之后大约 0.2 秒内再拆一次同样的，会多建出一个同名的空事项；刚归到事项里的线程也会在事项列表里短暂显示成「未归类」。原因是会话索引写盘的那几毫秒里，刚改的那一批既不在内存的待写表、也还没到盘上，读的人拿到的是旧索引。现在写盘途中的那一批对读者一直可见，直到落盘；退出时的收尾刷写也会把它一并写进去。
- **单文件 `Ruyi.exe` 用的摘要规则与正常启动不一致（第 107 波打包演练发现）**：`Ruyi.exe` 里打不进规则文件，走的是一份内置副本，而这份副本早就没跟上 —— 中文摘要提示词里有一句话出现两遍，英文界面在 `Ruyi.exe` 下拿到的仍是中文提示词。用 `Start-Workbench.cmd` 或桌面壳启动的不受影响。副本已与规则文件逐项对齐，并加了一把「两边必须完全相同」的锁。
- **存量用户会看到的行为变化（照实点名）**：
  - **怎么从 2.7.0 升上来**：下载 2.8.0 的完整包（Slim 或 Full），**解压到一个新目录**，关掉 2.7.0 后从新目录启动；数据目录不在安装目录里，首次启动自动迁移。**2.8.0 的覆盖包（overlay）套不到 2.7.0 上**（覆盖包只能给同一版本打补丁，预检会按版本拒绝）。旧目录先留着，那就是回退的路；**回退到 2.7.0 之前务必先备份 `config.json` 与 `steward\`**，否则语音识别的配置（模型的能力标签、转写端点与协议）、隐藏的模型名单与管家记忆的到期日／作用域会被 2.7.0 一次启动抹掉，再升回来也找不回（管理员手册 §7.5，本版打包演练实测过）。

  - **管家代批默认开**：从 2.7.0 升上来的「智能自动」用户**不经确认就获得**这个能力（关法见上一条）。这是明确拍板的取舍：用户要这个能力，代价写在这里而不是藏起来。
  - **三个上下文压缩开关会被这次升级一次性打开 —— 包括你此前显式关掉过的**（第 126 波 ＋ 第 107 波 T1）：`runtimeSummaryPromptI18nV1`、`runtimeHistoryReadDedupV1`、`runtimeReseedTailUnitsV1`。**为什么要动你盘上的配置**：这几个键的值在配置文件里永远压过出厂默认，而工作台首次读配置就会把整份配置写回磁盘 —— 于是所有装过 2.7.0 的机器上它们都实打实写着「关」，光改出厂默认一个人也吃不到。所以本版把配置版本号抬到 12，并带一次**只跑一次**的迁移。**你会看到的变化**：① 界面语言设成 English（`locale=en-US`）的用户，从此拿到**英文**摘要（`auto` 与 `zh-CN` 逐字节不变）；② 压缩之后不再出现「尾部一条不留」的空重播种（实测 11 次 → 0 次），**代价是摘要要多跑几趟、摘要费用约 +60%**（实测 ¥1.681 → ¥2.687／6 次配对）；③ 同一个文件在一条线程里读过好几遍时，较早那几份全文换成指针（原件随时回查），L1 单趟多释放 **+70.0%／+40.8%** 的 token。**怎么关**：在数据目录的 `config.json` 里给对应的键显式写 `false`，重启服务。**2.8.0 之后你自己关掉的，以后的升级不会再打开它。**
  - **按「刷新」不再把展开着的「最近几次」收起来**（第 107 波）：定时任务块的刷新键只刷新数据，不再把你正在看的那一格收走。

### English

- **Scheduled tasks (wave 123; model tier and per-task folder completed in wave 127)**: you can hand a piece of work to the clock. Settings → "Steward" → "Scheduled tasks" → "New": once / daily / weekly / monthly / advanced (cron), and at the appointed time either "just remind me" (no model call, no cost) or "let Ruyi run a turn". Every task can be **paused/resumed**, **run now** (with a second confirmation — it is not a dry run: it really starts a turn and may cost money) and **deleted** (also confirmed). "Later" on a quiet card is a real snooze: it creates a one-off reminder N minutes out (N is configurable) and puts the card away. **Missed firings are reported honestly**: a time missed to sleep or shutdown is re-run once inside the grace window and labelled "late", beyond the window it is labelled "skipped" and you are told; a crash mid-turn is recorded as "outcome unknown, check it" — **never counted as success, never blindly resent**. New in this release: each task can pick its own **model tier** (strong for complex work / fast for simple work / follow the global endpoint), so you no longer change the global engine for one scheduled task; and each task gets **its own working folder**, so two tasks firing at the same time no longer queue on one folder lock.
- **Acceptance says who said so (wave 124)**: every acceptance item now carries a provenance label — **machine-checked** (your check really ran and passed, with time and result), **human-reviewed** (you ticked it), **self-reported** (the model said so; whether the machine check never ran or failed is spelled out), or still open. A thread with no mission ledger shows **"acceptance not recorded"** instead of a `0/0` that reads as "nothing done".
- **The original commission is visible (wave 124)**: for a thread the steward opened, the first thing under the thread head is the **commission** — the goal in your own words, how acceptance is judged, who dispatched it, when it started; "view original" jumps back to the steward's own turn.
- **Only a receipt counts as done (wave 124)**: "scheduled / sent / created" is now driven only by handler receipts. With no receipt in hand the system says "I started it, but I did not get a receipt" instead of **rounding the model's claim up for it**.
- **Stop really means stop (wave 125)**: a thread or crew you stopped is not restarted by the steward on its own — auto-retry, auto-resume and auto-relay all degrade to a button. **Pressing that button yourself still works**: this is "no automatic restart", not "no restart".
- **Failures give a reason (wave 125)**: when a thread dies, the reason and next step the steward reports come from the workbench's own table rather than the model's imagination; the table grew from 12 classes to 32 (`timeout`, `network` and sub-agent failure — the most common ones — were not in it at all before). A class not in the table is reported as "unknown class"; the model is not allowed to fill the gap.
- **Stale results are labelled (wave 125)**: when the network is down or a site refuses, `web_fetch` falls back to the local cache, and that tool card now carries a "cached · fetched N days ago" badge (or "cached · fetch time unknown"). The badge reads structured fields only — nothing the model says can change it.
- **Steward memory expires and knows what it governs (wave 126)**: steward memory entries gain an **expiry date** and a **scope**. An expired entry stops being injected into the prompt but stays visible in the panel (marked expired; you can extend the date or veto it). Scope is set from **what you said**, "only in this project" versus "everywhere" — it is **not guessed from where the sentence happened to be said**.
  **Wave 107 closes one gap**: "an expired entry stops being used" missed a spot — when the steward decides **which thread a sentence should go to**, it was still reading expired entries, so a long-stale focus kept pushing one thread to the top. That path now filters expiry too. (Scope is **deliberately** not filtered there: thread pre-routing isn't inside any project, and it uses a memory as a source of words to match against thread titles rather than as an assertion — an assertion now pins that choice so it isn't silently "fixed" later.)
- **Five new context-compaction switches (wave 126; three of them on by default in this release)**: token-budget boundary for the L1 evaporation, dedup of repeated reads inside history, bilingual summary prompt, unit-wise tail retention for L2, and re-attaching recently read files after reseeding. After the paired real-model A/B runs, **three are now on by default** — the bilingual summary prompt (`runtimeSummaryPromptI18nV1`), read dedup inside history (`runtimeHistoryReadDedupV1`) and unit-wise L2 tail retention (`runtimeReseedTailUnitsV1`). The other two stay **off**: the L1 boundary (`runtimeEvaporateBudgetBoundaryV1`, whose headline metric moved the wrong way) and re-attaching files after a reseed (`runtimeReseedReattachFilesV1`, where the reading came out contaminated and could not be measured). Every switch's readings are in the admin guide's "2.8.0 default-enabled list".
- **Voice input (wave 127)**: pick a provider and model under Settings → "Models and services" → "Speech recognition (voice input)" (only models tagged as speech-capable in the model list are offered; with nothing selected the composer does not render a microphone at all), and a microphone appears next to the composer in **both the Workbench lens and the Steward lens**: click to start talking, click again to stop, and the transcript is **inserted at the caret** and **never auto-sent**; Esc cancels; 3 minutes per take, after which it ends itself. Also new: the transcription endpoint `POST /api/audio/transcribe` (the only new outbound surface in this release, with a 25 MB gate), **best-effort transcription of uploaded audio attachments** (a failed transcription never blocks the upload and the original file stays downloadable; the transcript enters the prompt fenced and angle-bracket-neutralised, treated as untrusted), and the native tool `audio_transcribe` (native tools 96 → 97).
  **To be plain about the requirement**: Ruyi originally spoke only the **OpenAI-shaped `/audio/transcriptions`** endpoint, and none of the four candidate models tested on the developer's own machine offer it — MiMo `mimo-v2.5-asr`, Bailian `qwen3-asr-flash` / `fun-asr-flash` and Hunyuan `hy-asr-3.0-preview` **all returned 404**. So this release adds a **per-provider protocol switch**: Settings → "Models and services" → expand a provider's "Protocol & capabilities" → "Speech-to-text protocol", choosing either **Whisper style (`/audio/transcriptions`, the default)** or **Chat style (`/chat/completions` with `input_audio`)**. On the same machine, Tested one by one on that machine with real keys, through Ruyi's own transcription route: **MiMo `mimo-v2.5-asr` and Bailian `qwen3-asr-flash` work over the chat style, at 100% character accuracy**; **Bailian `fun-asr-flash` is still refused over the chat style** (that model needs Bailian's own dedicated transcription API); **Hunyuan is refused at the billing step** (the account has no billing enabled for speech recognition; whether it transcribes once enabled is unverified). **Nothing is promised** for the last two. Because chat-style upstreams accept only wav/mp3 (MiMo rejects webm with a plain 400), microphone recordings are now **always converted to 16 kHz mono WAV before upload**; audio attachments and the `audio_transcribe` tool still send **your original file, untranscoded**, so a webm attachment may be refused by a chat-style provider. **We still promise nothing about any particular vendor working out of the box**; with an incompatible endpoint or format the UI says plainly that the transcription did not succeed and leaves your text untouched.
- **Service entry and service state (wave 127)**: built-in templates now say which kind of service they belong to — **research, organizing, writing, coding, scheduled digests, watching** (two purely action-shaped templates are deliberately left unclassified; **unclassified does not mean unavailable**) — and a "scheduled digest" template was added that plugs straight into the scheduler. The skill library's search box doubles as a **natural-language entry**: type "tidy up downloads" or "write code to fix a bug" and a service row appears at the top of the list saying how many templates you can use right away; when something must be configured first you get **at most one configuration prompt** (the rest collapse into "N more"), and a category with no template says so honestly. Template state also went from two values to **four**: available / needs configuration / unavailable (with the offline wording when the network is what is missing) / **unknown** — "the capability this card needs has not been probed yet" used to be folded into *both* "available" and "unavailable", two opposite directions; now **unknown says unknown**, and the service row counts only genuinely available templates.
- **`shell_send` / `keyboard_send_keys` are no longer mistaken for "sending on your behalf" (wave 127)**: the permanently-exempt tool-name test used bare substring matching, so any name containing `send` was caught — handing one line to a local shell that is already running was treated as posting in your name and needed your finger at every safety profile, while `run_command`, which starts a command outright, was not caught at all. It now pins the whole words that really mean outbound sending. **The command-body scan was not loosened by one character** (`rm -rf`, `winget uninstall`, `git push` are still held), and when it fires it now tells you **which category** caught it (deleting data / changing the system / installing or uninstalling / sending outbound / pushing to a remote).
- **The steward can approve some of it for you (wave 127; on by default)**: when a thread stops to ask about a permanently-exempt action, the steward may now approve it on your behalf provided **all ten gates pass**: the switch is on; the effective profile of *this turn* is "smart auto"; the thread is one the **steward is watching** or one a **scheduled task opened** (a thread you opened and are watching yourself still asks you); **not one** of the matches is a floor item; the command text was scanned in full and is **short enough for the steward to read whole** (no longer than the 300-character excerpt it is shown — it may not approve what it cannot see); the command contains **no indirect construction** (concatenation, encoding, `iex` and friends); a delete-class target carries **no absolute path** (drive letter, leading slash, `~`, `$env:`, `%VAR%` are all refused — relative paths only); the steward wrote down a **reason**; **nothing outbound or push-to-remote is delegated if the thread read a web page this turn** (or last turn, with no message from you since); and at most **6 times per hour**. **Floor items that always wait for your own hand**: payments, purchases and transfers; formatting and partitioning; shutdown, restart and boot-entry changes; registry and firewall changes; registering an MCP server; tools whose very name means sending a message, plus `sendmail`; and treating `/`, `C:\` or your home directory as a deletion target. Every delegated approval produces a **receipt** and is written into the action ledger (category, reason, redacted command excerpt), so the record says it was the steward who approved it. **To turn it off**: Settings → "Steward" → "What it may do on its own" → untick "when a thread stops to ask about a permanently-exempt action, the steward may approve it for me by the rules". **The steward cannot change this setting itself.**
- **Three local disclosure surfaces and one "judged here, ran there" (wave 107)**: ① the status route `GET /api/status` is **host-gated only and takes no token**, and it used to hand out `modelsApiKey` (the Agent CLI model endpoint key) and **the `env`, `headers` and command-line arguments of every external MCP server** in the clear — any process on the machine could read the whole credential set with one request. Those values are now masked to `••••<last four>` (**key names stay visible**, so you can still see which variables are configured), and on save the real value is restored only for the **same launch target**: an entry whose `command` / `args` / `url` changed in that same save does **not** get its secrets re-attached (so "I cannot see the key but I can point it at another program or endpoint" does not work); to change a value, type the new one. ② `powershell_run` / `script_run` / `shell_start` used to run in the **home directory** when no working directory was given, while the permission gate judged **the thread's working folder** — the model believed it was inside the workspace while relative paths landed at home (one `Remove-Item .\tmp -Recurse` deleted from the home directory). All three now use only the directory the gate judged, so **what was judged is what runs**. ③ The redaction table was completed: quoted JSON key/value shapes such as `"apiKey": "…"` slipped through entirely, and segmented keys like `sk-proj-…` / `sk-ant-api03-…` were cut at the first `-`. That same table governs the command excerpts the steward sees, the audit log and session-search excerpts.
- **A fourth disclosure surface: the workbench MCP's "read resource" (pre-release hotfix, found in wave 128)**: the workbench's own MCP server lists one "Workbench config" resource, and reading it used to hand over `config.json` **verbatim** — plaintext provider API keys, the Agent CLI `modelsApiKey`, and tokens in external MCP connectors' `env`. Any model connected to the workbench MCP (Claude-engine sessions, and sessions in Claude Code or any other client where you registered the workbench MCP) could read them with a resource-read tool, bypassing both the status-route masking above and the file tools' sensitive-path refusal. **This has been present since v1.4.0 (the first open-source release); 2.7.0 and every earlier version have it.** The resource now returns the same masked view as the status route (`••••<last four>`, key names still visible). **If you registered the workbench MCP in another client, consider rotating those keys** — there is no way to know which session may have read that resource.
- **First launch falsely reporting "cannot connect" (pre-release hotfix, from a user's first-launch walkthrough)**: on first launch the interface said it could not reach the local service even though the service was up, and opening a new thread made it go away. Six defects were found and fixed: (1) the startup connectivity probe could **mark an online machine as offline** and remember it for 60 seconds when the service was busy with first-launch work (the Full build's local Python detection takes several seconds) — during that window network tools were hidden and the prompt told the model it was offline; an unreliable measurement now counts as "unknown" and is remembered for only 5 seconds. (2) the desktop window could **stay on the loading spinner** while its title bar said "Connected" (when the service became ready before the embedded browser component, that navigation was skipped and never retried). (3) the startup error card used to be drawn in the workbench lens's conversation area, so **it was invisible in the default steward lens** — only a two-second toast remained; it also said "cannot connect" whatever step failed, and any failure stopped the interface from updating itself afterwards. The card now floats above everything in both lenses; it says "cannot connect" only when the service is really unreachable, otherwise it says plainly that one startup step failed, offers "Reload" and "Keep using it", and no longer stops live updates. (4) "Show diagnostics" used to hold **a single line** (the server's actual reason was swallowed into "The service encountered an internal error."); it now names the failed step, status code and request path, the server's own message, the error code, a stack trace and the time, with a one-click copy for sending to the developer; internal-error messages elsewhere now carry the original reason too. (5) raw placeholders such as "Attempted {n} times" after clicking Retry, or "Saved: {value}" in the agent-role settings, are fixed. (6) unhandled server errors **never reached the log**, so the in-app log viewer could not show them either; each one is now logged (request contents are not).
- **Undo means undone (wave 107)**: undoing a hand-off right after it was sent could show "✓ Undone" while the message was in fact still in the thread (more likely on a busy machine). A copy of the session read *before* the undo was saved *after* it and wrote the undo over. Such stale copies can no longer be written back; small changes saved at the same moment (a thread name, a turn's outcome) are re-applied on the post-undo copy instead of being lost with it. The workbench's "Rewind", the drawer's "Rewind the whole thread" and "Undo" in the action ledger go through the same place and are fixed together.
- **Splitting no longer creates a duplicate empty mission, and a just-filed thread no longer flashes back to "Unfiled" (wave 107)**: splitting the same threads out a second time within about 0.2 s of the first split created a second, empty mission with the same name, and a thread that had just been filed into a mission could briefly show as "Unfiled" in the mission list. For the few milliseconds of every session-index write, the batch being written was neither in the in-memory queue nor on disk yet, so readers got the old index. That batch now stays visible to readers until it has landed, and the flush at exit writes it as well.
- **The single-file `Ruyi.exe` used different summary rules from a normal start (found in wave 107's packaging drill)**: the rules file cannot be bundled into `Ruyi.exe`, which falls back to a built-in copy — and that copy had drifted: one sentence appeared twice in the Chinese summary prompt, and an English UI under `Ruyi.exe` still got the Chinese prompt. Starting through `Start-Workbench.cmd` or the desktop shell was not affected. The copy now matches the rules file item for item, with a lock that fails if the two ever differ.
- **Behaviour changes for existing users (named as such)**:
  - **How to upgrade from 2.7.0**: download a 2.8.0 full package (Slim or Full), **extract it into a new folder**, close 2.7.0 and start from the new folder; the data root is not inside the install folder and is migrated on first start. **The 2.8.0 overlay cannot be applied to 2.7.0** (an overlay only patches the version it was built for; precheck refuses it by version). Keep the old folder — it is your way back — and **back up `config.json` and `steward\` before going back to 2.7.0**, or 2.7.0 erases the speech-recognition setup (model capability tags, transcription endpoint and protocol), the hidden-models list and steward memory expiry/scope on its first start, and upgrading again does not bring them back (admin guide section 8.4; measured in this release's packaging drill).
  - **A new thread follows the engine you last used** (wave 123): `newThreadEngine` ships as `last`, so new threads no longer always land on the global engine. Only **your own choices** count (switching from the thread head, turns you started yourself); turns dispatched by the steward or the scheduler are not recorded. If that endpoint is gone, or the CLI engine is no longer detected, it falls back to the global one and writes an audit line. Set it to `global` for the old behaviour.
  - **Steward delegation is on by default**: users upgrading from 2.7.0 on the "smart auto" profile **gain the capability without being asked**. That is a decided trade-off — the capability was asked for, and the cost is written here rather than hidden.
  - **This upgrade turns three context-compaction switches on once — including ones you had explicitly turned off** (wave 126 plus wave 107's T1 cut): `runtimeSummaryPromptI18nV1`, `runtimeHistoryReadDedupV1` and `runtimeReseedTailUnitsV1`. **Why your config file is touched**: the value in `config.json` always wins over the factory default, and the workbench writes the whole config back on the first read — so on every machine that ever ran 2.7.0 those keys sit on disk reading "off", and changing the factory default alone would reach nobody. This release therefore raises the config schema to 12 and carries a migration that **runs once**. **What you will notice**: (1) with the UI language set to English (`locale=en-US`) you now get **English** summaries (`auto` and `zh-CN` are byte-for-byte unchanged); (2) compaction no longer reseeds an empty tail (11 occurrences → 0 as measured), **at the cost of more summary passes — about +60% on summary spend** (¥1.681 → ¥2.687 over 6 paired runs); (3) when the same file was read several times in one thread, the earlier copies become pointers (the original stays one click away), releasing **+70.0% / +40.8%** more tokens in a single L1 pass. **To turn one off**: write `false` for that key in the data root's `config.json` and restart. **Anything you turn off after 2.8.0 will not be reopened by a later upgrade.**
  - **Pressing "refresh" no longer collapses the expanded "recent runs" row** (wave 107): the refresh button in the scheduled-tasks block refreshes the data and stops taking away the row you were reading.
  - Two more factory defaults, named for completeness: **the scheduler master switch is on** (zero polling and zero cost with no tasks) and **the steward master switch is on** (flipped in wave 121; see the correction to the 2.7.0 entry below).
- **Catch-up: these shipped on by default in 2.7.0 and were simply missing from that entry (waves 103–106)**: observation reduction plus on-demand re-read of the original (−81.0% context on real history, byte-identical re-read); session notes externalised and re-injected; summary entity checking and single-shot summaries (overall gate 88.9% / ¥0.1352 against 77.8% / ¥0.1945); estimate buckets; the summary fact table (+56.2pp entity retention on its own item, **but a mixed overall gate in the same round, 66.7% against 77.8%** — stated as measured); append-only tool schemas and tool-result caching (cache hits +17–24pp, tool-phase time down about 64%). All of them can still be switched off explicitly in config.
