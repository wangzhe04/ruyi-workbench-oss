## Preview 2 新增（第 137 波）· New in Preview 2

1. **子代理不再污染主会话。** 主会话只收一份精简的交付结果；子代理的工具调用与上下文压缩留在它自己的卡片里，需要全文时按需取。Spawn Agent 并入 Orchestrate Agent；代理可以后台跑，主会话照常对话，结果只送达一次。
2. **迁移中心。** 启动时把 `~/.claude/CLAUDE.md`、Codex／Kimi 的 `AGENTS.md` 导入核心记忆并保持同步；MCP 自动导入覆盖 Claude Code、Codex、Kimi；读取 Codex、Kimi、Claude Code 插件里的技能；老版本如意不管装在哪都能认出，一键改到新版（备份、可撤销），老包只移进回收站。
3. **每种引擎都知道自己在如意里。** Claude Code／Kimi Code 线程有如意运行环境说明；**随包的 ripgrep 以前从没被用上**，现在模型终端里能直接用 `rg`；模型知道界面会画 Mermaid 图。
4. **管家界面重设计。** 右栏可收起并记住；「打开线程」直接去工作台对应线程、线程头可「回到管家」；更少的控件与噪声；管家沿用事项所在的工作区，如意自建的文件夹不再进常用工作区。
5. **线程与设置。** 运行中不再提前显示本轮总结、有运行指示、左栏不再忽大忽小；设置新增「模型分配」「权限与安全」「用量与限额」，MCP 页签合一，大多即改即存；修了旧草稿回写服务商设置等三个缺陷。

1. **Sub-agents stay out of the main conversation** — only a compact delivery envelope comes back; Spawn Agent merged into Orchestrate Agent; background agents with exactly-once delivery.
2. **Migration center** — CLAUDE.md / AGENTS.md imported as core memory; MCP and skills from Claude Code, Codex and Kimi; older Ruyi installs detected wherever they live, repointed with backup and undo.
3. **Engine briefings** — Claude Code and Kimi Code know they run inside Ruyi; the bundled ripgrep, previously never found, now works in the terminal; Mermaid rendering is announced to models.
4. **Steward view redesign** — collapsible right panel, "Open thread" goes to the workbench, lighter layout, workspace reuse instead of new folders.
5. **Threads and settings** — no premature turn summary, running indicator, stable thread list; new Model assignment / Permissions & safety / Usage & limits pages.

### 七条值得知道的变化

1. **管家成为日常入口。** 一件事项可以关联多条线程，统一管并发、目录锁和预算；管家能直接搜网页、抓页面、读已登记工作区里的交付文件，能把预置流程连同参数交给线程执行。它读过外部内容后，当回合的写动作降为待你确认的提议。
2. **状态说得清。** 提问与权限请求集中进右下角「等你处理」队列；仍在跑的后台命令列在线程输入框上方，能看输出、能停（先确认，且绑定原线程）；后台失联时显示「状态截至 xx:xx」，恢复后自动对账。
3. **语音从入口变成连续体验。** 有本地组件时边说边出字；每句说完可重听、让大模型改字或合成两版；手改过的句子受保护；识别结果从不自动发送。设置里有关闭／轻度／标准／重度／自定义档位。
4. **长任务更接得住。** 观察结果缩减与按需回读、摘要保留事实、重复读取去重；记忆有作用域、到期日与否决；当前指令优先于旧偏好。
5. **多模型与资料输入更顺手。** 模型目录与下拉统一；图片输入支持 Responses 直发、发不出图时 OCR 兜底、大图自动压缩派生件。
6. **输出更好读。** 回复里的 Mermaid 直接渲染，可全屏缩放平移、导出 SVG／PNG；文件搜索内置 ripgrep 快路径。
7. **地基补了。** 修了状态／MCP 资源里的凭据暴露、权限判断与实际执行目录不一致、撤回被旧快照覆盖、同步探测阻塞、进程清理误伤等问题；配置改为只保存你显式改过的键（以后改默认值对存量安装也生效）。

## From 2.6.2 to 3.0: from a task runner to a steward that takes work off your hands

1. **The steward is the everyday entry point.** One matter can span several threads with shared concurrency, folder locks and budget. The steward can search the web, fetch pages, read deliverables in registered workspaces, and hand a preset workflow (with parameters) to a thread. After it has read outside content, its write actions in that turn become proposals you confirm.
2. **Clear status.** Questions and permission requests queue in a "waiting for you" panel; background commands still running show above the thread's input box, with output view and a confirmed stop bound to the original thread; if the backend drops, the status shows "as of hh:mm" and reconciles on reconnect.
3. **Voice input that flows.** With the local add-on, text appears as you speak; each sentence can be re-listened, corrected by an LLM, or merged from both; your manual edits are protected; nothing is ever sent automatically. Presets: off / light / standard / heavy / custom.
4. **Long tasks hold together better.** Observation trimming with on-demand re-reads, fact-preserving summaries, duplicate-read dedup; memories gain scope, expiry and veto; current instructions beat old preferences.
5. **Models and inputs.** A unified model catalog and picker; image input via Responses, OCR fallback when images cannot be sent, automatic downscaled derivatives for oversized images.
6. **Readable output.** Mermaid diagrams render inline with a fullscreen viewer (zoom, pan, SVG/PNG export); file search ships a ripgrep fast path.
7. **Foundation repairs.** Fixed credential exposure in status/MCP resources, permission checks disagreeing with the actual working folder, withdrawals overwritten by stale snapshots, blocking sync probes, and process cleanup hitting the wrong processes; config now stores only keys you explicitly changed, so future default changes reach existing installs.

## 本预览的验证 · How this preview was verified

- 自动化全量回归（390 件 e2e ＋ unit 前置 ＋ 77 件静态锁）：**390 pass / 0 fail / 0 flaky**（发布提交上跑的最后一轮）。
- 冻结前的基线全量抓到 9 件红灯，全部查清根因后修复，其中 **3 件是真的产品缺陷**：「等你处理」列表在线程多时每次刷新慢 0.3 s、别的线程的提问弹窗会抢走正在打字的焦点、选 Kimi CLI 引擎时每次状态刷新都多起一个进程（约 1 s）。其余是测试没跟上此前有意的界面改动。
- Slim／Full 两个 zip 在全新目录解包冒烟（自带 node 与 Ruyi.exe 两条路径），`/health` 与 `/api/status` 报 `3.0.0-preview.1`；Full 包内桌面组件离线载荷完整性校验通过。
- 完整记录：[55 号文](https://github.com/wangzhe04/ruyi-workbench-oss/blob/v3.0.0-preview.2/docs/optimization-plan/55-release-3.0-preview.md)。

- Full automated regression (390 e2e suites + unit precheck + 77 static locks): **390 pass / 0 fail / 0 flaky** on the release commit.
- The pre-freeze baseline caught 9 red suites; all were root-caused and fixed. **3 were real product bugs**: the "waiting for you" list took ~0.3 s per refresh with many threads, questions from other threads could steal focus while you were typing, and with the Kimi CLI engine every status refresh launched an extra process (~1 s). The rest were tests lagging behind earlier intentional UI changes.
- Slim and Full zips smoke-tested from fresh folders (bundled node and Ruyi.exe paths); `/health` and `/api/status` report `3.0.0-preview.1`; the Full package's offline desktop-control payload passes its integrity check.

## 预览版的边界 · What this preview does not promise

- **还没做、正式版前要人来做的终验**：独立安全红队终审（写代码的人不给自己发合格证）；真读屏与人因走查；Full 包在真实桌面上双击启动器（会改动真实配置，留给用户）。
- 「本地工作台」指软件与数据放在你机器上；用云模型、在线检索、云语音时，必要内容仍会发给对应服务。
- 本地语音组件、本地模型需要另外安装（ruyi-toolbox），不在两个 zip 里。
- Human-only sign-offs still pending before 3.0 final: an independent security red-team review, real screen-reader and human-factors walkthroughs, and double-clicking the Full launcher on a real desktop.
- "Local workbench" means the software and data live on your machine; cloud models, web search and cloud speech still send the necessary content to those services.
- The local speech add-on and local models are installed separately (ruyi-toolbox) and are not inside these zips.
