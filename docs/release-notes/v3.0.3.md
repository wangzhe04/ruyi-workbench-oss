# 如意 Ruyi 3.0.3 · 2026-11-19

3.0.3 基于 3.0.2，修复已有加密凭据的用户升级后密钥显示为空、保存设置后仍无法使用的问题。

- 工作台先从凭据库读取服务商密钥、额外请求头和连接器凭据，再迁移配置。保存设置时，加密配置及其上一版备份都继续使用凭据引用。
- 如果 3.0.2 已将加密占位符改写为空对象或空数组，3.0.3 会在校验原记录后恢复。如果用户给同一服务商另填了一把密钥，当前条目保留新密钥，原密钥会出现在带「原凭据库」后缀的服务商条目中。
- 如果凭据库缺失、无法解锁或记录与服务商不匹配，工作台会报告错误并保留已有配置。恢复需要原凭据库和可以解锁它的 Windows 用户账户。

## Windows 下载与升级

先退出旧版，完整解压到新目录，再启动 RuyiDesktop.exe 或 Start-Workbench.cmd。使用原 Windows 账户和原数据目录。Slim 包含工作台、桌面壳和 Node。Full 另含离线 ACC、Python、OCR 和浏览器依赖。两个 ZIP 的校验值见 Ruyi-v3.0.3-SHA256SUMS.txt。

## English

Ruyi 3.0.3 fixes a credential compatibility issue in 3.0.2. The workbench now unlocks and verifies existing vault references before migrating settings. Settings saves keep both the primary configuration and its previous copy encrypted when credential encryption is enabled.

If 3.0.2 rewrote a known placeholder, the workbench restores the value from its authenticated vault record. If you entered a replacement provider key, that key stays on the active entry and the original is available on a separate provider entry. A missing vault, unlock failure, or mismatched provider binding stops the operation and preserves the configuration.

Exit the old version and extract the new ZIP into a fresh directory. Launch RuyiDesktop.exe or Start-Workbench.cmd under the same Windows account with the same data directory. Both ZIPs include the desktop shell and Node. Full also bundles offline ACC, Python, OCR and browser dependencies. The SHA256SUMS file covers both packages.
