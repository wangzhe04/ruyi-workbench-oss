# 管家持续监工与长任务恢复

2026-10-23 修复。3.1 加密适配规划暂停，本次只处理监工、记忆和运行限制。

## 唤醒与推进

`thread.done`、`thread.needs_you` 和 `thread.adopted` 都会补拍收件箱；成败账落定后通过 `StewardHooks.onThreadSettled` 再补拍。收件箱继续负责去重、合并和游标，不另建第二套任务执行器。

被看管线程的完成事件不再因用户坐在另一条线程而被丢弃。用户正查看提问/权限、明确停止、关闭看管、目标权限及费用预算仍按现有规则判定。普通“要继续吗”只表示继续原任务，不等同于新增授权；真正的问题和正式待决继续走原来的决策通道。

一批事件里的所有线程都会被检查，不再把第 4 个目标降级给用户，也不再截掉第 6 个结构化动作。线程正常收工后检查任务是否完成；计划与工具结果连续三轮都没有变化才暂停自动续跑。仅凭一次 todo 没打勾不算停工理由。

启动时从线程事实重建未完成任务的处置机会。已停止、已完成、不再被看管、仍在运行或由事项驱动器持有的任务不自动恢复。小时/日预算暂时触顶时保留队列并定时重判。

## 记忆与上下文

管家对话默认 `forever`，到访间隔仍为 60 分钟；到访不等于遗忘。用户选择的短保留策略继续有效。交接文字 `stewardWatchNote` 随对应线程保存，每个管家回合从线程重新加载，不依赖偏好记忆或压缩摘要是否保留了原话。

主会话、管家和子代理的默认上下文至少 1,000,000 token。管家默认预算从 200,000 调到 1,000,000；名称猜测不再把未知后续模型压成 128K/200K。手动窗口、上游探测和真实超窗学习仍能收紧实际窗口，压缩比例仍可配置。前端用量表采用同样的默认口径。

用户明确写入的长期记忆默认不过期，行动经验默认 30 天；记忆块按相关性和字符预算注入，不等于数据库到期删除。监工委托独立于这两类偏好记忆。

## 运行限制审计

| 旧规则 | 当前规则 |
|---|---|
| 普通/长任务最多 300/1000 次工具迭代 | 有新的成功工具进展就按检查点扩展；陈旧或重复调用仍受防循环规则限制 |
| 自动续跑最多 2/5 次 | 无固定次数上限，按计划与工具结果检查无进展 |
| 后台代理最多连续唤醒父线程 6 次 | 新交付持续唤醒，每份交付仍只处理一次 |
| 内置 CLI 角色隐式携带 100/150 回合上限 | 新 CLI 节点默认不传该上限，明确配置的节点预算仍有效 |
| 子代理默认 30 分钟催收尾、60 分钟硬停 | 默认关闭总时长收尾；用户明确设置的时限继续生效 |
| 管家每回合深读最多 6 次 | 不限次数，保留总字符预算 |
| 每批最多处理 3 条线程、执行 5 个动作 | 全部按对应线程权限处理 |
| 5 批无需动作的通知之后等用户重新唤醒 | 不再因此停止监工 |
| 管家端点故障重试三次后丢弃本批处置机会 | 保留事件，指数退避，最长每分钟重试 |

保留资源并发、上下文/输出大小、明确的小节点预算、空闲看门狗、错误重试保护、权限与金额预算。这些约束与正常任务持续推进分别处理。

## 验证入口

`unit/steward-supervision.test.js` 覆盖 9 个线程同批处理、8 次深读、7 轮自动续跑、持久委托注入、恢复排除已停止线程、连续无进展、1M 默认及显式小窗口。相关 e2e 为 `steward-continue-unfinished`、`steward-tools`、`steward-runner`、`steward-stop-respected`、`adaptive-budget` 和 `agent-wake`。
