# 文档分类与维护规则

本仓库按“用户操作、开发契约、当前规划、历史证据、生成清册、运行时资源”维护文档。[文档导航](README.md)是阅读入口，[发布与迭代路线](OPTIMIZATION-ROADMAP.md)是当前范围入口。分类依据用途，不按文件修改时间判断是否过期。

## 各类文档的用途

| 类别 | 位置 | 维护方式 |
|---|---|---|
| 产品和操作手册 | 根 README 中英版、`ruyi-workbench/README.md`、`ruyi-workbench/docs/manuals/`、离线部署和升级说明 | 描述当前可用行为、实际入口和能力边界。区分已发布包与源码未发布功能；相关中英版本一起更新 |
| 开发与安全契约 | CONTRIBUTING、CLAUDE、SECURITY、工程规范、Mission Schema、模型工作流、MCP 文档 | 随行为、接口和工程约束变化维护；安全能力以实现和测试为据，保留已知限制 |
| 当前规划 | 路线图、优化方案索引、86 号 3.1 补完与隐私路线 | 标明待实施、依赖、验收和暂缓；不把规划写进用户手册作为已具备功能 |
| 历史证据 | `docs/archive/`、带日期的审计、旧优化方案、旧 UI 概念、源码阅读和视觉审阅记录 | 保留原始日期、基线、决定和结果；页首说明适用时期。修链接可以，不能将未通过改成通过 |
| 生成清册 | facts、路由、模块依赖、架构契约快照 | 运行对应生成器；不手改数值、生成时间或表项。存储清册和文本锁清册仍需随代码登记 |
| 运行时内容与数据 | 随包技能 SKILL.md、命令和提示词、语言包、语音样本文本、依赖清单 | 属于产品行为或测试输入；文档清理不重写其语义。按相应功能测试和发布流程维护 |

许可证、第三方声明、贡献准则和安全联系信息保留各自职责，不因界面迭代移动或合并。自动生成 mockup、截图和历史方案中的代码片段按记录时点解释；当前界面以产品及相关浏览器测试为准。

## 事实来源

| 问题 | 优先核对 |
|---|---|
| 当前源码版本 | `ruyi-workbench/package.json`、启动常量与 `facts.json` 一致性 |
| 某功能是否已经发布 | 对应 Release 记录、发布说明和安装包；不能只看源码版本或标签 |
| 已合入但未发布什么 | CHANGELOG 的 Unreleased 与提交记录 |
| 工具和测试数量 | `facts.json` 及其生成器；数字需要说明是注册全集、默认回归还是 live probe |
| 后端模块与路由 | `app/src/manifest.json`、生成的模块依赖与路由清册 |
| 安全和恢复边界 | 当前源码、SECURITY、行为测试；原子替换不等于断电绝不丢失，文件检查点不等于命令副作用可撤销 |
| 接下来做什么 | 当前路线图及其指向的方案；历史文档里的“下一波”不是今日排期 |

旧审计记录包含缺陷不表示缺陷至今未修，正式发布也不表示所有旧验证已经完成。保留“代码确认”“隔离复现”“真实模型验证”“真浏览器验证”的区别。

## 链接和归档

仓库文档使用相对文件链接。需要 GitHub 源码行定位时使用 `file.js#L123`，不用 `file.js:123`；历史行号必须说明基线。当前方案优先使用“文件加符号名”，避免行号漂移。

移动文件之前检查来自文档、源码、测试和打包脚本的引用，移动后修正文内相对路径。按维护用途将历史证据归入 `docs/archive/`，现行规范、候选研究和运行时入口保留各自位置。固定被运行时、构建或 harness 消费的路径，须先迁移消费者；无法确认时保留并记录原因。保留兼容路径时要写清真正入口，避免出现两个“当前”版本。

旧路线正文已经保存在[3.0 历史路线](archive/OPTIMIZATION-ROADMAP-HISTORY-3.0.md)。截至 2026-10-21，69 篇历史方案见[归档索引](archive/optimization-plan/README.md)，现行设计与候选研究见[方案索引](optimization-plan/README.md)。历史测量 JSON 因 live harness 默认输出路径仍被消费而保留原地；临时日志与用户数据先核对归属和依赖，再归档，不作为杂物删除。只删除可确认重复且无独立证据价值的文本；基准数据、原始决定、审计记录不作为杂物删除。

## 修改后的检查

1. 核对变更是否同时影响中文、英文、用户手册、管理员手册和打包附带说明。
2. 检查本地文件链接、图片资源和引用式链接；跨文件标题锚点必须指向真实标题，示例链接不能混入实际导航。
3. 运行 `git diff --check`。涉及产品数字、手册约定和文案时，按范围运行 `facts.static.e2e.js`、`manuals.e2e.js`、`copy-terms.static.e2e.js` 和 `i18n.static.e2e.js`。
4. 涉及自动生成内容时执行生成器，再运行对应校验；纯文档修改不重复全量产品测试，不把此前的测试结果记为本次新结果。
5. 阅读新入口和相关子页，确认“现行、待实施、候选、历史、已发布、未发布”没有互相矛盾。

本地链接检查只证明仓库路径可解析，不证明外部网站可用、下载包存在或历史结论仍适用于当前实现。
