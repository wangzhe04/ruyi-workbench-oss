## 用户旅程与边界

在指定助手回答下点「存为一键任务」，先明确选择认可成果、关键纠正、下次可变输入和验收项，再让 provider 提炼。纠正来自同会话中明确选中的用户原话，也允许成果之后补充的要求；不自动采用最近一条无关问题、其他成果的文件或系统唤醒。成果最多列最近 12 条、用户原话最近 24 条；成果上限 6000 字符、纠正上限 4000 字符，过长来源不暗中截断后起草。首版提炼所选回答和该轮列出的产物路径，不自动读取外部产物全文。

草稿展示标题、说明、任务规则、1–12 个必填输入以及 1–8 条验收项，显式保存前不会落成 Playbook。规则可编辑、恢复打开时的内容或取消；从技能库「复制并修改规则」使用新 ID，原做法保留，取消副本不改原版。此片不建通用版本账本，不自动覆盖原版或内置模板。

运行入口显示所选验收项与「在新材料上验证」。用户填本次材料和输出路径后，经原参数替换、普通线程、原权限和文件工具执行；管家仍可通过既有 brief.playbook 交办。新材料必须重新读取、计算与检查，不能复制来源任务的数值或结论。缺参按原入口拒绝，不补猜路径。做法元数据始终是 unverified；保存、一次模型自检或历史成果不升级为跨材料机器验收。用户仍需核对本次产物，机器检查与模型自报保持原区别。

起草仍依赖配置中的活动 provider；无 provider 时返回明确不可起草且不耗模型名额，不承诺 CLI 起草等价。既有无 selection 的草稿调用保持兼容；自然语言管家工具增加 sources/draft 与显式 selection，先看来源再选择，不凭模型猜测用户认可哪份。定时冻结模板及参数快照仍是下一候选，此片未接 scheduler。

## 实现与失败处理

来源引用是会话身份、消息位置、角色、原文、回合及摘要的 SHA-256；起草完成重新读取并核对所选引用。来源变化拒绝迟到草稿；后来无关消息不会替换用户的明确选择。选择无效、参数名非法、重复键、验收项缺失或未声明占位符在相应校验处拒绝，不能静默丢弃输入后保存坏模板。验收段由正常化器加入原 promptTemplate；修改检查时替换旧段，普通 UI 与管家共享现有执行器，不另开执行通道。

新 UI 叶模块 `playbook-reuse.js` 注入原 API、弹窗、文案和刷新依赖；保留现有表单和主题。异步导入和响应检查当前会话／弹窗存活，切换任务或取消后不复活旧编辑器。保存失败保留编辑值并允许重试，成功才关闭并刷新。复用原 POST /api/playbooks/draft 和 POST /api/playbooks，没有新路由、工具或独立存储。模块已登记 overlay；后端修改在 src，生成 server.js 与清册随提交保存。
