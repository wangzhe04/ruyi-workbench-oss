## 交付范围

用户在管家输入区手选已有任务后，可带已上传材料继续办理。复用 `handOff → steward_thread_continue → stewardRelayDeliver → stewardLaunchTurn → runSessionTurn`；不另建上传、任务或回合系统。

- 仅目标空闲、可以启动新回合时支持附件。执行中、排队、等待回答或审批时整次拒绝，文字和附件均不递送；原行保留原话、附件和目标，并提供核对与同一次重试。当前没有为插话或回答通道增加附件协议。
- 服务端以 `id/name` 重新定位上传目录内的真实文件，校验存在、文件类型与目录包含关系，重建大小和文本文件预览，不使用客户端路径或大小。图像/音频保留类型及上传端提供的有界 OCR/转写预览，预览仍属于用户资料，不作为服务端核验事实。附件仍位于上传目录，由既有附件管线交给目标线程，工作区不会被切换。
- 回合启动再次检查目标仍存在且工作区未变化；失效时不自动创建新任务。未登记回合不返回递送成功。
- 重试复用原 attemptId 和附件记录，成功及在途回执绑定请求内容指纹，目标或内容变更必须另发一次；工具明确拒绝（外层 `ok:true` 但 `executed:false`）不再记入成功回执。模型输出或 HTTP 200 不等于动作成功。
- 回包丢失继续使用 70 号的核对/重发路径。附件显示在原用户行和待重试行，重试不覆盖新输入草稿。

搜索结果新增 `scope`，明确 `fullText:false`、8192 字符/会话、用户消息 400 字符、助手消息 240 字符，以及大正文头尾各 1 MiB 的采样边界。关闭索引时标记 `metadata_only`。管家候选面板展示“未找到不代表从未做过”，工具说明提示使用已有线程分页读取核对。没有扩大索引或新增全量扫描器。
