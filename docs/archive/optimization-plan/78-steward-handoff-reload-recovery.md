## 恢复与执行边界

手选目标递话在清空输入区之前，将 attemptId、目标、原话、上传引用和修订来源同步保存到本标签页 sessionStorage。首次可执行请求前，再保存服务端返回的实例和十分钟窗口。存储不可用、损坏或达到 20 条／256,000 字符容量时拒绝新增，保留输入、附件和目标，不悄悄淘汰未确认记录。缓存不是服务端执行账本，不包含额外授权，不跨标签页同步；关闭标签页后的恢复不作承诺。

刷新或重新进入管家后，按原 attemptId 恢复原话、附件与待核对行，不自动执行、不自动重发。可只读核对、显式取回原话及附件、显式移除记录；取回时若输入区已有草稿，不覆盖它。取回不会发送；再次发送属于用户另行决定，界面要求先查看原任务。记录成功结算或用户明确移除时只清该项，其他未确认递话保持。

原页面内的同次重试仍复用 attemptId。服务端保留原内存幂等账，新增窗口和淘汰水位：同实例、有效期限、且该窗口之后没有可能抹掉相关回执的淘汰，缺失才可证明 not_applied。已有回执只重放；inflight 共用原 promise；实例变化、TTL 或容量淘汰后的缺失保持 unknown，不能重新执行。过期和容量删除都推进水位，宁可要求人工核对，也不把查不到说成未执行。旧无窗口工具调用保持兼容，不把旧接口升级成持久 exactly-once 承诺。

只读核对返回 applied／inflight／not_applied／unknown，applied:false 的旧兼容字段不独立作为安全重试证据。新 UI 携原窗口；未知、失效和服务重启不会更新旧窗口来绕过守卫。没有新增路由、工具或持久化服务端幂等系统。

## 回执收敛和复核

真实 HTTP 的 replayed 位于顶层，前端原来读嵌套 result，导致安全重放后仍新增递到回执和撤回入口，现按真实信封结算原行。核对与重试成功都更新主气泡、状态和按钮；切视角后迟到成功按 attemptId 结算已恢复行，不再追加新成功行或撤回。新会话代数变化、离开管家也不能由旧请求强行聚焦新视图。

独立 agent 审查发现并推动修复错误码未从 net.api 的 JSON 错误信封解包、迟到成功留下旧 unknown、HTTP 重放标记层级错误，以及重试后主气泡未收敛。新浏览器断言进一步发现切视角不会递增 conversationGeneration，已增加“已结算恢复行”的守卫。恢复阶段读缓存失败单独提示未知，不套用新增请求的“本次未发送”。
