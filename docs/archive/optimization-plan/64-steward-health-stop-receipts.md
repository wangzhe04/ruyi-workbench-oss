## 本批设计

### 运行故障和读取质量分别表达

工具箱已有持久化失败、空闲中止和资源阻塞提示，但班组总览没有接齐。`agent-workflows.loadAgentRuns` 的详情读取失败会被转换为 null：有缓存时悄悄保留旧内容，首次加载时则可能丢掉该运行。顶层错误只临时覆盖工具箱文字和班组用量区，下一次重绘会擦掉提示。

本切片复用同一份运行快照，在工具箱和班组分别显示运行故障与读取质量：

- 运行故障由共享纯判据读取已有 `persistenceDegraded`、`idleAborted` 和资源阻塞证据，可同时显示，不用一个条件分支遮住其他故障。
- 读取质量作为客户端附属元数据，不写入运行快照或业务五态。失败保留上次读取的数据并说明过时；首次详情失败只展示摘要中确知的身份，不把缺失详情伪装成空班组。
- 只有有效且身份匹配的成功响应能清除失败提示，权威空列表才清空。畸形 HTTP 200 不算成功。旧请求、换会话前的迟到响应不得覆盖当前数据和读取质量。
- 不新增轮询器或编造服务端版本；沿用现有刷新通道、样式与交互。故障提示在视图切换与重绘后仍保留，恢复后及时撤除。

本批先完成工具箱和班组的最小闭环。`13d.missionRunDigest` 与管家全局投影的故障字段接线、SSE 重连换进程后的权威重取仍单列后续切片，不以此宣布第一轮故障一致性全部完成。`06i` 与 `mission-state` 五态保持原判据。

### 停止回执必须有证据

现有 `stewardThreadStop` 将 null 或 `{ok:true, stopped:false}` 当成功，UI 因此可能报告并未发生的停止。停止操作仍复用既有 `/api/stop`，本批统一回执判据：

| 回执 | 用户应看到的结果 |
|---|---|
| 明确 `stopped:true` 或 `queuedStopped:true` | 停止请求已受理；不把请求受理当作进程已经退出 |
| 明确 `stopped:false` 且无队列取消 | 当前没有正在运行的任务，不伪报成功 |
| 缺失、畸形或传输中断 | 停止结果未确认，核对状态；不自动重复发送 |
| 明确拒绝 | 保留失败原因，不伪报成功 |

同一目标的在途重复点击不应重复发请求；不同目标不能相互阻塞。只读刷新不改变回执事实。既有行动日志只在实际发起停止后记录的边界保持不变。

**身份绑定不纳入本切片。** 审计发现看板卡片 `turnSeq` 未必与活回合一致，队列只有 `sessionId/enqueuedAt`，没有可直接复用的队列请求身份。隔离探针复现了携带旧 `turnSeq=1` 的停止请求仍停止当前 `turnSeq=2`：现有接口并未使用该字段校验。后续应把现有 driver 身份贯通仲裁与读面，先验证再停、撤权和取消队列；不得通过异步读旧磁盘快照宣称原子校验，也不能用本批回执修正代表已经防住所有旧按钮误停新回合。
