### 输入 3:兼容、离线升级/回滚、双壳成本与退出期限 ✅ 可接受

## 4. 建议:**GO(有条件)**

条件(冻结范围时逐条写死):

1. **性能门前置**:P2 新壳层 Preview 公开前,EC-D 性能硬门(真实 Edge 首屏 <1.5s、视图切换 P95 <200ms、事件流增量渲染)必须对新壳层复跑通过(go 条件 #8 的唯一缺口)。
2. **双壳退出死线入发布计划**:新壳层默认后最迟第 2 个公开 Release 退出经典壳层;退出前交付数据导出 + 回滚说明 + 兼容报告。
3. **全局「需要你」的决策动作**列入 P3 显式范围(当前只读聚合 + 各会话经典 UI 决策;跨会话决策 UI 不得绕过现有 decision 端点与幂等语义)。
4. **残余架构债挂号**:provider 回合进行中经路由突变 mission 可能被回合收尾盖回(第72波记录在案);P1 schema 冻结时一并评估,不得带入 3.0 静默放大。

## 5. 冻结建议(范围 / 兼容策略 / 时间表)

- **范围**:Pretender 3.0 = 概念稿 §8.2 六目标;非目标照 §8.3 原文冻结(不引云账号/协作/移动端/遥测;不为大版本而重写执行资产;不绑定前端框架;不用模型摘要冒充权威状态)。
- **阶段**:P0 ✅(本波)→ P1 领域基础:补 schema 冻结文书(mission.id 主键决策、interventionIds 反向引用、事件语义)+ 残余竞态评估 → P2 新壳层 Preview(原始镜头先行 + 经典切换 + 性能门复跑)→ P3 完整任务交付(全局需要你决策、班组图、叙事镜头、收工卡)→ P4 硬化与切换(双壳退出)。
- **兼容策略**:双壳读同一聚合 API;旧会话只读适配维持「绝不回写」;原 `/api/mission`、`/api/agent-runs`、检查点调用方在双壳期持续有效;数据迁移/壳层切换/应用升级各有独立回退路径。
- **版本纪律**:P2 Preview 前不把 Pretender 名/3.0 版本号混入用户界面与发布物(概念稿 §8.3);Escapade 2.x 继续按既有发布门迭代(2.3 候选 = EC-E 数据层,与 Pretender 正交,可先行发布)。

## 6. 遗留缺口(诚实清单,P1+ 必须跟踪)

1. 全局收件箱只读;跨会话决策仍回各会话经典 UI(P3)。
2. 需要你类型未含「停滞/停工卡」(概念稿 §2.4):停滞检测信号在 driver 内,尚未投影成 Intervention(P3 决策:是否新增 intervention type 'stall')。
3. 叙事镜头未建;规则折算函数未写(V3 前只承诺「工具动词人话化 + 时间线」)。
4. mission.id 独立主键 vs sessionId 事实主键:P1 schema 冻结点,影响「一单多会话」目标(§8.2-1 要求一张任务单关联多次会话——当前投影是 1:1)。
5. 新壳层性能未实测(go 附加条件 #1)。
6. provider 侧 mission 写并发残余竞态(第72波挂号)。
