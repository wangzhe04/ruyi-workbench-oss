# Escapade · 回合叙事化对话设计

> 状态：**第54波已完成（P1）**
>
> 原型：[mockups/v4-turn-narrative.html](mockups/v4-turn-narrative.html)
>
> 适用：Claude CLI 与 OpenAI 兼容引擎，共用一套数据协议和渲染器。
> 不改变：一个任务一个大对话框、现有毛玻璃视觉基线、消息末尾的工具/变更/产物复盘能力。

> 已落地：双引擎 `message.segments`、流式/静态同序渲染、权限/提问/计划/工作流/Mission 终态复原、长工具折叠、尾部工具索引与键盘定位、宽屏消息面、滚动锚点、`role="log"` 和双主题像素回归门 v2。全应用拆域与 CSS 全量分层转入 EC-D 第55波后半。

## 1. 设计结论

当前界面把一次助手回合拆成了“文字消息 / 工具卡 / 后续文字消息”三块平级内容。用户看到的是系统事件的分栏，而不是一个人在完成任务时自然地“先说一句、做几件事、再接着说”。

Escapade 应把**一次用户请求对应的一次助手回合**作为最小视觉对象：

```text
┌ 如意 · Claude CLI / Provider ───────────────────────────────┐
│ 我先核对路线图和现有消息结构。                               │
│                                                             │
│  ┌ 已读取 Optimization Roadmap · 完成 0.4s ──────────────┐  │
│  └────────────────────────────────────────────────────────┘  │
│                                                             │
│ 现状的根因是文字和工具分别追加到两个容器。接下来我再确认……   │
│                                                             │
│  ▸ 并行完成 3 项：检查双引擎事件、消息持久化、工具折叠        │
│                                                             │
│ 建议采用“回合叙事容器”，保持一个大框，但让过程自然穿插。       │
│                                                             │
│ ── 本轮记录 · 4 次工具 · 2 个文件 · 1 个产物 · 18.6s ─────  │
│  工具记录（可展开）                                          │
│  变更与撤销                                                   │
│  [设计稿.md  打开  定位]                                     │
└─────────────────────────────────────────────────────────────┘
```

这不是把所有技术日志铺进正文。正文承担叙事，工具记录只作为紧凑的“动作插页”；完整审计仍统一放在回合末尾。

## 2. 信息结构

### 2.1 外层：一轮只有一个助手框

- 头像、引擎徽标、消息操作、用量只出现一次。
- 思考、文字、工具、计划、询问、子代理、错误均是该框内的**有序片段**。
- 全屏回合阅读面扩到 `min(1320px, 94%)`，窄屏仍随视口收缩；不引入 vNext 的任务单外壳。
- 用户插话仍是独立的用户消息，但在助手框内留下一个小型“已接收插话”的边界标记，能看出它在哪个动作之后生效。

### 2.2 中层：按真实事件边界分段

片段顺序来自事件流，不靠句号、换行或前端猜测：

| 片段 | 展示 | 默认行为 |
|---|---|---|
| `text` | Markdown 正文 | 相邻文本增量合并；遇工具/决策事件封段 |
| `thinking` | 线性轨迹图标 + “思考中 / 思考 · N 字”轻量行 | 活跃时展开；遇正文、工具或任一语义事件即收起，不打断正文层级 |
| `tool` / `tool_batch` | 紧凑动作行 | 成功收起，运行中与失败始终可见 |
| `plan` / `ask_user` | 决策卡 | 保留现有交互，作为叙事断点 |
| `subagent` / `workflow` | 子任务行或进度卡 | 默认摘要，失败不收起 |
| `note` / `error` | 中性提示或错误 | 原位显示，不挪到整轮末尾 |

每次工具开始都会结束当前文字片段；工具完成后的首个 `assistant_delta` 会创建新的文字片段。因此模型在工具前后说的话能回到它们真实发生的位置。

### 2.3 内联工具：小、可读、可收

单个工具默认是一行，目标高度 `28px`：

```text
✓ 读取 Optimization Roadmap                  120 行 · 0.4s  ▸
```

- 简易模式显示人话动词与关键对象；专家模式额外显示原始工具名。
- 参数只保留一个关键对象（文件名、命令摘要、URL、工作表名）；原始 JSON 在详情内。
- 结果只显示可验证摘要（行数、文件数、退出码、尺寸、状态），不把大段返回值铺开。
- 点击行可展开现有工具卡的输入、结果、diff 与复制操作。
- 所有工具无论运行、成功或失败都默认收起；失败通过红色状态与左侧细线外露，但不自动抢开详情，用户可按需展开。

连续工具的折叠规则：

| 数量/状态 | 内联展示 |
|---|---|
| 1–3 个顺序调用 | 各一行 |
| 2 个以上同批并行 | 一个“并行 N 项”组，展开看每项 |
| 第 4 个及以后 | 已完成项自动并为“已完成 N 项”；当前运行项留在外面 |
| 任一失败 | 失败项保留红色状态并默认收起；成功项照常折叠 |

### 2.4 段落节奏

- 正文段落：现有 Markdown 段距从 `.55em` 调到 `.72em`。
- 思考片段取消整框虚线和脑形 emoji，改为 26px 冷色轨迹摘要行；展开内容以细左线承载，完成后只保留一行。
- 工具片段同步降为 28px 过程行，取消厚重整框；输入/结果留在展开层，单项与批量工具组全部默认收起，失败只外露红色状态。
- 文字片段之间不额外套卡；工具边界提供 `10–12px` 留白。
- 连续工具行间距 `4px`，工具组与正文间距 `10px`。
- 大标题、代码、diff 仍使用实色阅读面；不增加新的模糊表面。
- 流式光标只出现在当前文字片段，不挂在整轮末尾。

“活人感”来自叙述连续性和呼吸节奏，不来自伪造“我正在努力”等状态文案。界面只显示真实事件。

### 2.5 长过程的阶段收纳

模型连续进行“思考 → 工具 → 思考 → 工具”且暂时没有正文输出时，这些片段仍按真实时间顺序记录，但不再逐行占满整屏：

- 同一正文断点之后，累计至少 5 个已完成的过程片段，且包含至少 2 段思考、总计至少 6 个思考/工具事件时，自动合并为一行“过程记录”。
- 当前正在生成的思考或运行中的工具始终留在折叠行外；事件结束后才进入过程记录。
- 过程记录默认收起，展开后仍是原始时间顺序，不丢失工具输入、结果或失败状态。
- Claude CLI 与 OpenAI 兼容引擎共用同一套收纳规则；连续两个以上工具也会自动组成工具组。
- 回合末尾的“定位到过程”会先展开过程记录、工具组与目标工具，再滚动、高亮并移动键盘焦点。
- 生成中的思考框只在用户仍位于底部时自动跟随；用户主动向上滚动后停止抢滚动。

## 3. 回合末尾：完整复盘坞

末尾保留并加强现有能力，命名为**本轮记录**。它与内联工具的职责不同：

- 内联记录回答“进行到这里时做了什么”；
- 末尾记录回答“这一整轮最终做过什么、产出了什么、能否撤销”。

固定顺序：

1. 摘要头：`N 次工具 · N 个文件 · N 个产物 · 时长`。
2. 工具记录：按调用顺序列全；`≤3` 默认展开，`>3` 默认折叠；有失败则展开到失败项。
3. 本轮变更：沿用 `turnSummaryCard`，保留逐文件撤销和整轮撤销。
4. 文件产物：始终露出文件 chip，保留打开/定位；不藏进工具折叠。
5. 用量：token、费用、引擎置于最末，视觉降级。

末尾工具行可点击“定位到过程”，滚回它在正文中的内联位置并短暂高亮。重复展示因此不是冗余，而是“叙事定位 + 审计索引”两种入口。

## 4. 双引擎统一协议

### 4.1 统一模型

新增持久化字段 `message.segments`；现有 `content`、`toolCalls`、`nativeAgents`、`turnSummary` 暂时保留，兼容旧版本与外部读取。

```js
message.segments = [
  { id: "s1", kind: "text", text: "我先核对路线图。" },
  {
    id: "s2",
    kind: "tool",
    callId: "call_1",
    batchId: "batch_1",
    name: "file_read",
    input: { path: "docs/OPTIMIZATION-ROADMAP.md" },
    result: { lines: 390 },
    isError: false,
    durationMs: 412
  },
  { id: "s3", kind: "text", text: "现状可以归纳为两个问题……" }
];
```

约束：

- `id` 在一轮内单调、稳定；静态重渲染不能重排。
- `tool_result` 通过 `callId` 原位补全，不另建一个视觉片段。
- 同一模型响应返回的并行调用共享 `batchId`；折叠器按 `batchId` 呈现“并行 N 项”。
- 相邻 `text` 合并；工具或决策事件到达后封段。
- 大结果仍只存一份；`segments[].result` 与 `toolCalls[].result` 在过渡期可由同一对象生成，避免双写漂移。

### 4.2 Claude CLI

Claude 的 stream-json 已能给出有序的 `assistant_delta → tool_use → tool_result → assistant_delta`。在服务端转发事件的同时写入 segment builder：

- 首个 `assistant_delta` 创建文本段，后续增量追加。
- `tool_use` 封闭文本段并创建工具段。
- `tool_result` 按 id 回填。
- CLI 同一 assistant content 中连续出现的多个 `tool_use` 共享批次号。
- `AskUserQuestion`、原生 Agent/Task 事件也进入同一有序序列。

### 4.3 OpenAI 兼容

Provider 每次模型迭代天然形成 `call.text → call.toolCalls → role:tool → 下一次 call.text`：

- `call.text` 写文本段。
- 同一次响应的 `call.toolCalls[]` 共享 `batchId`。
- 工具执行完成后原位回填；下一次模型响应另开文本段。
- 聚合必须按 `tool_call.id`（有 `index` 时兼容使用），不能把缺 `index` 的并行调用塞进同一槽；这与路线图 E1 共用修复。

两个引擎最后都只把 `segments` 交给一个前端 `turnNarrativeRenderer`。引擎差异只影响可用字段，不影响 DOM 结构。

### 4.4 字段缺失时的诚实降级

- 无 duration：不显示时长，不估造。
- 无结构化结果：显示“已完成”，详情中保留原始返回。
- 无 batch 信息：按顺序工具处理，不推断并行。
- 旧会话无 `segments`：走当前 `content → toolCalls → turnSummary` 顺序；不伪造历史穿插位置。

## 5. 流式与静态渲染

### 5.1 流式

当前 `createLiveAssistantShell()` 固定创建一个文字 bubble 和一个 `toolsWrap`，这正是分离的根因。改为：

```text
turn shell
└─ segment list
   ├─ text segment (active)
   ├─ tool segment (updates in place)
   ├─ text segment (active)
   └─ turn dock
```

- segment keyed 增量追加，不整树重建。
- 每个文字片段在工具边界或回合结束时只做一次 Markdown parse。
- 用户滚离底部后不抢滚动；运行状态更新不改变工具行高度。
- 后台回合重挂载复用同一事件归一逻辑，不能另写一套排序。

### 5.2 静态

- 有 `segments`：按序渲染；连续工具在渲染阶段组成组，不改存储顺序。
- 无 `segments`：沿用旧渲染器。
- “本轮记录”从 `segments + turnSummary` 派生，避免依赖当前 DOM。

## 6. 简易/专家模式

两种模式共用结构，只改变信息密度：

| 项目 | 简易 | 专家 |
|---|---|---|
| 工具名 | “读取路线图” | `file_read · 读取路线图` |
| 参数 | 文件名/对象 | 关键参数摘要 |
| 输入/结果 JSON | 二级详情 | 一级详情 |
| 批量成功工具 | 更积极折叠 | 保留更多行 |
| 末尾工具清单 | 人话名称 | 人话 + 原始名 + call id |

错误、权限、变更、产物不因模式隐藏。

## 7. 可访问性与性能

- 外层使用 `article`，标签为“如意的本轮回复”；内部 segment list 不设置多个聊天 role，避免读屏误报成多条消息。
- 仅当前文字和状态变化进入 `aria-live`；末尾复盘是重复信息，不再次播报。
- `<details>/<summary>` 或等价 button 保证键盘可达；“定位到过程”后移动焦点并给出可见焦点环。
- 回合最多保留一个玻璃表面；内联工具使用半透明纯色，不增加 `backdrop-filter` 数量。
- 超长回合按 segment 分片渲染；大工具结果仍沿用现有高度上限和按需展开。

## 8. 建议实施顺序

建议把它放在 Escapade 的早期体验迭代，先于更大范围的视觉精修，也先于 Pretender/vNext 壳层实验：

1. **协议层**：抽 `TurnSegmentBuilder`，Claude/OpenAI 各接入并补顺序契约测试。
2. **持久化**：新增 `segments`，旧字段双写一段兼容期；旧会话 fallback。
3. **流式渲染**：把 `bubble + toolsWrap` 改为 keyed segment list。
4. **静态渲染与复盘坞**：历史重进顺序一致；末尾工具、变更、产物完整。
5. **折叠、定位与双模式**：并行组、多工具组、失败外露、末尾跳回过程。

## 9. 验收红线

- Claude CLI 与 OpenAI 兼容引擎的同一脚本化事件序列产出同构 DOM。
- `文字 A → 工具 1 → 文字 B → 工具 2 → 文字 C` 在流式期、刷新后、切会话重挂载后三次顺序完全一致。
- 并行工具不串 id、不串结果；一个失败时失败项不被收起。
- 回合末尾能看到全部工具索引、全部变更、全部产物；产物无需先展开工具记录。
- 旧会话可读，旧客户端读取新会话时仍能使用 `content/toolCalls/turnSummary`。
- 100 次工具调用的回合默认只增加常数级可见行，展开后按需渲染详情。
- 简易与专家模式、明暗主题、键盘操作与读屏策略全部通过现有回归门。
