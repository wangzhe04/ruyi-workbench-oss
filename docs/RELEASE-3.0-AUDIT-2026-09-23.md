## 4. 最值得做的体验收尾

以下为源码路径审查；没有冒充真浏览器或受试者走查结果。

### 发布前优先：Mermaid 查看器键盘闭环

`public/js/mermaid-runtime.js:283–410`：创建 `aria-modal` 对话框并聚焦，keydown 仅处理 Esc；关闭时只移除节点，没有 Tab 焦点循环、背景 inert 或触发按钮焦点恢复。项目已有 `modal.js` 的焦点约束可复用。

验收：打开后 Tab/Shift+Tab 留在灯箱控件内；Esc/关闭后回到原“放大”按钮；不能 Tab 到背后的发送或权限操作。修主题 token 时一并验收。

### 发布前优先：新队列更新时保住键盘位置

`prompt-queue.js:336,399` 与 `background-tray.js:225,281`：集合/状态签名变化会清空列表并重建按钮；没有保存和恢复当前焦点。新请求进入、任务结束或进入 stopping，都可能移除用户正聚焦的按钮。

验收：在第二行操作时另一行新增/结束，焦点留在同一条；当前项消失时落到最近合理位置；重排不让一次键盘操作落到另一权限项。建议按稳定 ID 更新 DOM，或显式保存/恢复焦点。

### 建议打磨：后台状态显示数据新鲜度

`background-tray.js:80–107`：刷新失败被静默吞掉，旧 items/counts 保留；每秒计时继续走。持续断连时，旧任务仍可能显得像在正常执行。全局断连提示即使存在，也不能解释这条任务状态是否新鲜。

验收：连续刷新失败后显示“连接中断，状态截至 xx:xx”；恢复后自动对账。不要把未知状态推断成仍在运行或已完成。

### 建议打磨：终验用完整旅程而非只验单控件

固定五条旅程：首次配置→首个交付；语音冷启动→取消→改字→发送；多线程提问/权限→排队→超时/处理；后台任务→切线程→断连恢复→停止；旧版本数据→升级→打开旧交付→恢复。每条至少记录完成率、误操作、状态能否讲清、失败后能否继续。

已有语音预热、模型菜单统一、待处理队列和后台任务条不应作为新需求再做一遍。先把上述边界磨顺，再讨论 3.0.1 的增量。

## 5. 建议收口顺序

1. 修确定的静态门问题与 Mermaid 键盘闭环，查清 ACC 探针和 unit 前置未完成原因。
2. 合并更新发布总账：逐项写“已交付 / 证据关闭 / 明确延期 / 待终验”，收口 E02 与候选池口径。
3. 冻结候选 commit；全量、五旅程、性能与安全/读屏终验；只接阻塞修复。
4. 冻结后统一正名 3.0、生成链、Full/Slim/校验和、实际升级回退验收；任何改动使受影响证据失效就补验。
5. 更新最终形态的 Release Brief 与 CHANGELOG，再走发布批准。

不建议承诺“只差改版本号”，也不建议再以候选池为由无限扩功能。现在剩下的主工作是明确范围、修小而真实的缺口、让当前代码与发布证据对得上。
