## 1. 总策略

**一句话:换容器,不换引擎;投影先行,壳层渐进置换;每一步都有退路。**

- 执行资产(双引擎/工具/权限/检查点/审计/技能/记忆/离线存储)**零重写**——概念稿 §8.3 非目标第 2 条冻结。
- 新壳层全部状态来自 EC-E 已交付的持久化投影(`/api/missions`、`/api/interventions`、mission.result、turnSummary、Intervention 账),**禁止前端拼装散装端点、禁止模型文案猜状态**(go 条件 #1/#5,no-go 触发器 #1/#3)。
- 双壳并存期:新功能只实现一个业务入口,经共享 command 层(现有 REST API)被两壳调用,**禁止两套业务状态**(§9.2)。
- 每波沿用本仓纪律:红绿双证 e2e、冻树全量门、主会话亲跑验收、src/ 改动主树串行(server.js 11k+ 行单文件不派并行 worktree)。

## 3. 波次规划(P0✅ → P4,自第74波起)

波次号是内部序列,与版本号解耦;每波给出:交付、退出条件(可执行断言)、主要风险。P2 起每波退出条件含「经典壳层零回归」。

### P1 · 领域基础收尾(第74–75波)

EC-E 已提前完成 P1 大半(schema 主体、幂等、过期/取消、迁移契约均有测试),本阶段只收三个口。

**第74波 · schema 冻结文书 + C4 竞态评估**
- 交付:`docs/PRETENDER-SCHEMA.md`——Mission projection / Intervention 字段级冻结(字段名、类型、权威来源、可变性)、事件语义、幂等规则、过期规则、schema version 与迁移契约;**mission.id 主键按 D1=方案 B 成文**(字段名 `missionId`、派生规则、1:N 扩展语义、与 sessionId 的关系界定);C4 竞态修复方案定稿。
- 退出条件:文书覆盖 §9 两张 schema 全字段;e2e 现有断言与文书逐条可对照(无文书承诺但无测试的字段)。
- 风险:低。纯文书+评估,唯一代码改动是竞态修复(若定为本波做)。

**第75波 · missionId 落地(方案 B)+ C4 竞态修复**
- 交付:
  - **missionId 派生**:session 主键与文件布局不动;新会话创建时 `missionId=sessionId` 派生写入;`normalizeSession` 对存量会话**只读派生**(同 70 波 kind 纪律,绝不回写);mission 对象自身携带 `missionId`。
  - **API 命名对齐**:`/api/missions` 列表/详情的标识字段、`/api/interventions` 的 `missionId` 反向引用,从第一天起以 missionId 为对外名;sessionId 保留为内部/通道标识。当前 v1 行为严格 1:1,schema 注释明示 1:N 扩展语义(未来一单多会话时 missionId 不变、sessionIds[] 扩容)。
  - **C4 竞态修复**:provider 回合内 mission 写与回合收尾盖回的定序(第72波挂号项),红绿双证。
- 退出条件:missionId 在投影/详情/Intervention 三处一致;存量会话只读派生不回写(e2e 双方向);竞态 e2e 红跑复现旧盖回、绿跑定序正确;`mission.id` 进入 schema version 与迁移契约。
- 风险:中。触碰 05-claude-engine 回合收尾写路径,主树串行。

**P1 出门闸**:schema 冻结文书 + 主键一致 + C4 关闭。此后 P2 任何 UI 不得引入文书外字段。

### P2 · 新壳层 Preview(第76–80波)

原则:**原始镜头先行**(现消息流渲染器零改动嵌入),班组图/叙事镜头本阶段不开;Preview 期新壳层默认关、经设置开启,经典壳层默认。

**第76波 · 壳层骨架**
- 交付:案头条(四事实:工作圈/安全档/引擎/鎏金铃)+ 任务坞(72px 瓷章轨,三态:青花进行中/鎏金脉冲需要你/静默收工)+ 主台单视图容器 + 新/经典壳层切换开关(持久化,默认经典)。~300 行新 CSS/HTML 纯新写,不动经典壳层文件;五态派生复用 `mission-state.js` 双导出。
- 退出条件:骨架 e2e(切换持久化、瓷章三态由真实投影驱动、案头四事实同源 chips 数据);经典壳层 DOM/测试零改动(frontend-domains.static 绿)。
- 风险:低-中。纯新增视图域;CSS 分层纪律(tokens/base/components/views)沿用。

**第77波 · 任务单(原始镜头)**
- 交付:全宽任务单 = 头部(五态+工序进度+用量)+ 现场(现消息流/工具卡渲染器原样嵌入)+ 收活台初形(需要你计数/成果引用/台账只读,数据全部来自 `/api/missions/:id` 快照)。点击瓷章→任务单 1 击可达(go 条件 #7)。
- 退出条件:任务单 e2e——四旅程数据面在任务单完整呈现;渲染器复用断言(不复制消息流代码);长任务 cursor 续断点。
- 风险:中。SSE/增量渲染在新容器内的焦点与滚动稳定(EC-D 56/57 波的坑,复用其粘性滚动与 keyed 增量机制)。

**第78波 · 交办台首页 + 交办确认卡**
- 交付:交办箱(提交→交办确认卡:AI 复述/工作圈/本单安全档/有依据才显的时长花费→开工立单→瓷章落坞)+ **速问逃生舱**(`?` 开头或点速问,直接问答不立单,kind=quick_ask)+ 熟活架 + 续办条 + 最近收活(带反悔柄入口)+ 首跑引导态(圈地/接引擎/试一单,原位完成)。
- 退出条件:确认卡→立单全链路 e2e;逃生舱 e2e(quick_ask 不进 `/api/missions`、五态不硬套);首跑三态原位呈现。
- 风险:中。交办确认卡是从任务卡填空逻辑扩展(概念稿 §5-4),勿新造表单体系。

**第79波 · 双壳切换/迁移说明/故障回退 + 性能门复跑(C1 硬门)**
- 交付:壳层切换的迁移说明与故障回退路径(切壳≠数据迁移,各自独立回退);**EC-D 性能硬门对新壳层复跑**:真实 Edge 首屏 <1.5s、视图切换 P95 <200ms、长任务事件流增量渲染不全量重建。
- 退出条件:**C1 全绿——这是 Preview 公开放行闸,不过则 P2 不公开、回到对应波修**;回退路径 e2e(切回经典后数据与状态无损)。
- 风险:中。性能门首轮抓红是常态(参照 2.2 门抓 5 处存量红),预留修复余量。

**第80波 · Preview 收尾走查**
- 交付:双主题、双语(locale 扁平键纪律)、a11y、视觉回归门扩展至新壳层;USER-GUIDE 新壳层章节(概念稿 §6-6 文档重写在 Preview 公开时必须就位)。
- 退出条件:走查清单全绿;冻结项核查(UI/发布物中无 Pretender 名/3.0 版本号,§2.2)。
- 风险:低。

**P2 出门闸(= Preview 可公开)**:C1 性能绿 + 四旅程在新壳层可走完(决策动作回经典壳层)+ 双壳回退实证 + 文档就位。

### P3 · 完整任务交付体验(第81–85波)

**第81波 · 全局「需要你」决策动作(C3 范围)**
- 交付:鎏金抽屉内直接决策(权限/提问/计划/池审批),复用现有 decision 端点;跨会话决策后各会话经典 UI 同步;停工卡 v1(出了什么事人话+再试/换法子/先算了三动作)。
- 退出条件(C3 硬门):重复提交 409 不重复执行的 e2e 从单会话扩到跨会话;绝不默认批准(重启/过期=安全终态)断言沿用 71/71b。
- 风险:中高。决策动作跨会话,触碰回合生命周期,server.js 手术主树串行。

**第82波 · 班组图镜头**
- 交付:P3 画布稿(分层布局/贝塞尔边/状态着色)语义换装:节点=队员、工头一句话常驻、**Agent 提议新任务=虚线鎏金拟增工序节点**(批准实线化/拒绝消失);递话(选队员说一句,下一步生效)。
- 退出条件:多 Agent 旅程在班组图镜头完整可监督;拟增工序与池审批 Intervention 数据一致(图=数据的面,不是第二状态)。
- 风险:中。视觉表达丰富的诱惑——节点数据全部来自既有字段,装饰不承载信息(§6-7 防装饰主义)。

**第83波 · 叙事镜头 v1(规则版,诚实边界)**
- 交付:现场纪要——规则折算纯函数(工具动词人话化+对象+时间线,每句可展开原始卡),前端纯函数双导出(同 mission-state.js 纪律)。**不承诺散文、不调模型摘要**(非目标 §8.3-4 + 概念稿 §6-2)。
- 退出条件:折算函数 e2e(每句可溯源到原始事件);长任务叙事不全量重建(增量 append)。
- 风险:低-中。质量天花板是已知的,用户预期管理靠「每句可展开原始卡」。

**第84波 · 反悔柄 + 台账时间轴**
- 交付:收活台台账=改动时间轴(每条带回退钮,revertible 真实标注);任务单头部常驻整单回退;档案里已收工任务保留反悔柄;不可逆账在台账显性列出(72 波数据)。
- 退出条件:go 条件 #6 e2e——每个回退钮对应真实有效 checkpoint/change-set,无按钮无能力、有能力不藏钮。
- 风险:低。数据面已齐,纯陈列与接线。

**第85波 · 收工卡闭环 + 专项可用性验证**
- 交付:收工卡(成果/验收/未完成项/变更/用量/审计聚合,数据源=mission.result)+ 存为熟活(委托书参数化抠空位)+ 记住习惯(现有记忆起草流程);长任务离场/回来、失败恢复、人工接管专项验证。
- 退出条件:四旅程**完整在新壳层闭环**(交办→离场→回来→处理例外→验收→反悔→沉淀);go 条件 #1–#7 对新壳层全量复评通过。
- 风险:中。熟活参数化是任务卡体系扩展,同 78 波纪律。

**P3 出门闸**:go 条件 #1–#7 全绿(#8 性能在 P4 终验);四条附加条件中 C3 关闭。
