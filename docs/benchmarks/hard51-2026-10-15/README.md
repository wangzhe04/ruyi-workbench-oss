**中文** · [English](README_EN.md)

本次支持的结论是：**如意 + DeepSeek V4.1 Flash 这一组合，以约 ¥42 的模型 API 支出取得了 86.27% 的完成率，与表中的旗舰组合处于接近的成绩区间。** 这展示了如意 harness 在真实工程任务上的交付能力。模型、框架、推理配置与执行环境不同，因此不能把组合分差单独归因于 harness，不能据此证明基础模型能力排序或“如意独立优于 Codex / Claude Code”。隔离 harness 增益需要固定模型、预算与环境的受控实验，本次没有做该实验。51 题的单次结果也不能替代全量集成绩。

官方页面没有公布同口径逐次费用与耗时，不对竞争组合编造费用、速度或性价比倍数。

## 测试协议与版本

- **运行构建：如意 3.0.0**，`app/server.js` SHA-256 为 `a80a4e1b6a6d6a13eb292f28135a1eb9f0fb2c676b7674cbf5dc1a297e3a5779`。这是此次实测构建的身份，不等同于所有 3.0.0 构建，也不是随后发布的 3.0.1 重新跑分。
- 模型为 **DeepSeek V4.1 Flash**，实际 API 名称为 `deepseek-flash`，通过本机 DeepSeek provider 调用；没有把本机配置写成官方 `high` / `xhigh` 等跨厂商等价档位。
- 官方仓库 [SWE-bench_Pro-os](https://github.com/scaleapi/SWE-bench_Pro-os)，固定 verifier commit：`66f92766bba642462d4bbe5479e83f91f9211862`；51 题 ID 清单 SHA-256：`6e35e84708a26443e1746ae928940555a3188654c90f3a2eb691f4f699482bd1`。
- 每题独立新会话、一次模型运行；每题解题上限 50 分钟，CPU / 内存为原版 task.toml 的 1 CPU / 4096 MiB。最多三题并行，不是多模型投票或多次尝试取最好结果。
- 如意运行于 Windows 宿主；仓库操作经 MCP `docker exec` 进入离线任务容器。模型阶段不联网查解答，不提供参考补丁或隐藏测试；不因隐藏测试失败修补模型答案或重跑模型。
- 在全新官方基础镜像应用模型补丁，用固定版本的原版 verifier 判分；判分容器允许 public network 补依赖。该适配保留上述任务条件，**不是官方 Harbor 的执行或提交**。详见[官方 V2 协议](https://github.com/scaleapi/SWE-bench_Pro-os/blob/66f92766bba642462d4bbe5479e83f91f9211862/v2/README.md)。

## 明细与核验边界

[results.json](results.json) 公开 51 题的 instance ID、原版镜像 digest、基础 commit、通过/失败、所需测试数、时间、token、费用和模型补丁 SHA-256。不是只挑通过题发布。所需测试数采用官方解析器的目标集合口径，不等于每次 pytest/Jest 实际收集的全部测试数。

发布前已核验 51 份模型补丁哈希、255 份官方 verifier 文件哈希、逐题 reward 与判定、费用分项和总和。审计的 85 次宿主文件/报告工具调用包括独立 scratch 目录内的验证证据，以及未执行成功的路径/语法误调用；成功的仓库修改与测试经容器 MCP 执行，无未处理审计项。

完整模型轨迹、补丁正文和逐请求回执保留在本地，本仓库只发布脱离机器路径的摘要和哈希，不包含 API 凭据或服务商原始响应。公开数据允许复核本报告的统计与费用计算；哈希是所留原件的标识，不意味着仅凭摘要就能独立重验补丁正确性。最早运行的任务（本地 task index 33）计费用如意真实 turn usage 加辅助调用 ledger，其整段运行在高峰；其余题逐请求对账。51 题均无未取得的计费用量。

7 道失败保留原判：Ansible 的 Galaxy 缓存回归；Open Library 的作者匹配、MARC 字段/作者解析及 observation 持久化共 4 题；Proton Mail 的 API 等待顺序；qutebrowser 的进程对象清理。未用环境问题的名义重跑这些失败。Teleport **6/6**、Flipt **7/7**、Element Web **4/4**；全部仓库计数见 JSON。
