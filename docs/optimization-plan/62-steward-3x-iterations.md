# 如意 3.x 管家体验与功能迭代方案

更新：2026-10-16。源码核查基线：`0f1d3ec2`，应用版本 `3.0.0`。本文是待实施方案；版本归属为建议，不承诺发布日期。

3.x 围绕管家推进：用户能够交代事情、补充材料、看清进展、处理决定、收到结果并继续修改。先修会影响任务归属、状态可信度和数据一致性的问题，再补齐高频使用过程，最后扩大能承接的工作类型。4.0 暂不确定方向；跨设备交接、完整成果编辑器均不进入本轮范围。

## 范围和现有基础

当前管家已经具备线程搜索、预路由、手选目标、递话与撤回、原文交付卡、文件和网页只读工具、速查、任务交办、待决处理、通知、设置管理、记忆、Playbook 和定时任务。后续以这些实现为基础，不重建任务、通知、权限或调度系统。

现有方案按用途继承：[41 号文](41-personal-workbench-iteration-plan.md)保留用户旅程和产品原则，[40 号文](40-wave-124-dispatch-and-delivery.md)保留交付与验收来源约定，[42 号文](42-wave-125-truthfulness-and-recovery.md)保留停止、失败和缓存真实性约定，[49 号文](49-wave-129-steward-empowerment-completion.md)与[60 号文](60-smart-auto-and-bypass.md)作为已实现能力的核查依据。历史文档中的“下一轮”“待做”不自动进入本次排期。

用户已退役的委托书横幅不恢复；交办要点沿用首条消息中的可折叠内容。管家、工作台两视角继续共用任务和执行状态。

## 问题和证据

“已复现”指隔离探针观察到了错误；“代码确认”指实现或契约存在明确限制，尚不能推出用户发生频率；“待验证”先做旅程测试和基线，再决定改动。

| 问题 | 证据强度与现状 | 安排 |
|---|---|---|
| 同数据目录可以启动两个实例，后启动者将待决标成重启取消 | **已复现**：两个临时实例使用同一数据目录、不同端口；A 存活时 B 将持久化 `pending` 夹具改为 `cancelled_restart`，并覆盖握手文件。未使用真实模型等待中的 promise。见 E01 | 第一轮，P1 |
| 同一次运行的故障信息在视图间不一致 | **代码确认**：工具箱显示 `persistenceDegraded`、空闲中止和资源阻塞；班组总览未接齐这些运行级信息。见 E02 | 第一轮，P1 |
| 轻量读取已有工具，稳定提示仍要求一律转速查 | **代码确认**：提示包与 `steward_web_search/file_read/thread_artifact_read` 描述冲突；是否导致多开线程、增加等待需测量。见 E03 | 第二轮，P1 |
| 同名任务候选被标题去重 | **代码确认**：候选列表可将不同 `sessionId` 的同名任务折成一个。见 E04 | 第三轮，P1 |
| 手选任务后不能直接带附件递话 | **代码确认**：当前明确拒绝此组合，需回到管家；这是功能边界，不是已发生的串线。见 E04 | 第三轮，P1 |
| 交付原文、文件、验收和修改入口分散 | **代码确认**：原文卡已有回合定位，操作主要是折叠和打开线程；文件预览与验收在其他入口。见 E05 | 第四轮，P1 |
| 长会话有内容搜不到 | **隔离原函数探针已复现采样限制**：每会话索引最多 8192 字符，25 条用户消息的末条唯一词可落在额度外；超过 2 MB 的正文另有头尾采样。见 E06 | 第三轮说明边界；完整分片索引列后续专项 |
| 多项待决和自然语言设置是否容易误解 | **待验证**：已有合并、单项 CAS、设置分档与撤销；需要测事项归组、作用域和部分失败的完整流程。见 E07 | 第五轮，P2 |
| 认可的做法是否能在新材料上稳定复用 | **代码确认起草输入有限，收益待验证**：当前 Playbook 主要取最后一条用户消息和最近变更摘要；多轮纠正、认可成果的提炼需要补充。见 E08 | 第六轮，P2，先验证再扩面 |

P1 表示影响数据、办事准确性或高频流程，应优先处理；P2 表示在前序稳定后扩展。没有证据的假设不作为已知缺陷对外发布。

## 六轮安排

| 轮次 | 用户可感知的结果 | 建议版本 | 依赖与退出条件 |
|---|---|---|---|
| 第一轮 运行可靠性 | 重复启动不干扰在办任务，状态和动作回执可信 | `3.0.x` 修复线 | 独立启动；数据所有权、故障与回执场景过门 |
| 第二轮 答疑与派单 | 简单问题直接得到回答，需要执行的工作准确交办 | `3.1` | 可与第一轮开发并行；对外发布依赖第一轮 |
| 第三轮 找回和续办 | 找对旧任务，带材料继续做，失败后原话和目标仍在 | `3.1` | 依赖第一轮回执；与第二轮共享意图和目标约定 |
| 第四轮 交付和修订 | 从管家看到结果、打开文件、辨别验收，再继续修改 | `3.1` 收口 | 依赖第三轮的目标及回合绑定 |
| 第五轮 待决和设置 | 多件事集中处理，设置改了哪里和何时生效说清楚 | `3.2` | 前四轮稳定；沿用 CAS、在场信号和配置分档 |
| 第六轮 工作类型扩展 | 一组步骤有序执行，认可做法可在新材料上复用 | 后续 `3.x` 候选 | 前五轮与场景验证通过后逐项纳入，不整包承诺 |

版本按完整体验发布，不要求一轮恰好对应一个版本。首批先做第一轮和第二轮的契约修正；第三、四轮组成 3.1 的主要用户价值。第五、六轮不阻塞前面的可靠性修复。

### 第一轮 运行可靠性

**目标旅程**：用户开着几件任务，再次启动如意、刷新页面或遇到暂时写盘失败，原任务与待决仍然可辨认、可接手。

1. **按数据目录取得服务独占权。** 在启动恢复、索引失效、自动导入和同步前取得租约。目录使用真实路径与 Windows 大小写归一；握手文件继续只承担握手职责。已有活实例复用或明确拒绝，失效实例才允许回收；释放前核对所有者身份。合法的 MCP 子进程不因服务租约被拒。启动约定须先与 `port-fallback.e2e.js` 中旧接管语义对齐。
2. **统一故障与新鲜度提示。** 复用五态、投影版本、构建时间、SSE 和现有故障字段，在管家、班组和工具箱说明“还在执行”“等待资源”“信息暂时无法刷新”“写盘失败”。业务状态与读取质量分开；读取失败不能显示为没有待决或已经完成。重连换进程后重取权威快照，不另起轮询器。
3. **动作回执贯穿实时与回放。** 复用递话、待决、任务控制的执行入口和回执。“已送达”“正在执行”“执行完成”“结果未知”各有依据；双击、超时、回包丢失不触发无条件重派，旧按钮不能操作已变更的对象。模型输出结构完整不等于工具已经执行。
4. **建立本轮验收基线。** 修复或明确定位本机浏览器夹具的 CDP 连接障碍，再做真实页面旅程；不能以静态测试替代界面验收。记录交互反馈、事件传播、模型等待和动作完成四段耗时。

**验收**：同根双端口、并发启动、目录联接别名、崩溃残留租约均有隔离行为测试；旧进程不得取消新进程待决或释放别人的锁。断连、乱序、写盘失败和恢复时，两视图状态一致，过时快照可辨认。重复点击只产生一次逻辑动作；回执缺失不显示成功。

**拆分**：启动所有权及其测试 → 故障投影及视图接线 → 回执和重放场景。每块独立提交；只修其阻断问题，不顺带重构整个存储层。

### 第二轮 答疑与派单

**目标旅程**：“这份材料讲什么”可以直接回答；“把三份材料整理成报告”能够交办；“刚才那个结论依据是什么”读取原件后解释。

1. 对齐中英稳定提示、工具说明和调用路径：已有状态查询、受限文件读取、网页读取和交付读取可以在管家回合完成；长过程、写文件和执行命令继续交给速查或任务线程。
2. 用同一组场景检查分流：已知状态、单文件说明、多材料研究、修改文件、已有任务续问。按所需工作与能力分流，不按提示词长度猜复杂度；模型能力缺失时说明下一步。
3. 交办后给简短回执：实际交给哪件事、目标是什么、是否已开始。只在缺失信息会改变对象、范围或结果时追问；独立且已明确的工作可以先开始。
4. 保留现有外部内容污染规则：读过网页或文件后，不因“轻量任务”而绕过写动作提议、权限或确认边界。

**验收**：生产管家回合经 fake provider 真正调用工具，检查下一次请求中的回执和最终落盘；不能只手工构造工具上下文。直接读取不额外开线程；需要执行的请求有实际交办；追问答复进入原请求。语义分流质量另用固定真实模型样例比较，不由 fake 通过率代替。

**拆分**：提示与 schema 契约修正 → 五类固定旅程 → 有证据的追问与分流调整。契约修正可先作为补丁交付；体验调整归入 3.1。

### 第三轮 找回和续办

**目标旅程**：“把昨天那份报告按这张新表改一下”→辨认同名任务→递送附件与原话→失败时原地重试，任务与草稿不串线。

1. 候选以 `sessionId` 保留身份，同名任务显示日期、工作区或简短内容区别。用户显式选择优先于预判；迟到预判不得改变已选目标。
2. 失败保留原话、附件和目标；重试先核对上次递送回执，避免网络超时造成重复任务。撤回沿用现有锚点与能力边界，不能承诺撤销已经发生的外部副作用。
3. 将“手选任务加附件”做成独立切片：沿用既有上传记录和会话附件管线，校验附件生命周期与目标工作区；拒绝或不支持时保留输入，并明确仍需用户处理的步骤。
4. 搜索显示有界索引的范围；未命中不能说“从未做过”。可提供用户触发、限候选、限读取量、可取消的深入查找。按消息分片的完整索引作为独立后续专项，覆盖删除、回退和增量失效，不成为本轮前置。

**验收**：两个同名任务均可选；快速切焦点、跨日续问、附件过期、目标删除、发送中刷新与重复重试均不误递。回复只清理所属输入，不覆盖新草稿。长会话末段未索引时不作全量搜索承诺。

**拆分**：候选身份与消歧 → 失败和迟到响应保护 → 附件续办 → 搜索边界及按需查找。已有预路由、手选、换一条和撤回继续复用。

### 第四轮 交付和修订

**目标旅程**：用户在管家收到报告，直接打开对应文件，看清哪些检查通过，再说“只改第二部分”，修改回到原任务。

1. 原文交付卡沿用 `sessionId + turnSeq`，接入该轮产物、未完成项和现有验收来源。不能把其他回合或线程最后一条助手话当成本轮交付。
2. 提供“打开产物”“查看检查”“继续修改”的就近入口；文件不存在或内容已变时提示并重新检查。已验证、用户确认、模型自报和未记录保持区别。
3. 修订操作绑定来源任务和回合，必要时附文件引用。原话保留；用户改变目标后，旧结果仍可查，但不能表示新要求已经完成。
4. 先使用现有回合、变更记录、结果历史和检查点表达关系。如果确需独立委托修订标识，先证明现有字段无法表达，再增加单一权威字段；不得把 `updatedAt` 或摘要当作目标版本。

**验收**：从交付卡最多两次操作打开目标文件（建议体验目标）；缺文件、部分完成、验收失败、旧结果迟到、刷新回放均显示真实状态。修订不会改错同名文件；旧检查结果不能证明修改后的文件通过。

**拆分**：只读交付投影 → 卡片文件及验收入口 → 修订归属 → 旧结果与文件失效的完整旅程。3.x 本轮不建富文本编辑器、通用成果版本平台或新的验收账本。

### 第五轮 待决和设置

**目标旅程**：“现在有哪些事需要我决定”可以在一处处理；“这条任务换强一点的模型，之后新任务不变”准确作用于所指任务。

1. 用现有待决投影按事项归组，说明每项影响和来源；同文字的不同待决仍保留不同身份。已有五分钟通知合并、安静时段、稍后提醒和在场信号不重做。
2. 先交付逐项处理，再考虑明确选中项的批量操作。每项保留 `interventionId`、期望版本及独立回执；一项失败不能隐藏，用户在其他入口已处理的项不能再批。首版不自动把多个问题合成同一答案。
3. 设置操作呈现对象、作用域、生效时机、实际修改值和可用的撤销动作。复用 `config_get/set` 及 free/confirm/forbidden 分档；涉及线程模型时走对应线程入口，不通过修改全局默认“模拟”线程设置。
4. 对常见意图做验证：减少普通提醒但保留错误；仅调整这条任务；更改后续新任务默认；修改等待时长。含糊请求不推导成扩大权限。

**验收**：处理中刷新、他处已答、陈旧按钮和部分失败有行为测试；拒绝不会变允许，关卡片不等于办完。设置页和管家回显一致；写盘失败不说已生效，下轮生效不说当前已经切换。

**拆分**：事项待决清单 → 逐项处理 → 有需要的显式批量 → 设置回执和作用域。两条开发线可并行，共同等待前序回执与状态契约稳定。

### 第六轮 工作类型扩展

本轮逐项验证后再纳入后续 3.x，不同时承诺以下三项全部交付。

| 候选切片 | 可交付范围 | 验收和取舍 |
|---|---|---|
| 多步骤交办 | 限一个新事项下的单一协调线程，内部复用 `orchestrate_agents`、DAG 依赖、资源租约、预算和交付信封 | 前序失败不误启后序；停止传播；重启结果未知时不重放；重复完成事件仅交付一次。先用资料汇总、对比报告、文件整理三类任务验证 |
| 认可做法复用 | 用户选择认可成果、关键纠正和可变输入，复用现有 Playbook 起草、编辑、保存与普通执行路径，增加在新材料上的显式验证 | 换一份新材料仍满足要求；修改规则可见且可撤回。当前起草依赖 provider 的限制须明确，不能承诺所有引擎立即等价；无收益就留作候选 |
| 定时运行既有做法 | 复用 scheduler，显式记录所选 Playbook 与参数快照；首版建议在登记时冻结，模板更新须显式更新计划 | 先处理能力、参数、工作区和权限；同一 occurrence 不重复派发，执行未确认或结果未知时如实记账、先核对再恢复；验证休眠补跑与取消。当前 payload 只有 reminder/prompt，不能只在提示词里拼名字就算支持 |

**边界**：事项容器表示归属，现有 DAG 表示单次运行的节点依赖；线程关联列表只是导航，三者不能互相冒充。`wait_for` 当前没有“另一线程完成”语义。因此对既有 A、B 任务的接力，第一档提供读取原件、标清来源和显式交办；自动跨既有线程依赖须单独设计，不能以 `running=false` 或文件存在认定完成。

## 管家的职责边界

| 请求 | 默认承接方式 | 用户应看到什么 |
|---|---|---|
| 状态、已有结论、轻量资料解释 | 现有查询或受限只读工具 | 直接答案、必要来源和时效 |
| 需要独立调查或短时执行 | 现有速查或任务线程 | 正在处理什么，结果回到哪里 |
| 修改文件、运行命令、较长工作 | 有工作区、权限和预算的执行线程 | 实际目标、进度、需要决定的事项和交付 |
| 改设置、定时、控制任务 | 现有专用工具与确认规则 | 作用范围、生效时机和执行回执 |
| 一组有依赖的工作 | 第六轮限定范围的协调线程与 DAG | 哪些能先做，哪些在等，缺什么，怎样停止 |

扩大服务范围以完整承接请求为标准，不以增加工具数量为标准。停止、用户在场、外部内容污染、预算和权限规则继续由现有权威实现判定。

## 固定验收和发布

沿用 41 号文的 J 编号，避免旧旅程被另一套评分覆盖。每个版本记录通过、部分通过、未覆盖和回归；历史未覆盖项不会自动阻断无关补丁，但本轮改变的路径必须验收。

| 固定旅程 | 主要断言 | 对应轮次 |
|---|---|---|
| J01 J03 交办和对象 | 同名任务可区分，原话、工作区和附件归属正确 | 第二、三轮 |
| J06 中途修订 | 新要求生效，旧结果迟到不能冒充新交付 | 第三、四轮 |
| J04 J05 J16 输入和重连 | 草稿、目标、焦点、滚动保留，已处理通知不复活 | 第一至五轮相关界面 |
| 待决与在场 | 真页面查看时管家不抢答，离开后可继续，代答有依据 | 第一、五轮 |
| J07 停止和恢复 | 停止后无自动复活，用户明确恢复仍可用 | 第一、六轮 |

| J09 J12 J13 记忆与分歧 | 本次要求优先、项目隔离、旧偏好不复活、来源可回查 | 第二、三、六轮 |

每个新增服务另测缺能力、缺必要参数、权限待决和部分失败四条分支。验证层次如下：

- **切片检查**：相关单测、真实生产调用链的离线行为 e2e；核心修复至少一条能证伪的反向场景。结构性约束用静态锁，运行正确性不用字符串存在代替。
- **界面检查**：改动路径在真实页面上操作；覆盖窄屏与桌面、双语双主题、键盘、慢响应、刷新和切任务。向单独模块注入快照只能证明该层行为。
- **语义验证**：分流、追问和做法提炼使用固定任务对照；记录模型、样本量、失败、unknown、修改次数、耗时和成本。确定性测试不能证明模型会准确理解；本方案没有进行新的付费评测。
- **候选版本**：冻结树 Windows 全量结果列明首次失败、flaky 和 skip；升级副本、全新数据目录、实际 Slim/Full 包分别验证核心旅程。补丁范围和功能版范围分别冻结，不因增加文档或通过静态门而宣称可发布。

用户体验主要看误投/重复开任务次数、用户重复解释次数、完成与修订所需操作数、错误后恢复成功率。性能分开报告本地反馈、事件传播、模型等待与总完成时长的 p50/p95；与首轮同环境基线比较。除“两次操作打开产物”的建议目标外，其余数值线在基线后确定，不能用任意秒数替代实际测量。

## 工程安排与暂缓项

第一轮的启动租约与第二轮的提示契约可并行开发；涉及 `06i`、`13k`、`13o` 的变更按工作包依次合入，避免多人同时改变目标和回执语义。第三轮稳定后接第四轮。第五轮的待决与设置各有独立提交，第六轮每项单独作范围决策。

近期不启动：跨设备交接、实时多人协作、完整 Office 编辑器、全局依赖图重写、默认云向量检索、任意跨线程自动依赖。关键状态的断电持久性、按消息分片索引和核心依赖环缩减保留为专项；只有成为当前旅程的实测阻碍时才进入当前轮，避免把 3.x 主线拖成底层重建。

每轮收口更新本文工作包状态、对应用户手册与 Unreleased，并留下行为验收证据。计划状态与发布状态分开：写入方案不表示实现，合入源码不表示已随安装包发布。
