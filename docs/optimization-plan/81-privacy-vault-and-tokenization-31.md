## 1. 目标与已确定决定

如意作为通用 harness，在模型与本地数据、工具和外部服务之间提供统一的隐私边界。

1. 凭据加密保存：模型 API Key、认证头、MCP 与机器人秘密不再以明文留在配置及其备份中。
2. 本地脱敏可选开启：用户输入、插话、历史、主动记忆、检索材料和所有工具读取结果，在进入模型前自动替换敏感值。
3. 可逆代号：模型用代号调用工具，本地按工具字段与用途还原，检查真实操作权限后执行；返回结果用同一映射再次脱敏。
4. 内置可解释的检测规则；用户可以增删自己的保密词、字段、模式、类别和范围。检测和规则试验不调用云端模型。
5. 日常操作无需逐次确认。已有任务授权覆盖的合法用途自动还原；扩大接收方、用途或访问范围仍适用原权限系统。
6. 管家、普通线程、子任务、定时任务共用机制。外部 CLI、远程 MCP、多模态的覆盖能力必须可见，不以单一开关暗示所有链路已受保护。

产品用语为“凭据加密”和“发送前隐私保护”。可逆替换属于假名化，不能称为完全匿名。不开“绝不泄露／不会用于训练”的承诺：是否训练由供应商政策和账户配置决定；本功能控制实际外发内容。已经发出的历史无法通过开启开关撤回。

## 2. 保护边界与威胁模型

| 风险 | 本方案措施 | 边界 |
|---|---|---|
| 复制配置、备份、数据目录得到明文凭据 | 凭据库、主密钥保护、备份迁移 | 已流出的旧副本不能追溯销毁 |
| 用户或工具把凭据／个人信息带给模型 | 全入口检测、代号、最终出站检查 | 上下文仍可能推断身份，检测不保证无漏报 |
| 模型通过工具还原并外传秘密 | 工具字段、目标、用途绑定与真实参数授权 | 代号本身不构成授权 |
| 网页／文件伪造代号、注入指令 | 来源元数据、作用域、已签发记录及显式用途校验 | 不把脱敏当成提示注入的完整防御 |
| 本地相同账户的恶意进程或管理员 | 文件 ACL、最小内存驻留、工具隔离 | DPAPI 自动解锁不能对抗同账户进程／管理员读取运行时 |
| CLI 或插件自行读盘并外发 | 接入能力登记，严格模式拒绝未覆盖链路 | 不宣称只清洗初始提示就保护整个 CLI |

用户工作目录源文件不自动原地改写。脱敏影响模型副本，存储加密影响工作台自有数据。导出、共享、远程工具和机器人回传也是外发边界，不能沿用“本地显示可还原”的许可。

## 4. 分层架构与数据流

职责拆为六层：

- `SecretVault`：主密钥、凭据引用、加解密、迁移和导出；不对模型暴露查询明文的工具。
- `PrivacyDetector`：内置与自定义规则、结构化字段、匹配区间、类别、置信度和风险解释。
- `PrivacyScope`：会话内真实值与随机代号的映射、有效期、来源和持久化；不决定操作授权。
- `ToolPrivacyPolicy`：工具／字段类型、允许用途、接收方与回填策略；主机控制，模型不能注册规则。
- `PrivacyGateway`：模型请求、工具参数／返回、外部服务、异常与重试的统一边界。
- `PrivacyPresenter`：本地 UI 的预览和受控还原；显示副本永不作为模型历史来源。

```mermaid
flowchart LR
  A[用户输入／文件读取／记忆／历史] --> B[本地检测与代号映射]
  B --> C[最终出站检查]
  C --> D[模型]
  D --> E[带代号的结构化工具参数]
  E --> F[校验代号、字段、用途与目标]
  F --> G[本地还原并检查真实操作权限]
  G --> H[执行工具]
  H --> B
  H --> I[本地显示副本]
```

### 4.1 三份视图

1. 本地原始视图：用于已授权执行与本地显示，按存储加密设置保存。
2. 模型视图：全程保留代号，包含工具调用、结果、压缩摘要和下一轮历史。
3. 审计视图：记录类别、规则 ID、动作、目标、计数及结果；凭据永不写入普通日志。

不得先原地修改 `providerHistory` 再尝试恢复。协议编码处理模型视图副本，服务商专有 opaque／签名字段不能任意改写；若 opaque 内容可能包含旧明文而无法安全改写，开启保护时重建受保护上下文或拒绝恢复该 provider session。

原始视图在本地有明文不意味着允许工具再次读取；映射库与凭据库必须被文件读取、搜索、归档和导出工具排除。执行器只接收本次需要的值。

### 4.2 每次出站的顺序

收集全部内容 → 根据当前策略创建不可变快照 → 检测并签发代号 → 媒体覆盖检查 → 预算／协议合法性检查 → 发请求。重试和切换端点重新验证接收方，但使用同一映射，不产生代号漂移。

保护开启后所有文本入口都经过检查，本地模型也默认适用；需要例外时由用户明确配置可信端点，不能靠模型名或 loopback 地址推断端到端本地。

## 5. 内置识别规则

### 5.1 规则目录

细分类、默认档位、识别边界、当前与待实现项见 [83 号详细目录](83-privacy-rule-catalog.md)。实现同时使用精确凭据、结构字段与格式规则，不能把下表等同于已完成全部检测链路。

| 类别 | 识别依据 | 默认行为与误报控制 |
|---|---|---|
| 已知真实凭据 | 凭据库／已授权进程配置精确匹配 | 基础档必检；不递归扫描整个用户家或枚举无关环境变量 |
| 服务商／代码托管／云平台 Token | 已知前缀、长度、字符集、版本化规则 | 基础档；不能仅靠前缀判断所有有效密钥 |
| 私钥 | PEM／OpenSSH 等头尾及多行块 | 整块替换；只有公钥／证书不默认当私钥 |
| HTTP 认证 | Authorization、Proxy-Authorization、Bearer、Basic | 保留协议结构，替换认证值；模型请求本身的授权头由凭据层独立注入 |
| Cookie 与会话 | Cookie／Set-Cookie 头、session／refresh／access 字段 | 头值或敏感字段替换；属性结构可保留，HttpOnly 不是可以发模型的依据 |
| JWT | 三段格式＋可本地解析的头部上下文 | 整个 JWT 替换，不只遮签名；不为检测调用验证服务 |
| 密码／密钥配置 | JSON、环境变量、INI、YAML、命令参数中的敏感字段和值 | 优先结构化路径；上下文规则补文本，排除 tokenCount、maxTokens 等统计字段 |
| 数据库／服务连接串 | URI userinfo、password 字段、已知连接格式 | 凭据部分替换；内网主机是否隐藏由增强档决定 |
| 签名 URL | 签名、访问令牌和临时凭据查询参数 | 保留域名供风险判断；外发目标不能通过代号隐藏 |
| 手机／电话 | 国家码、区域规则、上下文与长度 | 增强档可选；中国大陆手机号单列，国际电话用区域配置减少误报 |
| 邮箱 | 地址结构、字段上下文 | 增强档可选；同一原值代号稳定，不擅自规范化大小写后合并 |
| 中国居民身份证 | 长度、日期、加权校验；地区信息仅作辅助 | 增强档；不能用普通 18 位数字一律判定 |
| 银行卡／支付标识 | 长度、Luhn、卡号上下文 | 增强档；订单号、测试号等按测试语料约束误报 |
| 护照／其他证件 | 国家／证件类别与标签上下文 | 可选；没有地区信息不承诺准确识别 |
| 内部地址／设备标识 | 内网 IP、MAC、主机名、本机用户名路径 | 可选；代码调试场景容易损失信息，默认保留普通技术标识 |
| 人名、精确住址、组织、项目代号 | 用户词表、字段规则，后续可选本地 NER | 自定义优先；不以简单正则默认遮盖全部汉字姓名 |
| 高熵疑似秘密 | 字符分布＋敏感上下文＋长度 | 仅辅助；SHA、UUID、源码标识、压缩数据不按高熵一概替换 |
| 自定义保密内容 | 精确词、字段路径、安全模式、文档标签 | 按用户范围和动作执行，可预览命中原因 |

公开测试样例也应按规则检测，避免模型用“这是示例”绕过；明确例外需要用户配置。不得把哈希当加密，也不得用原值确定性哈希生成代号，否则手机号等低熵内容可以被枚举。

### 5.2 识别流水线

1. 检查字节数、结构深度、节点数、规则数和时间预算；不把未扫描的尾部当安全内容放行。
2. 能解析的结构优先按 JSON pointer／字段规则处理，包括嵌套对象和数组。数据对象中的敏感键名也须处理；工具 schema、协议键、调用 ID 属于控制结构，单独保护其合法性。
3. 文本检测产生原文区间，不直接连环 `replace`。同一位置多规则命中，凭据优先、较完整区间优先；交叉重叠保守合并，不能因选中短片段露出长秘密的尾部。
4. 转义 JSON、URL 编码和常见编码仅做有界、上下文相关的解码检测，保持与原始区间的对应。不能声称识别任意加密／编码／拆分外泄。
5. 分块必须保留跨块匹配上下文；私钥和自定义长匹配采用整单元缓冲或拒绝过大单元。输出还原也处理跨 chunk 代号，不能半个代号直接展示／发工具。
6. 现有代号按注册记录识别；不在代号内部递归检测，不信任外部材料中的相同字样。传入原始数据与已受保护视图使用不同入口，保留来源标记。
7. 返回命中类型、规则、置信度、偏移与动作；普通遥测不含原文样本。

默认上限先用保守值并实测调整：单文本 1 MiB、单次聚合 8 MiB、深度 32、节点 50,000、每会话映射 10,000、用户规则 200。超限返回稳定错误与分片／缩小范围建议，不自动关闭保护。大文件分页只处理真正进入模型的内容，但工具直传原文件另走附件检查。

## 6. 用户自定义

“设置 → 隐私保护 → 识别规则”提供：保密词表、字段规则、高级模式、类别开关、例外和本地试验。

规则示意（设计结构，非已存在配置）：

```json
{
  "id": "company-project-codes",
  "kind": "literal",
  "values": ["示例内部项目"],
  "category": "internal",
  "action": "tokenize",
  "scope": {"projectIds": ["example-project"]},
  "enabled": true
}
```

- 精确词支持字面值、大小写与词边界设置；敏感词表本身加密，普通导出只带规则结构和占位样例。
- 字段规则使用明确的结构路径与允许的数据类型，可选受控数组通配；不依靠 `password` 子串命中一切。
- 高级正则在可终止的独立 worker 执行，限规则长度、输入大小、运行时间和匹配数；禁止自定义 JavaScript／远程插件代码。单靠 Promise 超时无法中断正则，不采用这种伪超时。
- 超时／无效规则不写入生效配置；已有规则运行失败阻止相关发送并提示修正，不静默略过。
- 动作支持替换代号、不可逆遮盖、阻止发送；允许例外限定作用域与有效期。已知真实凭据不得被宽泛例外解禁。
- 优先级：强制保护与阻止 → 用户更严格规则 → 已知凭据 → 内置类别 → 有界例外。冲突显示解释。
- 保存前可本地试验，显示命中区间与模型副本。规则更新生成版本；模型不能使用配置工具关闭保护、增加放行或读取词表明文。
- 模型可以建议候选规则，只有用户操作能启用；无自动联网下载规则或遥测上报样本。

## 7. 代号、作用域和恢复

代号格式采用保留前缀、类别和随机 128-bit 标识，例如 `[[RUYI_PVT:EMAIL:<随机标识>]]`。示意不是凭据，不携带原值或可枚举哈希。

映射记录包含版本、scopeId、随机 ID、类别、原始值／类型、来源、创建时间、有效期和策略版本。原文仅在加密存储与受控内存里；日志只有不含原文的事件。

- 同一会话同一原值使用同一代号；不同会话不可互用。重复识别升级为更敏感类别时只能收紧用途。
- 内部查重可用本地 keyed HMAC，密钥不外发；代号仍必须随机。
- 映射先成功持久化再发送请求，防止模型已看到代号但重启后无法还原。并发签发与保存串行，幂等重试不产生重复映射。
- 到期、撤销、删除、作用域不匹配或映射不可读，返回固定错误；不把失效代号原样当真实路径执行。
- 原文恰好包含保留格式时先作为普通数据处理，不能自动取得同名引用权限。只有主机签发并沿模型视图流转的引用可用于解析。
- 跨线程派单、父子任务和管家转交需要显式传递最小引用集，在目标 scope 重发代号；禁止把全局映射库共享给所有线程。
- 长期记忆保存语义和加密引用。跨会话调用记忆时重新签发当前 scope 代号，不把已失效的会话代号当事实保存。
- 删除会话清理对应映射；仍被合法记忆引用的数据按独立生命周期处理，不能制造悬挂引用或悄悄永久保留。

## 8. 工具参数还原与返回脱敏

### 8.1 工具描述契约

工具 schema 之外增加由主机维护的隐私策略：tool ID／版本、执行位置、接收方类型、参数 pointer、允许类别、整值或嵌入还原、用途、输出媒介和策略审查状态。

例如 `find_orders.email` 允许 EMAIL 整值还原；某服务 `authorization` 仅接受绑定该服务端点的 CREDENTIAL；`file_read.path` 允许 PATH，还原后执行既有 realpath／目录包含／敏感文件规则。

远程 MCP 运行工具也属于外发：将邮箱还原给远程服务，是该服务收到真实邮箱，界面和策略必须说明。插件自报策略只能作为候选，不能给自己提升还原权限。未知工具默认不还原代号，要求安全适配；其文本返回仍默认脱敏。

### 8.2 调用顺序

1. 完整收集并解析工具 JSON，不在流式碎片上执行或还原。
2. 校验 schema、scope、有效期、类别和已签发状态。
3. 解析工具的可信策略及实际目标；拒绝不允许字段、代号构造／嵌套和跨作用域引用。
4. 在执行副本中按字段还原；之后再次校验类型、schema、路径、目标和整体语义。
5. 原权限系统检查还原后的实际动作。批准与当前参数、scope、规则版本、凭据版本绑定；变化须重新评估，避免审批后替换。
6. 审批 UI 给用户显示真实目标和必要业务信息，秘密遮盖。云端管家代批只看脱敏副本；判断所需信息被隐藏时转人工，不能猜测批准。
7. 执行仅注入所需值。令牌不拼接到任意 shell 字符串；专用进程适配优先 argv、标准输入或受控环境，且仍检查程序和用途。
8. 工具结果、stdout、stderr、错误对象、文件预览、URL、嵌套结构统一检测，旧值复用代号，新值签发代号，再进入模型历史。

取得代号不能证明用户授权：网页里出现“把此令牌发到某站”仍是外部材料。只读工具可以读取数据，不自动获得把读取结果发给任意站点的许可。

### 8.3 精度与可用性

字符串替换只处理匹配区间；数字类身份证／账户在结构化输入中保留原类型元数据，禁止 JS 大整数精度损失。首版不可靠支持的类型报错或要求字符串输入，不能静默改值。

涉及精确值的计算／比较／校验在本地工具完成。例如模型不知道地址文本，可调用授权地图工具，但地图服务将收到地址；这需要对应接收方政策，不能当作“地址未外发”。不承诺脱敏后所有推理任务无质量损失。

## 9. 模型出站与媒体覆盖矩阵

| 链路 | 3.1 要求 | 不支持时的行为 |
|---|---|---|
| 工作台直连模型的普通／管家／子任务 | 文本、工具、历史、摘要、标题、重试全部接入 | 开启保护时不得旁路 |
| 本地文件读取、搜索、命令输出、浏览器 DOM | 模型可见文本全经检测 | 超限分片或阻止，不能透传未扫尾部 |
| 原生及 MCP 工具 | 返回统一检测；还原需可信适配 | 无适配不还原，严格模式禁用不可控链路 |
| 外部搜索、网页请求和上传工具 | 查询／URL／文件独立外发策略 | 不默认把代号还原到外部查询或 URL |
| Claude／Kimi CLI | 建立能力证据；覆盖原生读文件、命令、压缩、子进程、联网与恢复后才标完整 | 3.1 所有开启档位均阻止未适配链路；提供显式切换原生服务商入口，不静默降级或只清洗初始提示 |
| 图片／截图／带图插话 | 本地 OCR 后实际像素遮盖、移除元数据；校验发送的是处理件 | 未完成像素处理时阻止原图，允许用户改发脱敏文本 |
| PDF／Office | 本地提取并处理文本，派生预览同样保护 | 二进制直传未覆盖时阻止 |
| 语音 | 原始音频外发前决定策略；本地 ASR 的文本可脱敏 | 严格档不调用云 ASR；转录后脱敏不能宣称音频未外发 |
| embedding、rerank、TTS、第三方 OCR | 按外部接收方单独登记与过滤 | 未接入功能关闭或明确阻止 |
| 本地 UI／导出／机器人回传 | 本地显示受控还原；共享和远程回传独立判断 | 不把本地显示权限继承给外部接收方 |

多模态遮盖和 CLI 全覆盖可以分批实现，但 3.1 发布时必须有可验证的阻止／能力显示；缺失的完整支持不能记为完成。隐私不是统一网络代理对所有加密流量做拦截，本期不开展 TLS 中间人解密。

## 10. 加密存储与密钥管理

### 10.1 凭据库

AES-256-GCM 认证加密，每次新随机 96-bit nonce；密文带 schema、算法、keyId、nonce、认证 tag。AAD 绑定用途、schema、记录 ID 和所属实例，拒绝把一条凭据的密文调包给另一记录。主密钥由 Windows DPAPI CurrentUser 包装，解锁失败不尝试明文兜底。

Node `crypto` 提供密码原语；不自制算法。正常启动自动解锁主密钥，按需解密，避免每次模型请求都拉 PowerShell；不声称 JavaScript 字符串可以可靠擦除，缩短其生命周期并避免复制与日志。

配置只存 `credentialRef` 和存在状态；运行时解析对象与可写配置对象分离。模型服务商认证头仍需要给该服务商，脱敏处理针对内容，不替换连接本身必需的认证。

### 10.2 加密范围

| 数据 | 3.1 处理 |
|---|---|
| provider API Key／额外认证头／MCP env 与 URL 秘密／机器人凭据 | 第一批统一 vault，环境变量来源保持外部管理语义 |
| 隐私映射与自定义敏感词 | 隐私功能的必需加密存储，不跟随可选“聊天加密”关闭 |
| 配置备份、恢复副本、迁移临时文件 | 不产生新的明文副本，旧副本纳入迁移清单 |
| 聊天、工具结果、记忆、收件箱、附件和派生索引 | 第二阶段可选加密，独立验收；没有完成前 UI 明示仍为现有本地存储 |
| 普通日志、遥测、错误、调试快照 | 最小化＋脱敏；不能靠“日志已加密”允许任意记录凭据 |
| 用户工作区文件、CLI 自有配置／缓存 | 不自动改写；单列覆盖边界和工具访问限制 |

非 Windows 采用平台密钥库适配或用户解锁的加密备份密钥方案；未实现的平台必须明确不支持，不静默明文。后台无人值守与用户口令解锁互斥的体验要说明。

### 10.3 迁移、恢复与回退

持有数据根单写者锁 → 盘点所有凭据字段及备份 → 写入可恢复迁移日志（不含明文）→ 加密写 vault → 逐项解密校验 → 原子切换配置引用 → 验证重启／连接 → 处理旧明文副本并记录剩余项。每步幂等，可在任意断点恢复；失败不能清空原配置，也不能宣称已完成加密。

旧 `.prev` 不得在恢复时重新引入明文。迁移产生的备份同样加密；历史备份需要明确范围处理，SSD／快照／外部备份无法承诺物理安全擦除。

提供应用内“导出无凭据配置”和“加密备份与迁移”。备份由用户口令派生独立包装密钥（Node scrypt、随机盐、版本化有界参数），包内包含恢复所需密钥及数据，认证失败统一报错。导入先限制包大小与 KDF 参数，防恶意备份消耗资源；口令不记录、不进模型、不放 argv。

恢复包必须在另一账户／隔离环境实测。旧版本不认识加密格式，回退应使用明确的兼容备份流程，不能直接把新格式交给旧程序并假设无损。关闭发送脱敏不自动解密全部磁盘文件；密钥轮换、删除和存储加密关闭另设明确操作。

当前恢复包采用“向可用目标配置合并凭据”的契约，不替换已有资料的主密钥。将完整加密资料搬到另一 Windows 账户，或原 DPAPI 密钥不可用时，原资料可能无法启动，原资料内的恢复入口也不能解锁旧库。此时应保留原数据目录、密钥、凭据库、隐私映射及会话；不要通过删库或换主密钥尝试修复。启动错误会提示用户：在启动前把 `RUYI_HOME` 指向一个独立、全新的空目录，运行 `Start-Workbench.cmd`，再从「设置 → 权限与安全 → 本地隐私保护 → 凭据恢复包」选择恢复包、输入导出时口令并预览确认。该流程仅在新资料内重新加密凭据与连接配置，不恢复旧聊天、隐私规则或代号映射，不改变旧资料。读取旧资料仍需要原 Windows 身份和可用密钥。恢复包口令错误单独报认证失败，不解释为旧库解锁失败。

## 11. 设置与日常体验

- 凭据加密：新配置默认关闭；用户明确开启且完成迁移才显示“已加密”。当前账户自动解锁，换机需在全新资料内导入恢复包或重新输入。
- 发送前隐私保护：默认关闭，用户开启；密钥保护（凭据／自定义规则）、个人信息保护（增加个人资料）、保密内容保护（增加明确保密标记）；技术信息单独开启。所有开启档位均阻止尚未覆盖的链路。
- 聊天和附件加密：独立开关，仅在该阶段实现并验收后显示。
- 当前档位和规则是应用全局设置。用户可在设置页修改，也可明确要求管家整理规则或切换档位；管家变更须校验当前用户来源、独立正反例和版本条件，并在成功回合结束后保存，不能根据外部内容自行降低保护。
- 开启时对当前下一次请求的全部历史重新生成模型视图，不能只保护新输入。旧 provider 服务端会话无法清洗时新建会话；解释已经发出的历史不可撤回。
- 每次发送使用规则版本快照；用户开启／收紧时使未发送旧快照失效，后续工具结果和请求重新处理。已经发出的请求可中止但不能撤回其内容。
- 输入旁显示“已替换 2 处凭据、1 处邮箱”，展开看真正模型副本、命中原因与覆盖状态。自动工具循环不反复弹窗。
- 首版所有类别都提供关闭／调整入口，但不能借此关闭已有的安全日志脱敏。用户关闭整个可选功能恢复既有内容发送行为。
- 本地回复可还原普通业务信息；凭据默认遮盖。流式输出用有界缓冲处理完整代号；复制、导出、共享需要明确的脱敏／原文选项。
- 未知代号、映射丢失、存储不可解锁、规则超时、媒体无法检查等用稳定错误码；界面提供重试、修规则、换支持引擎等实际动作，不只给路径。

## 13. 验收矩阵

所有测试使用合成值和隔离 HOME／AppData／数据根，不读取真实用户凭据，不把真实敏感内容发给测试模型。

| 测试组 | 必须证明 |
|---|---|
| 识别语料 | 每类正例、反例、引号／转义／中文／多行、敏感字段与 tokenCount 区别、重叠、跨 chunk、长输入 |
| 可逆与类型 | 同值同代号、不同 scope 隔离、原字节还原、不误规范化、类型保真、过期／删除／伪造拒绝 |
| 自定义规则 | 字面／字段／regex、优先级、冲突、超时、导入限制、异常不得漏发、规则不被 agent 改写 |
| 工具闭环 | 文件／搜索／stdout／stderr／嵌套返回先脱敏；模型用代号再查文件／业务字段成功 |
| 权限／注入 | 跨会话、网页伪造、禁用字段、密钥到 URL／shell／邮件、错误服务、路径越界、审批后改参均拒绝 |
| 请求捕获 | chat／responses／anthropic、流式／非流式、管家／子任务、压缩／标题、插话、重试／切换、恢复均无合成秘密 |
| 历史与记忆 | 开关后旧历史再过滤；本地显示还原不回流；跨线程重发引用；主动记忆不会存明文凭据 |
| 媒体与 CLI | 图片像素和元数据、二进制文件、音频、未支持 CLI 明确阻止；仅扫 OCR 不计通过 |
| 加密 | GCM 篡改／错误 AAD／错误 key／随机 nonce、DPAPI 正反例、引用调包、无明文备份和日志 |
| 恢复 | 每个迁移断点、损坏文件、磁盘满、解锁失败、重启签发一致、恢复包独立解锁、轮换和删除 |
| UI | 开关／规则预览／覆盖状态／阻止原因／恢复／新旧会话，中英文与镜像语言包一致 |
| 性能 | 固定硬件上 10 KiB／100 KiB／1 MiB 的延迟和峰值内存，规则数／映射数上限，不能通过截断未扫描内容换速度 |
| 发布 | 构建／清册新鲜度、全单测与 Windows e2e、独立审查、真实离线包和升级副本 |

请求捕获测试须包含随机合成哨兵，断言原值不存在于请求正文、查询参数、调试输出和工具错误中；认证层允许的服务商认证头单独断言目标绑定。仅检查屏幕星号或 detector 返回值不算端到端保护。

质量评测记录两条轴：泄漏／误报与任务完成率。使用同一组合成任务做关／开对照，包括订单检索、文件读写、调试、含邮箱的表格、含私钥的错误日志和管家偏好复用；发布材料列明实际观察，不编造“零损失”。
