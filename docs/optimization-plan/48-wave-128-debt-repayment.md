## §0 为什么叫「偿债」

107 波连续撞到的几件事是同一层地基的裂缝，在它们上面叫 3.0，「更可控」这个承诺对不上：

- **默认值被冻在盘上**：`normalizeConfig` 是 `{ ...defaultConfig(), ...raw }`，而任一次写盘都把**整份合并配置**
  落下去 ⇒ 装过一次的机器上，每个键都实打实写着当年的默认值，此后产品改任何默认值，存量安装一个也吃不到。
  T1 只能靠一次性迁移补三个键；P1 又测出降级再升级会把用户关掉的开关重新打开（Brief §4.2 第 24 条）。
- **陈旧快照盖回新数据**：撤回被垂死回合的旧副本盖回（F7b 修了撤回这一条），但守卫是**按事故一条条手攒的**
  （路由覆盖、权限档覆盖、桌面工具覆盖、任务序号高水位、撤回代数，已第五个），其余读改写调用方跨在撤回上时
  「说 ok 其实没落上」（Brief 第 15–18 条）。
- **测试框架会误杀、会静默挂死**：`taskkill /T` 按父进程号找子孙，进程号复用时带走别人的树（F8 真杀过用户的
  Ollama）；各测试复制的 CDP 客户端在 socket 已关时静默挂到超时（Brief 第 19–20 条）。这两件让「全量绿」
  这句话本身不够可信。
- **G3 三个测试缺口**：简易模式零渲染覆盖、管家壳没有像素基线、人工键盘与真读屏没做。

## §2 128a 设计（主会话定）

**语义**：没碰过的设置跟随产品当前默认；碰过的设置永远照你的。

1. **显式键集合** `configExplicitKeysV1: string[]`，与 `configSchema` 一样是簿记键，随盘落下。
2. **落盘投影**（唯一写口 `writeConfigAtomic` 的输入）：`configSchema`、`configExplicitKeysV1`、**显式键**的值、
   以及**本版不认识的键**（原样保留——更新的版本写下的键，降级时不能被我们抹掉；2.7.0 正是这样保住了 2.8.0 的键）。
   等于默认值且不在显式集合里的键**不落盘**。
3. **什么算显式**：
   - 经 `mutateConfig` 的一次写入里，归一化后**值变了**的键（设置页、API、管家改设置、产品代用户记的状态如
     `lastUsedEngineRoute`，一律同一口径——「被改过」）；
   - 读盘时，盘上**出现**、且归一化后**不等于当前默认**的已知键（手改 `config.json`——手册就教用户这么关开关；
     以及旧版本写下的整份配置）。
4. **迁移按显式键判，不只按 schema 号**：`< 12` 那道三开关迁移跳过显式集合里的键 ⇒ 用户在新版里关掉的，
   降级到 2.7.0（它把 schema 写回 11、但保留不认识的 `configExplicitKeysV1`）再升回来也不会被重开（治第 24 条）。
   `< 9` 的 `engineMode` 迁移同样跳过显式键。
5. **首读即清理**：盘上等于默认、又不在显式集合里的键在第一次读时就被写回投影清掉 —— 不清的话，下次默认
   变了它们会被第 3 条的「手改」规则误认成显式，又冻住。
6. **`changed` 改判据**：是否写盘 ＝ 投影与盘上内容是否不同（不再是归一化过程中的内部标记）⇒ 派生值
   （如没设工作区时 `defaultWorkspace` 取家目录）每次读都重算、但不在投影里，不会造成每读必写。
7. **旧文件**（schema < 13，含降级往返后的）：第 3 条第二款把与当前默认不同的键都记成显式 ——
   等价于今天的行为（不会比现在更差），从此以后才享受「没碰过的跟默认走」。已知代价：降级到旧版期间旧版写下的
   **与新版默认不同的旧默认值**会被当成显式冻住（与今天相同）；在旧版里做的改动**保留**（不丢用户数据优先）。

**粒度**：键级。嵌套对象（`desktopMcp`、`storagePolicy`…）里某个子字段的默认变化，仍要走迁移。

**不改**：`normalizeConfig` 返回的内存视图照旧是整份（所有消费方零改动）；`GET /api/config` 形状不变。

## §3 纪律（每片都适用）

- 进程安全：只杀自己 spawn 的 PID（认子孙须核创建时间）；禁按名字杀；开工与收工各拍一次进程快照对照
  （[46 号文 F8 事故](46-wave-107-release-approval.md)）。用户的正式工作台（`dist/Ruyi-slim`，8765）与 Ollama 是禁区。
- 回归：`run-all --parallel 4`，控制台存档到文件、读 `EXIT=`；**跨轮重现的偶发件按真缺陷取证**。
- 生成器链在最后一次 `src/` 改动后整条重跑；控制字符／CR 扫描；反向验证每把新锁。
- 起服务的演练只用合成数据。
- 本地提交，不推送。
