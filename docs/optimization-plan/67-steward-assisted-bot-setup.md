# 管家代办外部机器人配置

设计日期：2026-10-17。基线：`88b02524`；实施分支：`codex/steward-3x-implementation`；当前应用版本 3.0.1。承接 [62 号主线](62-steward-3x-iterations.md) 与 [66 号远程控制](66-external-bots-and-steward-channels.md)。本批由主 agent 设计、独立验收和维护文档，6.1-sol 子 agent 实现后端、界面与凭据模块。

## 用户目标

用户说“帮我接上 QQ／飞书机器人”，提供已有应用资料，管家能判断还缺什么、准备配置、引导录入秘密并验证状态。用户不必自己决定连接 ID、环境变量名或查出自己的平台发送者与聊天 ID。最终结果仍是从外部聊天远程控制同一个如意管家，而不是只导入收件箱。

本批分清三类事情：管家可以直接代办的本机非秘密配置；专用输入框处理的秘密；本人远程控制权的最后本机确认。平台创建应用、机器人权限审批、事件订阅、HTTPS 入口不是普通本机配置，缺少这些外部条件时，管家给出具体下一步，不承诺已经替用户完成平台操作。

## 固定旅程

1. 用户提供平台和应用信息。QQ 本批需要 AppID；飞书需要 App ID、tenant key 和机器人的 open_id。管家读取现状，再询问缺项及获取位置，不猜测、不把昵称当身份。平台应用信息只需提供一次，不要求用户先读管理员手册或构造 JSON。
2. 管家调用专用 `steward_bot_setup` 工具检查或准备连接；自动生成连接 ID，连接保持禁用。工具真实成功后，回复提供“继续配置机器人”入口，打开这一条连接的配置引导。
3. 用户在专用密码输入框录入 QQ Bot Secret，或飞书 App Secret、Verification Token、Encrypt Key。输入直接到本机凭据管理接口，不经过聊天、模型工具参数、行动参数或浏览器持久缓存；系统只向管家返回“已提供／缺少／不可读”和来源。
4. 本机启动短时配对，显示回调地址与一次性配对码。用户在平台完成事件回调设置，向机器人发送该码；群内需要 @ 当前机器人。系统验证平台签名、应用和租户后自动获得发送者、聊天类型和聊天 ID，配对消息不进入管家执行。
5. 本机显示配对候选及“共享现有任务和管家上下文、群内回复所有成员可见”的范围。用户确认后，系统原子写入 owner、两个白名单与控制启用状态。任何旧页面、过期配对或配置变更都不能复用这次确认。
6. 界面显示“已启用，等待首次真实指令”。管家只根据事实解释进展；首次真实执行与平台回执是另一层证据，不能用凭据非空或配对成功冒充端到端验证。

常规非秘密资料可直接发给管家；密码框是这条对话旅程中的专用录入口。若用户主动把秘密贴到普通聊天，本批不能承诺自动识别任意格式或清除已经发送给模型的历史；提示词须明确不索要明文秘密、不重复引用、不建议通过 shell 或通用配置工具绕过专用入口。

## 工具与授权

新增窄工具 `steward_bot_setup`，提供 inspect 与 prepare。参数仅允许非秘密应用身份、显示名和已有连接 ID。inspect 返回缺项、配置状态和明确的后续步骤；prepare 只创建或复用完整身份的禁用连接，不修改已启用连接、不切换 owner、不启动配对、不授予控制权。资料不完整时返回结构化 missing，不保存一个因身份不可变而无法补齐的半成品。

写配置必须来自真实本机用户回合。`external`、`inbox`、缺失或伪造来源不能以工具调用准备新远程控制入口；模型传入 `userPressed`、`enabled`、凭据或 `controlConfirmed` 也不获得授权。最终启用通过本机专用接口核对服务端配对证据，不借用通用 act 的裸 `userPressed` 布尔值。导航卡只定位设置，不承担任何授权。

外部内容污染闸沿现有工具契约保留，网页、文件或平台文本不能把接入配置当成自助指令。工具返回真实结果，模型不能凭一句“已配置好”改变状态；界面显示权威阶段和缺项。

## 一次性配对与竞争保护

只有本机管理 token 能开启配对。连接必须禁用且当前凭据和平台应用身份完整；窗口五分钟，随机码至少 128 位熵，内存保存，重启即失效。配对码只向本机引导页面返回，不进入模型上下文或普通行动日志。

回调复用 66 号完整协议校验及原始字节保护，不放松飞书 tenant／bot 身份限制。仅在专用窗口接受精确的配对文本，首个合格候选固定后其他来源不能替换。非配对普通消息不会成为指令，配对不入收件账、不调用模型、工具或平台发送。平台地址 challenge 只完成地址验证，不能成为身份候选。

最后授权绑定连接完整快照、凭据版本与配对窗口身份，在原有状态串行锁内复核并持久写入。更换凭据、重新配置、停用／删除、过期、重启或其他页面先提交都会使旧确认失效。配对成功只证明某个账号能向该机器人发消息，本机用户仍须确认它就是本人所选聊天。既有 65 号执行身份和 66 号撤权／去重逻辑继续成立。

窗口内所有通过验签、只作为配置消息处理的事件，都必须在确认回调前持久保存去重凭据（规范来源键与内容摘要，不保存正文或配对码）。只有写成功才记录内存候选；最终启用的原子写再次核对并保留对应凭据。否则平台在启用或重启后重投配对码，甚至重投窗口中曾被忽略的普通文本，都可能误变成新的控制指令。后续回调先匹配这份最多 4096 条的凭据：同一消息换 eventId 也只确认，不进入管家；相同来源键内容冲突则拒绝。容量不足时拒绝新增配对消息／授权，不能悄悄删除旧去重凭据；旧 schema 1 文件可缺少此新增可选表。

## 凭据保存

现有 provider 配置是本机明文加出站掩码，没有可直接复用的系统加密库。本批新增机器人专用凭据存储：Windows 使用 DPAPI CurrentUser，保持 Node 零 npm 运行时依赖，经系统 PowerShell／.NET 调用；秘密通过受控标准输入传递，不写命令行或环境变量。进程隐藏启动、限制时间与输出，失败只返回稳定错误码，不能降级保存明文。

持久化采用严格、有界、原子写的独立密文账，绑定连接身份。读取缺文件不创建；损坏、未知 schema、解密失败都显式失败，不当作空库，不用失败写缓存冒充成功。GET 与工具只返回是否存在、来源及错误；不返回密文、明文或可执行命令。凭据只在禁用连接时更改，并撤销配对窗口，防止确认期间替换应用秘密。

密文账为数据根下 `external-bot-credentials.json`，最多 64 条凭据记录（包括保留版本的删除记录）、4 MiB；不自动驱逐旧记录。该文件、临时／备份族及硬链接别名沿现有敏感数据策略禁止模型读取、搜索、预览和修改。远程控制授权账 `external-bots/` 同时纳入精确敏感子树保护，覆盖正本、临时文件和硬链接别名，避免通用文件工具绕过管理接口修改 owner／白名单；无关项目同名文件不受影响。合法账本内单条密文解不开时仍显示错误与不含秘密的版本；只有禁用状态、版本匹配且显式完整替换时可跳过旧解密恢复。本机来源的所有槽必须重新填写，环境来源的槽明确删除未使用的旧本机值，环境引用本身不变。局部更新不能借恢复丢失其他秘密；损坏 JSON／schema 不能经此入口覆盖。

每个字段来源明确：存在环境变量引用时只读取该引用，否则使用本机保存值；缺失环境值不会静默回退另一份旧秘密。原有 env 配置继续可用。非 Windows 本批不保存 DPAPI 凭据，明确提示使用已有环境变量方式，不落明文。DPAPI 保护以当前 Windows 用户为边界，不宣称防御同一用户身份下的恶意进程；换账户／迁移机器后的解密需实际验证，失败时重新录入。

依据：[Microsoft ProtectedData](https://learn.microsoft.com/dotnet/api/system.security.cryptography.protecteddata) 说明该 API 依赖 Windows DPAPI；[数据保护用法](https://learn.microsoft.com/en-us/dotnet/standard/security/how-to-use-data-protection) 说明 CurrentUser 的使用方式。核查日期 2026-10-17。

## 界面与状态

沿用现有管家设置的紧凑表单、主题与字体令牌。对话入口定向打开当前连接；高级手工配置继续保留。密钥输入按平台显示，保存后清空，不回填掩码假值。配对期间仅在引导可见时有界刷新，关闭、换连接、换服务进程后旧回包不能覆盖新界面。

界面分别展示：应用信息完整、本机凭据可读、配对已验证、控制已启用、首次真实执行、平台已接收回复。任何读取错误保留上次可信事实并标明陈旧，不伪装为空白成功页。中文／英文、明暗主题与 1440／768／390 宽度均需验收。

## 验收退出条件

- fake provider 驱动生产管家工具 prepare，真实落下禁用连接；完整信息自动配置、缺项不猜、不完整不写、重复准备不造重复连接、已启用连接不被改写。
- 远程／收件回合及伪造来源、权限字段不能准备或激活；普通消息、坏签名、错应用／租户、群内未 @、猜测配对码不产生执行或配对成功。
- 本机秘密表单 → 真实 Windows DPAPI → 严格持久密文 → 服务重启仍可用于平台协议；日志、provider 请求、聊天、SSE、行动参数与 GET 回包不出现测试秘密。错误、取消、超时、损坏、写失败都不降明文。
- 配对首个候选、过期／重启、并发抢占、凭据或连接变化、旧确认与重复提交都受到约束。最终本机授权后，新的签名指令通过真实管家工具并回原消息；配对本身和启用／重启后的配对事件重投均零模型／工具／外发。
- 生产浏览器完整旅程，包括中文／英文、明暗主题、三档宽度、关闭／切换／重启、异常与草稿保护。
- 原有机器人 control、inbox、发送适配和本机管家行为回归；构建、清册、零依赖、分发载荷、全量单测和静态门禁。

## 后续切片

本批先消除本机手工环境变量、owner ID 与重复填表。下一步可通过用户明确发起的固定官方 API 探测，自动发现飞书 tenant key／bot open_id 并核验权限；该网络探测须有独立超时、错误与凭据边界，不放松验签来“发现”身份。专用真实账号和 HTTPS 联调继续沿 66 号 B 批，平台进度通知与远程待决保持原后续范围。

验收期间发现并修复：配对消息缺少持久去重会在启用后重投为指令；授权账可经通用文件操作绕过管理接口；凭据解密失败的恢复与局部状态误报；迟到读取覆盖写入结果；配对到期时间未随界面语言格式化。真实 PowerShell 首轮暴露 System.Security 加载方式不兼容，改为 Add-Type 后真实 DPAPI 全部重跑通过。

测试本身的失败也保留原因：浏览器切页未等列表／引导可见，截图最初拍到设置顶部；回复状态断言漏掉既有文案中的“API”；主验收曾误用不存在的 inbox 脚本名；旧工具数量快照、英文术语和剪贴板登记未同步。均修正或按正确脚本重跑，未把这些首次失败算作通过。普通提示包经逐项比较没有改变，版本保留 `2026-w138-2`，只更新管家提示内容。剪贴板例外仅允许平台回调地址与配对码，秘密复制反向探针保持失败。

本批没有真实 QQ／飞书账号与公网 HTTPS 联调，没有构建或发布安装包，也没有部署网关。平台创建应用、权限审批、事件订阅仍由用户在平台完成；飞书 tenant key／bot open_id 的官方 API 自动发现仍属下一切片。本批完成的是如意本机的对话准备、凭据录入、配对与授权闭环，不以假平台的成功回执宣称真实平台已上线。
