## §2 129a 提示词预算：字符 → token

**实测**（2026-09-20，判据用仓里自己的 `estimateTextTokens`：`ascii/3.6 + cjk/1.5`）：

| | 稳定层 | 规则层 | 现行闸 |
|---|---|---|---|
| 中文 | 1149 字符 = **596 tok** | 968 字符 = **507 tok** | ≤2500 ／ ≤2480 **字符**，两包共用 |
| 英文 | 2455 字符 = **682 tok** | 2444 字符 = **679 tok** | 同上 |

同一把字符尺子，2500 字符对纯中文 ≈1660 tok、对英文 ≈695 tok —— **英文拿到的真实预算只有中文的 42%**。
后果不是抽象的：`06b` 的注释里明写着有四条已经想清楚的规则（问候 ≤120 字、清单每条 ≤30 字、
转述交付拆成「结论／关键数字／没取到的」三行、「我做不了」不解释一段）**因为英文包的字数闸而留在注释里没进提示词**。
而「中文还剩一半空间」是**假余量**：按 token 算两包分别是 596／682，本来就差不多。

**改**：闸按 token 记，两包各判。新值 **稳定层 ≤900 tok、规则层 ≤860 tok**（仍保持 27 号文
「规则层不许比稳定层贵」那条关系）。这个数**比原意更紧**，不是放水：2500 字符对中文本来就等于 ≈1660 tok。

`steward_config_get`：**不给 key、不给 baseUrl**。

### 129a 提示词预算换成 token ＋ 补上卡在注释里的四条规则（2026-09-20，主会话亲做）

**改了什么**

- `14-main.js` 导出 `estimateTextTokens`（静态锁要用**产品自己那把尺子**量，不另写第二份判据）。
- `steward-runner.static.e2e.js` ③ 段：稳定层 `≤2500 字符 → ≤900 tok`、规则层 `≤2480 字符 → ≤860 tok`，
  中英各判；另加两条自检（尺子拿不到就红、中英文都量得出非零 token）与一条粗带（两包真实开销差 ≤35%）。
- `06b`：用腾出来的余量把**四条本来就想清楚、却因为英文字数闸留在注释里**的规则放进提示词 ——
  问候 ≤120 字、清单每条 ≤30 字、转述交付分三行（结论／关键数字／没取到的）、
  以及新起一行的「做不了的事一句话收，不解释为什么不行、不背规则条款」。中英同步，条数仍逐条对齐（各 12 条）。
- `06b` 管家包头注那句**陈述已经作废**：原文「它的工具面只有 17 个 `steward_*`，技能/playbook 那些层对它没有意义」——
  今天 33 个，而且它**能**改线程技能、**能**起草 playbook 却看不见清单。改成如实写，并点名由 129b 按管家口径补那两层。

**读数**

| | 稳定层 | 规则层 | 合计 |
|---|---|---|---|
| 中文 | 596 tok（1149 字符） | 507 → **572 tok**（1085 字符） | 1103 → **1168 tok** |
| 英文 | 682 tok（2455 字符） | 679 → **771 tok**（2774 字符） | 1361 → **1453 tok** |

**反向验证 7 条**（逐条还原、构建失败即停、sha 一致）：
① 撤掉 `estimateTextTokens` 导出 → 「尺子在」红（后面几条不再是「比空气」）；②③ 中／英分档那条的三个数改回粗档 → 各自红；
④⑤ 删掉／改写「做不了」那条 → 中英各自红；⑥ 往英文规则层灌 400 tok → `≤860 tok` 红（**验的是闸真在量，不是「拿掉锁」**）；
⑦ 只给中文包灌料 → 35% 粗带红。

**⑦ 先做小了一次**：第一版只灌了 200 tok，没红。量过才知道要把中文包撑到 2484 tok（≈+1600 汉字）才顶得破 ——
**这条粗带抓不了小改动**，真正管住绝对开销的是两个 per-pack 闸、管住「只给一包加规则」的是条数对齐。
这句话已经写进那条断言的注释里，免得下一个人以为它是精度判据。
