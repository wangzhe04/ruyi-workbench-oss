# 单事项多步骤交办

2026-10-18，62 号第六轮首片。源码实现与隔离行为、真实浏览器、本机 DeepSeek 验证完成；未发布。

## 范围与执行

在既有 `steward_thread_new` 增加可选 `steps`，2–8 项，每项包含任务正文和 read/edit/exec 工具档，默认只读。事项归属仍由原会话身份表示：只建一个自成事项的协调线程，不另开多条任务线程。首版按数组顺序生成 `step-1 → step-2 → …`，不提供任意 DAG 编辑；`missionId`、`relatedSessionId`、Playbook 与步骤计划互斥。输入不齐、无 provider、代理/DAG 关闭或预算不足时，创建之前拒绝。

步骤保存于委托书，首次可信管家启动将整张图交给原 `launchOrchestrateFromTurn` / `runAgentWorkflow`，不是请模型自己决定是否提交。复用模型选择、原权限档、回合代理预算、DAG 预算、共享/独占工作区租约、依赖结果注入、节点证据与交付信封；不增加原生工具、HTTP 路由或新存储。协调线程该回合只读和汇总，不能再开另一张图或自行重做写步骤；后续明确指示仍走原继续/工作流动作入口。

运行事实存于既有 Agent run，`kind:steward_delegation`。`steward_runs_status` 为这种运行附带逐步骤状态、依赖、等待权限与错误；工作台现有班组画布可显示进度和产物。首次回执只报告 accepted，不说执行成功。完成信封在真实工具记录中保存并登记原 delivered 身份；重复完成通知可保留日志原件，但不会重复注入模型。最终文字由协调模型生成，不能替代节点状态与实际文件证据。

## 权限、停止与恢复

普通子代理保持原无交互行为；本类节点沿协调线程的 `requestNativePermission`、写边界预检和原逐项 CAS 决定入口创建真实待决。拒绝、能力禁止和工具级越界必须令步骤失败，不能被随后非空文本改成成功；拒绝后立即退出同一响应的剩余工具批，后序不启动。

权限等待按节点登记，工作流与节点空闲看门狗以及节点自动收尾不会把等人当卡死；决定返回时移除登记并恢复计时。停止沿父 abort 到 run/node，取消只处理自身 permission request，经原自动决定 CAS 清理；已在 applying 的决定不被另一条清理吞掉，返回后再检查 abort，避免停止后执行。两处新增会话保存均带既有执行所有权与回合代数守卫；旧 DAG 晚退不得覆盖新回合。

本类节点逐工具读取当前会话权限，后序不能继承启动时更宽的快照；旧待决批准返回后、资源租约取得后再次判门，已收紧为 plan 的操作不会执行。普通子代理及显式请求级权限覆盖保留原优先级。相应三个正反行为场景均已回归。

此类运行即使纯读、即使开启 `autonomyAutoResume`，重启后也转人工恢复：不能证明结果就不自动重放。后续消息不会从持久委托书重建旧图。人工恢复/重试沿已有工作流入口，先核对已有产物；不承诺节点内部任意外部副作用可撤销。事项容器、一次 DAG 与相关线程导航继续是不同概念，没有跨既有线程的自动依赖。
