# 隐私规则目录、识别策略与维护规范

更新：2026-10-20。属于 [81 号 3.1 隐私方案](81-privacy-vault-and-tokenization-31.md)，实施见 [82](82-privacy-31-implementation.md)，最新识别补强及多代理验收见 [85](85-privacy-rule-and-settings-regression-31.md)。本目录定义目标覆盖及验收；“设计项”不是已支持能力。扩展目录保持 45 个规则 ID，当前版本见 `app/src/01i-privacy-rules.js`，初始规则和精确凭据匹配在 `01h-privacy-core.js`；原生文字请求与工具返回已接入生产网关。版本 3 新增集成凭据、卡有效期、车辆标识、工号／门禁卡及个人主页五条规则；后续版本沿用稳定 ID 补强格式。

## 1. 分类和默认值

| 档位／来源 | 内容 | 原则 |
|---|---|---|
| 基础 `basic` | 凭据、认证、私钥、恢复材料、支付认证 | 开启隐私保护后默认启用 |
| 增强 `enhanced` | 联系方式、身份、金融、健康及有明确标签的个人资料 | 用户选择增强档／对应类别后启用 |
| 技术 `technical` | 内网 IPv4、明确 client_ip／xff 等字段中的公网 IPv4、MAC、用户名路径 | 独立可选，避免默认破坏调试上下文；不是全部内部主机或 IPv6 识别器 |
| 保密 `confidential` | 项目、组织内部标识、商业资料 | 用户词表／字段／标签驱动 |
| 已知真实值 | 运行时实际使用的凭据和用户明确指定秘密 | 精确匹配优先；不被普通类别关闭或宽泛例外放行 |

每条规则保存稳定 ID、类别、版本、档位、识别依据、匹配范围、可解释原因、正反例及边界。不能用“高熵”“包含 password”替代整套策略；识别出候选格式也不能证明内容是真实有效凭据。

模型得到的类别使用 CREDENTIAL、EMAIL、PHONE、IDENTITY、PAYMENT、INTERNAL、PATH；目录中的细分类保留在本地元数据，不把精确诊断或身份类型作为额外提示泄露给模型。

## 5. 自定义契约与冲突

1. 用户可单独控制扩展规则 ID 的启用；未知 ID 和非布尔值必须拒绝，不能静默忽略拼写错误。
2. 已知凭据精确匹配不随普通模式关闭。用户关闭整个隐私功能是另一项可信 UI 操作。
3. 自定义规则支持：字面秘密、精确字段 pointer、项目／路径／工具／接收方范围、动作和有效期；这些范围必须在网关落实后才能显示为可用。
4. 后续正则只能在可强制终止的 worker 中运行，限制输入／时间／匹配数，拒绝无界脚本；超时会阻止发送。
5. 重叠区间取完整并集。CREDENTIAL 优先；不同业务类别冲突保守提升为 INTERNAL，避免把混合敏感内容借邮箱权限还原。
6. 同值后来发现更敏感用途时，现有引用权限收紧；不能因早先判为邮箱而允许后来的密码上下文外发。
7. 自定义 allow 不可用一个广泛规则放行已知凭据或伪造工具授权。规则命中与操作授权分别处理。
8. 规则修改生成新版本；生效前本地试验，显示原文区间、类别、原因和真正模型副本；敏感试验材料不保存到普通日志。

## 6. 编码与结构完整性

目录覆盖的是语义和入口，不只是一串正则。接线必须覆盖 JSON／JSONL／CSV／YAML／XML／HTML、命令输出、嵌套工具结果、URL 编码、引号转义、跨页／跨 chunk、多行秘密和模型历史。支持状态必须逐项验证。

结构数据优先解析；数字证件不得经 JS Number 丢精度；控制键与业务数据键分开。Base64 等只在明确字段和有界长度内解码检测，不能递归无限解码或把所有二进制当文本。大小上限触发阻止／分页，不能放行没扫描的尾部。

## 7. 维护和验收

- 每条新增可执行规则有至少一个正例与一组对应反例；合成值，不存生产密钥。
- 新前缀需要参考平台原始资料，并注明只是候选识别。GitLab 默认前缀可由自托管管理员修改，所以不能据 `glpat-` 规则声称覆盖全部 GitLab 秘密。[GitLab Token 文档](https://docs.gitlab.com/security/tokens/)、[管理员设置](https://docs.gitlab.com/administration/settings/account_and_limit_settings/)
- Hugging Face 官方用例展示 `hf_` 形式；仍需精确值和字段规则覆盖后续格式变化。[官方 Token 文档](https://huggingface.co/docs/hub/security-tokens)
- 定期记录漏报、误报、性能和任务完成率；不收集真实敏感样本用于遥测。普通日志继续最小化，不能因为有 vault 就容许日志明文。[OWASP Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)
- 每次版本变更跑规则语料、长输入上限、请求捕获和工具还原反向测试。界面展示“覆盖范围和已知限制”，不使用“已检测全部隐私”。

规则目录不是授权清单，也不是合规结论。新增识别类别不自动授予 agent 保存长期记忆、使用凭据或对外发送个人信息的权力。

## 8. 当前产品接线边界（通用工具与档位补充）

默认关闭、凭据加密选择、工具范围与性能契约详见 [84 号](84-privacy-tool-transport-and-profiles-31.md)。

- 应用内可选 off／basic／enhanced／strict；技术信息独立勾选。自定义 literal／完整 JSON Pointer field／regex 最多 100 条，其中正则最多 20 条、源码最多 1024 字符，flags 支持 gimsu（不得重复）。显式开启凭据加密时，规则值加密保存；关闭加密时，关闭状态下保存的规则沿用本机明文配置格式。普通配置掩码投影不返回规则值。
- 正则只在独立 worker 中编译、执行；单次扫描运行预算 250ms、启动预算 3s，同时最多两份作业。每个候选最多 1MiB、总计 8MiB／五万个候选、一万个命中；超过上限、空匹配、崩溃、超时均拒绝，不发送未扫描尾部。自定义 JavaScript 不可执行。保存验证语法；样本相关的零长度命中在试验／实际扫描时拒绝。
- 已知配置秘密对所有非空值精确匹配，包含短凭据和超过 4096 字符的值。收集 API Key、具有凭据字段名或 Bearer／Basic 证据的认证头／环境、URL userinfo 与敏感 query 的解码值、MCP 显式秘密参数；不把 PYTHONUTF8、PATH、Content-Type、版本头或普通端口等无关参数标为凭据。未知字段仍由内置格式识别及用户规则保护，不能承诺从任意自定义命名推断所有秘密。极短的真实凭据可能大量误报，控制字段被命中时明确拒绝；不再为了保持流畅而跳过短值。已知值与自定义规则合计超过检测器容量会拒绝请求。
- 设置内可试验未保存规则，显示脱敏结果、规则 ID、类别、片段偏移和规则版本；试验与生产共用网关，不写配置、映射或样本日志，结果与错误均 no-store。通用配置补丁不可修改隐私三项，规则保存必须经过专用验证。
- 配置损坏、旧备份自动回退或既有安装的配置丢失时，保持策略未确认状态并暂停外发；设置页核对并保存才恢复。非法隐私字段不能归一化成“健康的关闭”。专用恢复标志由配置持久化，普通配置补丁及管家不能清除。
- Chat／Responses／Anthropic 的出站文字请求、重试、主／子任务、辅助补全统一扫描。嵌套 JSON 按业务数据解析，协议控制字段单独保留；拒绝控制字段发生敏感替换。
- 已登记的原生工具及应用管理的 MCP 工具统一还原嵌套文字值、数组与对象键，包含凭据代号；工具名和代理目标必须属于真实登记项。还原后仍过原权限、工作区、敏感文件与网络目的地检查；代号本身不授予操作权限。未知、过期、跨 scope 引用拒绝。
- JSON 的自定义命中必须能证明已由叶值脱敏完整覆盖，跨越 JSON 语法或依赖 source 上下文而无法安全替换时拒绝。转义叶值必要时整体保存原始拼写，防止解码偏移错位和 file_edit 回退失真；凭据分类不能因此放宽。
- CLI、独立 MCP 工具／资源、服务端内建工具、图片、音频、带签名／加密思考目前拒绝。覆盖表与切换默认原生服务商入口已经接通，不修改已有会话固定路由。MCP 在返出正常结果及错误时重查持久策略；旧语音会话逐次检查，清理 DELETE 不受阻。上传 OCR／图片压缩在调用 MCP 之前阻止。没有声称支持它们的透明转译；任意编码递归、完整媒体及 CLI 原生工具覆盖继续单独验收。
- 同 scope 已识别原值在后续无标签文本、工具验证读取及副本中继续精确匹配；有限轮重扫原输入，避免先出现副本、后出现字段造成漏发。raw／decoded 拼写作为关联别名共同收紧分类、过期和撤销；加密持久化后重启保留，其他 scope 不继承。每次转换共享有界扫描工作与命中预算，失败不会放行未完成的扫描，也不会留下失联别名。
- 文件分页、行号、偏移、搜索、符号、文档、画像、审计、Git 差异与管家摘读先扫描完整来源，再从带本地证明的视图裁切；字段统计继续使用原值。旧原文缓存不复用，编辑未命中的诊断也先投影。来源有大小与数量预算，新学习信息使旧视图失效时拒绝，不能回退原文。
- 原生命令及登记工具可正常执行并统一扫描文字返回；第三方工具已丢失字段标签的摘录、任意编码或语义转换仍无法保证完整识别，应补 literal／regex 规则。工具的媒体与其他不支持载荷仍有能力门。

## 11. 通过管家自然语言管理自定义模式

直接对管家说，例如：“把 EMP- 后跟五位数字的工号作为内部信息识别，订单号不要隐藏。”管家复用现有设置工具读取当前规则、生成窄规则、构造合成正反例、在本机试验并保存；不新增另一份规则库或默认输入框入口。相同工具支持按 ID 修改／删除规则，以及切换 off/basic/enhanced/strict 和技术信息开关。关闭脱敏保留凭据加密；密钥、恢复包和导出不在此能力内。

现有 `steward_config_get` 使用 `{ "privacy": true }` 返回生效规则与 `ruleVersion`。字面量规则只返回 ID、类别与 `valueConfigured`，不把私密原值送给模型，脱敏关闭时也如此；本机设置页仍可编辑。`steward_config_set` 使用空 `patch` 加专用 `privacy` 操作，按 ID upsert/remove，避免整份替换覆盖其它规则或用元数据覆盖隐藏原值。例：

```json
{
  "patch": {},
  "privacy": {
    "op": "preview",
    "expectedRuleVersion": "读取时返回的16位版本",
    "upsert": [{"id":"company-employee","kind":"regex","value":"\\bEMP-\\d{5}\\b","category":"INTERNAL"}],
    "tests": [
      {"ruleId":"company-employee","sample":"EMP-12345","match":true},
      {"ruleId":"company-employee","sample":"订单12345","match":false}
    ]
  }
}
```

每条改动必须具备正反例，并独立运行实际 Gateway 试验，不能借现有内置规则命中来冒充新规则通过。regex 沿用有界隔离 worker；无效、空匹配、超时和试验失败均不保存。正反例是必要门槛，不能证明规则对所有输入都不过度匹配，管家仍须依据用户要求控制范围。

`preview` 只试验。`update` 还需要当前本机用户这一回合的 `sourceRef {sessionId,turnSeq,quote}`，逐字核对真实来源；收件箱、系统唤醒、管家委托、外部机器人及旧回合引文不能授权修改。外界内容污染闸继续生效，普通线程与未开启管家无调用权限，普通 config patch 仍禁止改隐私和密钥字段。

更新先返回 `pending`，本轮正常结束且所有执行空闲后，以读取到的规则版本及凭据加密状态作事务内 CAS 保存。失败、停止、抢占、配置冲突或其它任务仍在运行时不保存，也不留下后台自动重试。实际成功／失败回执进入管家结果和既有决策日志，日志只记模式、规则数量、版本等元数据，不复制正则、字面秘密或样本。设置页与管家读取同一份加密配置；首次明确开启脱敏时同步启用其所需的本机凭据加密。

## 12. 版本 5：实用防误泄密与第三轮边界

产品目标是减少常见敏感信息误发，不是任意编码的完整加密或信息流证明。新增独立合成语料 `third-scenario-corpus.js`：27 个敏感正例、25 个公开／半脱敏／普通编码负例、1 个技术信息开关对照。v4 原格式基线完整覆盖 5/27，半脱敏邮箱另有一处误报；这不是用户漏点保存或未开增强档导致的问题。

保持 45 个稳定规则 ID：补收款卡后的银行名称、保单号、明确车主／受益人姓名、病历叙述、驾照档案编号、明确实体地址、括号区号座机、动态口令叙述、WiFi 历史密码、门禁密码、Telegram 令牌、带 AWS 上下文的临时凭据和 `_PASS` 字段。三段 JWT 允许点号后的单个断行；军式数字读法按带报号／电话上下文的 11 位号码识别。样例“base64 身份证”实际解码为手机号，按解码后的真实格式识别，不照标签捏造证件类型。

订单号、关系称谓、亲子昵称、尾号、已经打星号的姓名／手机／证件／邮箱、裸 UUID／哈希／时间／版本／SKU 等保留。技术 IP 仍由独立开关决定。已打码过滤仅适用于自动发现，不覆盖显式用户规则或同 scope 已学习的精确私密值。

常见 Base64 和百分号编码只识别一层：候选 12–8192 字符，每次检测最多 64 个可解码候选、64 KiB 解码文本；验证 Base64 规范回编码、UTF-8 往返和控制字符，不递归、不解压、不解密。仅当解码文本整体为已识别敏感值才隐藏整个原始编码片段，公开文档／公开 URL 路径不因编码而隐藏。自定义 regex 仍只在原始输入上由隔离 worker 执行，避免将解码内容绕过 worker 缓存和执行约束。工具执行还原原始编码与换行，不替用户解码执行参数。

识别预算限制范围，超过候选／解码预算的后续编码片段不纳入本轮编码识别；普通格式、字段和精确匹配仍照常工作。这一层不承诺对抗特意堆叠的编码载荷，也不以频繁中断普通工具调用换取“全部敏感内容都已加密”的错误保证。正反例、输入框、工具结果、参数还原和真实端点的证据分别记入 85 号报告。

裸自由文本中的凭据按空白等分隔符结束，不推断空格后的普通说明也属于同一密码。带空格的秘密使用完整带引号值、完整 JSON 敏感字段或精确自定义规则；任意未标注格式的 YAML／配置语言语义不属于完整解析保证。

## 13. Oracle 评价与产品边界

本功能定位为本机发送前防误泄密，不是任意代码的能力隔离。`oracle-boundary-probe.js` 使用隔离临时目录和合成值，实跑已注册 PowerShell 工具：完整回显会再次脱敏；取首字符可以输出；直接读取已落盘文件再取首字符同样可以输出。探针不调用模型／网络，也不读取用户数据。不能承诺模型在任意工具能力下绝不间接得知私密值。

仅禁止脚本参数的代号还原不能堵住第二条读取路径，并会损失本地校验、格式转换和数据处理能力。单字符、任意分片、倒序、hex 等出口枚举既会大量误报，也不能穷尽编码、条件判断或哈希等派生结果，因此不作为默认策略。不把订单、公开哈希、普通数字和短尾号扩大为秘密，也不无限解码。

若未来提供强隔离档，应是独立明确的能力策略：控制任意执行、可读取的文件与数据、网络目的地和可释放的结果；可考虑受限代理／句柄工具。单靠检测规则不能提供该保证。本轮不引入会破坏通用工具工作的默认限制。模型提示禁止主动探测隐藏值，但提示词不被计作结构性安全隔离。

参数还原保证原值，不负责推断任意脚本／SQL／URL 的语法转义。含引号、换行或运算符的值应通过工具的结构化参数传递，或写为本地数据再读取，避免直接内联到代码字面量。后续代理／句柄方案还应提供安全参数绑定；“全部注册工具的通用传输契约通过”不等于“任意编程语言中的任意字符串插值都正确”。
