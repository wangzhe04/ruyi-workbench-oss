## 开关与档位

| 状态 | 请求／工具路径 | 存储与开销 |
| --- | --- | --- |
| 脱敏关闭、凭据加密关闭（新安装默认） | 原请求、原返回、原参数对象；不创建代号、不解析转译参数、不启动规则 worker | 不创建映射／主密钥，不自动迁移明文凭据 |
| 仅凭据加密开启 | 工具保持原路径；本地配置凭据在读写时保护 | 只初始化明确启用的凭据存储，不进行模型内容脱敏 |
| Basic | 凭据识别及用户规则；已识别值在本 scope 精确复用 | 不启用个人、内部与技术信息规则；无 regex 不启动 worker |
| Enhanced | Basic 加个人隐私识别 | 同 scope 学习及有界源内容投影 |
| Strict | Enhanced 加内部保密内容识别 | 保持资源上限，不依靠无限重扫提升覆盖 |
| 技术信息开关 | 独立控制私网地址、路径等技术信息 | 关闭时不执行这组规则 |

已有明确启用的加密配置和引用继续兼容，不能因为新默认值擅自解密。脱敏映射需要本地加密，设置页须明确选择加密后再开启脱敏；旧版脱敏开启却缺少该选择的配置暂停外发，等待用户核对。关闭加密只允许在脱敏关闭后明确确认“凭据将以明文保存”；配置原子提交失败仍保留原状态与可解锁凭据。旧 vault 不因关闭而删除，以保留已有备份的恢复能力。

工具与模型数据通路关闭时，在枚举凭据、构造数据识别器、解析转译参数、规则 worker 和映射持久化前返回。开启后无敏感命中的新 scope 不创建主密钥或映射；已落盘且版本未变的映射不重复 AES 加密和写盘。尚未完成的同版本持久化共享同一 promise，失败不能提前发送或记成已保存。

上述保证针对数据处理通路。配置读取仍校验规则配置，恢复票据使用进程内随机值做一致性认证；这些步骤不扫描用户或工具正文，不创建 DPAPI 主密钥、vault 或代号映射。用户主动试验或保存规则时仍可校验自定义正则；配置恢复故障仍会暂停外发，不能借关闭开关绕过恢复确认。

## 通用工具协议

脱敏负责模型侧数据转译，工具仍执行原有的权限、工作区、文件与网络检查。它不替代这些权限，也不额外给代理增加执行能力。

1. 模型历史保留代号。工具存在性来自实际注册表及受管路由；原值披露另由宿主适配器声明接收方、用途、字段、配置/策略与作用域身份。模型输入里的 `registered/recipient/permission` 等字段不能产生许可。
2. 统一执行副本只还原明确适配字段。日常本地文件及纯文本检索通过显式描述复用共同机制；路径先在宿主私有规划中解析，并在释放完整载荷前核实接收方。嵌套值和key只在适配器明确支持的数据字段内还原，控制字段不能借代号改成权限或执行模式。字典碰撞、未知、过期、撤销、跨scope引用继续拒绝。
3. `tool_invoke_*` 按真实 `name/arguments` 及兼容壳归一化，最终目标服从同一用途与字段合同；代理层数不能放宽授权。原输入树和代理递归共用深度、节点、文本预算。MCP路由只承认宿主完整server/tool记录，声明只读或已登记不能代替披露适配，原型链属性不能成为能力。
4. 凭据可精确还原到已核实的本地数据写入字段；远端认证须未来适配器绑定具体服务及认证槽。未适配脚本、命令、任意HTTP和MCP输入不得沿用通用注册权限恢复代号原值；普通无引用调用与关闭路径继续原语义。用途拒绝须给可行动原因，不能提示用户反复复制同一代号或静默关闭保护。
5. 主/子任务的权限面继续检查真实参数。权限改参、策略切换、取消、资源等待及目标变化后，实际派发重新裁决；文件提交路径保留原检查点、锁和失败回执。工具结果仍重新投影，已执行但结果被扣留时不能重做副作用。执行副本不修改模型原调用或历史。

适配覆盖与未适配拒绝矩阵从真实注册表核对，新登记项不会自动取得原值权限。本地适配器须以真实文件字节、原权限与主/子链路证明正常体验；纯合同测试另保留嵌套、碰撞、跨scope、代理和资源预算反例。旧通用运输测试与85号报告保留其原版本含义，不作为当前所有接收方已支持的证据。M2-7已核验原生主/子回合内受管MCP的文字工具结果、资源、分页及受限通知；无引用输入保持原语义，未知服务仍不取得原值输入许可。ACC/document等尚无可证明接收方身份的原值适配器，仍拒绝私密引用。详见[M2-7证据](evidence/privacy-m2-managed-mcp.json)。

## M2-3 首批本地适配范围

原值授权按以下宿主适配器执行，不按工具分类整组放行。普通无代号调用和关闭保护的调用继续沿用原路径；本地适配不新增确认框或口令。

| 用途 | 首批工具 | 原值字段及条件 |
| --- | --- | --- |
| 确定性文件操作 | `file_read/write/edit/delete/move/copy`、`data_profile` | 明确的路径、内容、编辑片段、分隔符及批量路径；检查真实本地介质、链接目标、工作区权限和实际 I/O。媒体读取及外部语法解析不借用文字许可 |
| 本地枚举与检索 | `file_list/search`、`glob`、`project_snapshot`、`docs_search`、`codebase_symbol_search` | 根目录、模式、过滤或查询等明确字段；只读本地文件，搜索 worker 消费宿主检查后的快照 |
| 本地审计 | `dependency_inventory`、`code_review_scan`、`frontend_audit`、`claude_md_audit` | 明确根目录及已有过滤字段；不由同组的执行工具继承许可 |
| 当前会话文字 | `todo_write`、`mission_update`、`scratchpad_write`、`thread_title_update`、`request_user_input` | 仅各工具声明的文字叶值，绑定当前真实会话；状态提交前复验，不授予文件或外发能力 |

UNC、网络映射盘、无法判定的介质，以及跳向此类目标的链接，暂不支持代号原值恢复。Windows 使用内置 PowerShell 的惰性本地盘类型探针，不要求用户安装组件；探针只查询盘符类型，不读取卷内容。首次启动有额外成本，空闲后退出；无引用调用不启动该探针。实际延迟和验证范围见 [M2-3 证据](evidence/privacy-m2-disclosure-contract.json)。

Git、任意脚本/命令、外部解析器、HTTP、MCP、浏览器及媒体/复合操作尚不能凭注册取得原值。公开搜索/抓取/下载与通用HTTP维持普通无引用调用，不新增通用内容脱敏或私密原值自动授权；M2-4仅核验既有轻量边界，M2-5已取消。其余仍在范围内的接收方按后续批次适配。这里约束宿主还原与提交边界，不提供操作系统文件隔离：同账户进程改文件、脚本自行读盘，以及先写工作区再执行的组合，仍在既有权限与隔离边界之内。

## MCP、复制与拒绝恢复的当前边界

受管资源工具仅在原生回合提供，不向 Claude/Kimi CLI 的清单或动态发现开放；不能通过猜名或代理调用绕过。受管 MCP 的文字投影不代表任意服务可取得原值，也不证明对端内部不读盘联网。

独立 MCP 的 M2-8 已完成本批实际验证。其合同是：先启动本机如意，打开所需工作目录的线程（或设置默认工作目录），再打开设置的「集成与 MCP」面板；核对面板显示的固定目录，为指定应用配置授权，一次生成标准 MCP JSON 配置并导入该应用。面板打开后目录固定，切换线程不会修改该面板或已签发连接的授权目录；日常调用无须重复配置。旧的未签发直连仍拒绝。最多授予七个文件工具（`file_read/list/search/write/edit/copy/move`），与现有权限和目录检查取交集；仅提供 `capabilities`／`workspace` 两类安全概要资源，提供 ruyi://consumer/{kind} 模板及这两类已授权资源的订阅／取消订阅和更新通知，沿既有连接每15秒核对更新并限制连接内状态；不提供任意资源 URI 或二进制支持。每个连接有独立临时代号，断连或撤销授权后失效；日常不要求填写端口或重复口令。这是应用授权边界，不提供 OS 隔离；off 仍须认证并遵守授权。

应用复制按钮使用与实际来源绑定的受保护副本；明确的原文选项不扩大来源授权。暂时没有可核实来源的内容，只能在宿主权威策略为 off 时按字面内容取得复制回执，不还原代号，也不授予 scope 原值权限。启动失败的「复制诊断」按钮始终只复制固定安全摘要，即使 off 也不回退原始诊断；屏幕原诊断及用户手动选择／Ctrl+C不在应用按钮控制范围。

P0体验已验，以精确稳定错误码和结构化回执提供双语原因与行动。设置／引擎按钮只打开已有页面，不改变保护、不重发；CLI被拒后须用户明确选择原生引擎，再发起新请求。损坏策略须用户复核并明确保存后再发起新请求。已执行而模型结果被扣留时，保留本地原结果和可用检查点，提示先核对变更／投递，不自动重做；未知旧错误保留通用呈现。实际双语UI、语音竞态、历史卡、receipt及恢复结果：最终17次运行、15个唯一fixture合计1995 PASS/0失败/0跳过；H13浏览器122项两遍43.981/47.903秒，voice98/52.047秒、stream39/34.259秒、warmup58/29.089秒替代旧5次前端；后端bot108两遍及其余有效回归保持各自原始冻结身份。；完整门与冻结字节见[本批证据](evidence/privacy-m2-p0-closure.json)。该恢复只保留既有凭据加密开关，不表示M3工作数据全部加密。

## 源内容投影

对完整 JSON 字段识别后再按行或字符截片，会丢失字段语义，甚至只留下敏感值的一半。原来用整类禁用避免这类泄漏的方式改为内部源适配：

- 只使用本次工具原本获准读取的完整 snapshot，先识别再按原坐标生成显示片段；搜索匹配仍基于真实内容，不因代号替换改变查找语义。
- 窗口触及敏感替换跨度时扩展至整个代号，不能切出半个原值或半个代号。文件编辑仍可逆转译为原始拼写，包含转义、重复键与长整数字面量。
- 搜索 worker 返回与实际匹配同一次读取的 snapshot；Git 比较原 blob／工作树哈希和行内容，避免第二次读取的内容冒充原结果。差异的 hunk section context 也属于源内容，不能保留被 Git 截短的敏感前缀。
- 只有宿主登记的结果容器对象、具体 JSON Pointer 叶值和精确文本具有来源 proof。proof 由 WeakMap 保存，绑定 scope 和不可伪造 view；允许多 source 显式联合。普通 MCP JSON、clone、未登记 metadata 和伪造 view 不能获得信任。
- 证明同时检查 JSON 解码后的引用归属。后出现字段或别的源学习到新敏感值时，旧 view 必须重新证明覆盖；未覆盖的旧片段拒绝，不把已知完整值的 exact 检查当成半截值保护。

当前限额：每次 scope 回合最多 128 个源 snapshot、累计 8MiB、单源 1MiB；源匹配共享 32MiB 比较工作与命中上限。越限、内容变化或证明失效给固定错误，不发送未检查尾部，也不自动扩大文件读取权限。

## 验收与边界

- 关闭时校验对象身份、参数 getter／注册回调不触发，脱敏边界的数据识别、参数解析、规则 worker、映射与主密钥包装为零；开启时记录匹配、密文写次数及代表输入耗时，避免用模型网络时间掩盖本地开销。
- 每档位测试明确本地适配器的字段、凭据写入、代理及真实参数权限；未适配脚本/MCP、未知字段与伪造宿主能力在handler前拒绝。权限改参、迟到旧策略、接收方变化及取消不复用旧许可；模型请求不得出现哨兵原文。
- 源投影需包括部分字符／跨行／非 ASCII、分组搜索、画像完整样例、Git hunk context、proof clone／篡改／晚学习与编码引用反例。
- 命令与任意 MCP 可对数据做编码、截断或任意语义转换；本地识别不能保证还原这些未知变换。自定义规则与已知值匹配仍生效，不能声称自动理解所有第三方程序的保密语义。
- 数字／布尔／对象敏感值、二进制和不透明签名内容沿用明确的能力限制，不能把类型错误或无法检查的媒体记成已保护。多媒体外发策略等待用户对独立开关的选择；当前没有默认放行原媒体。
- 稳定产物的真实 DeepSeek 扩展矩阵已完整通过 20 个场景；Windows 全量、成品 ZIP 与升级结果以 [82 号实施记录](../archive/optimization-plan/82-privacy-31-implementation.md) 的最终完成项为准，早期成功只证明对应 SHA 的候选。

## 本地档位基准

`dev-harness/privacy-31/profile-overhead.js` 使用合成凭据包装与真实 AES、约 3136 字符输入，预热一次后每档重复 100 次；不访问网络或用户配置。一次迭代包含请求、工具返回与参数处理。2026-10-19 Windows / Node 24.14.0 实测：

| 档位 | 中位 ms | P95 ms | 整档密文写入 | 正则 worker 扫描 |
| --- | ---: | ---: | ---: | ---: |
| Off | 0.0019 | 0.0094 | 0 | 0 |
| Basic | 1.9529 | 3.4145 | 1 | 0 |
| Enhanced | 2.4569 | 5.4990 | 1 | 0 |
| Strict | 3.4972 | 6.9586 | 1 | 0 |

报告 `%TEMP%/ruyi-privacy-profile-overhead-20261019.json` 记录源 SHA。该实验用于比较本地档位开销，排除模型网络延迟、真实 DPAPI 冷启动、规则 worker 和大型来源扫描，不作为这些场景的耗时承诺。普通关闭路径另有 getter／对象身份反例验证，不能仅凭微基准推断没有加密调用。

2026-10-20 ux10 加入常见一层编码识别后，同口径合成微基准：Off 中位 0.0016 ms／P95 0.0055 ms；Basic 3.3026／5.7640 ms；Enhanced 5.7861／8.0895 ms；Strict 5.6070／6.7210 ms。Off 整档密文写入与 worker 调用均为 0；其余每档稳定映射只写 1 次，无自定义 regex 时 worker 调用仍为 0。结果受本机并行构建／测试负载影响，保存在 ux10/validation/profile-overhead.json，不是大型文件或真实 DPAPI 的时延保证。默认关闭仍直接绕过识别、映射、工具参数加解密；开启后的编码识别不递归，并按候选和解码文本预算限制工作量。

Windows 启动另测冷路径：首次默认配置中的同步 Claude／Kimi 发现曾占约 1.73 秒，与 DPAPI 无关。真实 serve 启动改用已有异步探测，绑定后配置消费与恢复等待完整发现，显式路径与验证失败回退保持。89132 稳定产物实测启动健康响应 354ms、探测期间 2ms，原 2500／800ms 预算不变；普通非 serve 的首次配置读取契约保持。

配置丢失时不能将“新安装默认关闭”当成用户曾确认关闭。恢复选择按引用、真实布尔选择、独立保存的成功读写原语与未知非空 vault 保守回退判断；未知旧库继续加密并暂停外发，可信明文 prev 可继续关闭。真正新安装不创建 vault。恢复包导入凭据也不会代替策略确认，用户确认后才恢复模型调用。
