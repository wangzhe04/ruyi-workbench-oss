## 0. 目标与类比边界

目标是：**在明确的正确性边界内，让每个验收成功的任务更便宜、更快、更可控。**

- 复用分层摘要、确定性节点、工具调度、预算与恢复基座；没有比较实验，不称“同类最优”，不预先承诺数量级收益。
- Agent SoC 仅作为分层分析比喻：会话内优化与多 Agent 编排优化分开计量，不以“满足 SoC 判据”证明能力或正确性。
- 模型路由会改变能力和错误分布，并非只改变速度的硬件 DVFS；摘要是有损表示，不等于无损换页；内容去重／propagate 不等于缓存一致性协议；共享内容也不自动成为可命中的共享前缀。
- 默认关／shadow 只表示未启用时不改变主动行为，不表示启用后的提示词、观察或模型变化“天然不改语义”；shadow 本身也有 CPU、内存和日志开销。

区分三层收益证据：

1. **机制收益**：满足限定条件时，少执行、少等待或少传输；可用确定性测试和本地基准证明。
2. **任务收益**：同一任务的质量、总费用和端到端时间改善；改变模型输入／模型选择的项目必须真实模型对照。
3. **总体使用收益**：对日常使用分布的平均改善；需要代表性使用数据，但不阻塞前两层的限定范围验证。

首要成本指标为“**评估范围内全部尝试的总费用 ÷ 验收成功任务数**”，失败、重试、升级、摘要、投机和后台调用均计入分子；成功数为零时标记不可计算，不报告零成本。另列成功率、端到端延迟、人工介入负担和本地资源成本。

## 3. 本线明确排除的四个独立建设方向

- **SMT**：不在 HTTP 客户端模拟 provider 内部寄存器或执行单元复用。
- **多分支 Thought 投机**：本线不为并行探索增加无界模型调用和副作用风险；不以“CPU 错预测只浪费周期”作为论据。
- **流式工具早执行**：本线不增加在参数／响应未完成时提前执行的协议路径；这是范围取舍，不声称所有 provider 永远不支持安全的工具流式执行。
- **ECC／双模型互校新机制**：复用已有 implement-review-fix-test 等评审工作流和最终验收，不另造一套；不宣称模型互评具有纠错码的数学保证。

## 4. 证据分类与执行顺序

### 4.1 不以长期真实用户数据作为统一前置

| 类别 | 不等待长期用户数据的验证方式 | 可形成的结论 | 不能替代的证据 |
|---|---|---|---|
| **A：确定性测试＋本地基准** | 已知调用次数的合成账本、版本化文件夹具、实际本地工具、并发／故障注入、混合负载 | 在明确输入与资源条件下的正确性和机制收益 | 假延迟模拟只能证明调度逻辑，不能宣称实际磁盘／端到端加速；不推断日常命中率 |
| **B：固定任务集＋真实模型／后端** | 人工任务、公开基准、合成仓库、带答案文档与故障案例，真实 provider／CLI 配对重复实验 | 对限定模型、任务族和硬件的任务收益 | 假模型只能验协议与分支，不能证明质量、provider 缓存计费或后端能力等价 |
| **C：收益边界模拟＋限定工作流验证** | 扫描命中率／分支概率／资源开销，给出盈亏边界，再选指定工作流真实验证 | 何种条件下可能划算；限定范围通过后可申请受控试用 | 人造高命中率不是实际分布；机制可行不等于通用预取／学习值得维护 |

长期真实数据主要用于扩展适用范围与估计总体收益；不是 A／B 的统一入场门。C 也可缩小为指定任务族验证，不必无限等待。现有 HB360 历史对账仍如实标记 blocked/deferred，不能用合成测试冒称该历史门已通过。

原始问题记录（保留供审计追溯）：

- 运行时前 12 次调用全采，之后每 4 次采 1 次，每回合最多 400 条 economics 事件；报表用 started 条数直接计算 callsPerTask。
- 按现有采样规则构造 40 次调用，报表显示 19 次且配对为 1:1。该合成复现只证明口径缺陷，不是实际用户任务测量。

**交付**：

1. 不抽样的轻量总量计数与可抽样明细分开；定义逻辑调用、实际 HTTP attempt／重试、摘要／子节点调用的归属，记录采样率、截断、缺失和对账覆盖率。缺失无法恢复时标 unknown，不用推算值冒充精确总量。
2. 区分 turn／task／run／node；固定基准提供明确 taskId，模型费用不漏掉摘要、升级、失败与后台工作；provider usage 与估算分列。
3. 需要重复率时，增加受控作用域／有效期的 HMAC 指纹，或离线扫描本地授权记录、仅输出脱敏聚合；不记录原始参数、路径或内容，不假定普通哈希就是匿名化。
4. 建立可重放夹具与版本化基线：当前实现为基准，串行版本只作诊断参照；不必等待新的真实用户日志，也不必先建 #14 后台服务。
5. 基础统计校准后再挖掘重复调用、跨模型调用工具链、cache usage 和观察重复率；数据不足时标明覆盖范围，人工选定候选亦可进入限定场景实验。

**验收**：短／长调用序列、越过 400 事件上限、中断／异常／重试、子节点／摘要计费均有已知答案；总量与独立夹具账目相符；配对正确、总量准确、覆盖充分分别断言。

#### 候选条目 · #13a-t 长命令预算策略（起草 2026-08-27，未实施）

**定位**：#13a 的工具级延伸，不新增方向编号、不扩大 15 项承诺。目标一句话：让任何单条本地命令都**既不能主导回合墙钟，也不能用超大 stdout 污染之后每一次请求的输入**。

**机制草图（全部复用既有控制面，不造第二套控制器，符合 §6.3）**：

1. **时间预算**：`powershell_run`／`script_run` 已在 `INTERRUPTIBLE_NATIVE_TOOLS` 内（steer 可中断、进程树回收）且有资源租约——在此之上加两级配置化 deadline：软警告 N 秒（向回合流发 bounded `tool_progress` 告警）、硬终态 M 秒（沿现有取消路径杀树、写合法配对 `tool_result` 含 elapsed 与已捕获字节、回合继续）。状态机与 Mission 预算/watchdog 共用，不新增止损器。
2. **字节预算**：长 stdout 流式落盘 + 模型视图只保 head/tail 有界窗口与精确字节计数，全文以磁盘产物引用回取；**引用安全依赖 20-C1 的 rawRef／回载前置——其三个 High 阻断未解除前，本项只实施时间轴 + 截断计数 shadow**，不做结果引用改写。
3. **计量与开关**：每次 trip 落脱敏事件（含 why/deadline/bytes）；上线前先以 bounded shadow 统计「本应触发多少次」校准阈值。时间轴、字节轴独立开关、默认关；按 §6.4 先单轴后组合。

**证据类别 A（合成夹具已知答案，不用 sleep-only 数字宣称真实加速）**：dead-long-runner 与 MB 级 stdout 生成器两类夹具——① 硬 deadline 触发：命令被杀、进程树回收、配对铁律完整、审计记录原因/耗时/字节数、回合可继续推进；② 大输出截断：head/tail 边界确定、计数准确、原文可寻址（当且仅当引用侧就绪）；③ 零触发路径逐字节不变；④ 权限／checkpoint／恢复零回归。

**范围红线**：不静默吞掉预算触发的失败（原因必须可见可审计）；不动 MCP 第三方工具的现有超时契约（如 15 分钟上限），除非用户显式配置；全部默认关，不得以实验收益冒充默认收益。

**排序**：与 #13a 基础层同波实现（复用其预警／预留管线）；因基线实证疼痛明确，支持把 #13a(+t) 排到 #2a 之前。

## 6. 安全契约与验收纪律

### 6.1 缓存、观察与只读边界

- **只读 ≠ 可缓存 ≠ 无外部影响**。#2a 从版本明确的本地白名单起步；网络搜索、浏览器／桌面状态、权限未知或资源版本不可验证的工具不默认准入。
- 缓存身份至少覆盖工具及实现／schema 版本、规范化参数、解析后的工作目录／资源身份、资源版本、权限作用域与影响结果的环境。每次命中仍验证当前授权；跨项目／用户共享不在首批范围。
- 失效必须考虑用户／编辑器／外部进程写入、删除／重建、重命名、目录成员变化与权限变化；仅监听如意写工具不足。TTL 不是强一致性保证，无法可靠确认版本即 miss。
- #2a 命中后仍保留本次 toolCallId、配对结果与审计来源，不冒称重新执行；不缓存错误／中断／副作用未知结果。缓存命中并不自动省模型 token。
- #2b 保留每次观察的来源、时间、版本、状态与证据身份；内容相同不合并来源关系。引用必须能跨 compact／重启解析，处理 GC／过期、坏引用与授权失败，并诚实标记不可回载；不能用不可访问的 rawRef 替代唯一关键证据。
- #6／#8 不越过写／控制边界或未满足依赖。混合批后半只读岛不得在前面的写动作完成前预执行。本线不扩张写／exec 并发或投机；不改变已有授权的编排执行语义。
- 投机预执行前完成授权，禁止借“最终未采用”绕过访问控制；费用、外部请求、日志、内存和限流均计入损耗，设取消与资源上限。

### 6.2 前缀、批量与融合

- #1 首次冻结 schema 顺序，后续稳定追加，不每轮全量排序。保持权限最新；若撤权必须改变请求，应接受并记录必要的缓存失效，不能为命中率保留错误授权。
- 分 provider／模型／配置核验缓存作用域、有效期、前缀匹配与 usage 口径；相同内容出现在不同前缀后不承诺命中。未报告 cache usage 不能填成“缓存未命中”或推算已省费用。
- 固定多轮请求比较冷／热状态，总费用纳入缓存写入、缓存读取、未缓存输入与输出；命中率提高不等于总费用下降。改变资料顺序／模型输入时必须追加 B 类质量验收。
- #3／#4 必须有稳定候选 ID、完整覆盖、重复／漏项拒绝、输入输出上限；测逐项与批量、随机顺序、容量边界、异常候选和失败重试。尽可能只重试失败项，但须验证上下文依赖。
- #9 区分“同 batch 的相邻工具”与“可省的跨模型往返”；保留中间判断／权限门与原始动作审计，计算新 schema 和结果长度开销。

### 6.3 预算、降级与后台隔离

- 分开上下文窗口、累计 token、费用、时间、并发额度；估算与实际 usage 分列。并发调用需预留在途预算、收尾与必要升级额度，usage 延迟／缺失时保守处理；不能承诺无预留情况下绝不超支。
- #13a 先做保护，不固定采用“激进摘要→小模型→检索节流”的顺序。暂停／取消说明原因并保留恢复状态，复用现有 Mission／watchdog 控制面。
- #13b 的摘要、路由和节流各自独立开关；摘要成本、前缀失效、重查、重试和升级全部计费。合法的轮询／必要检索不能仅因次数多被误杀。
- #11／#15 的廉价信号须在正确与错误样本上校准；自报置信度、schema 合法或少重试均不能证明答案正确。限定适用任务族，保留显式模型选择，设置防反复切换的滞回／冷却与升级次数上限。
- 达到升级条件而剩余额度不足时，暂停或请求追加预算；不静默突破用户上限，不带着未解决的不确定性宣告成功。
- #14 独立决定优先级、能力和额度；不绑定“交互=强模型／后台=弱模型”。测前台尾延迟、后台饥饿、取消、共享磁盘／内存／provider 配额竞争；后台单独记账但纳入总成本。

### 6.4 实验、启用与停止

1. **当前实现为对照**：锁定代码、模型、provider、任务集、硬件与配置版本。每项实施前记录收益假设、适用范围、阈值、开关、停止条件和回退方式；不能看到结果后再选有利门槛。
2. **成本完整**：模型调用、HTTP attempt、tool batch／call／phase、token／cache、工具／后台费用、本地资源分账；费用不可得时如实标不可得，不拿字符数替代账单。
3. **安全与质量分开验收**：配对／权限／checkpoint／审计／恢复等不变量在测试矩阵中零回归。overall 质量退化目标 ≤1pp，必须说明评分尺度，采用固定任务集、按任务族／模型分层的配对重复实验，并报告样本量与置信区间；不能以总体均值掩盖关键任务失败。
4. **非劣证据**：模型实验预先固定统计方法（默认报告 95% 置信区间），检查质量差下界是否满足非劣界；证据不足标“不确定／未观察到退化”，不宣告已证明非劣。可补构造 holdout 或缩小范围，无需自动等待长期用户数据。
5. **坏情况必测**：除目标命中场景，还覆盖零命中、小任务、资源变化、错误／中断、资源竞争、权限拒绝和容量边界；只用 sleep 假工具得到的加速不能当本地真实性能。
6. **单轴后组合**：独立开关、默认关或有界 shadow，先单轴、再累进组合；重点复测压缩×缓存、并发×配额、降档×升级。涉及历史布局时保持 session-sticky，不在同一长会话随意切策略。
7. **分清证据与部署**：A／B 通过后可申请限定任务／provider 的显式 opt-in 或受控 canary；默认启用另经发布门。未通过、未知范围回退原路径；长期流量用于扩围，不是所有候选的统一入场门。
8. **停止条件**：相对当前实现无净收益、证据／质量门不过、真实资源争用抵消收益或复杂度不值得维护时，不启用／结束该项。20-T1／C1 的现有阻断不因本线立项自动解除。

## 7. 计算机发展史借鉴与设计评审

以下是设计推论，不是能力等价证明，也不新增必须实现的方向。

| 历史经验（一手资料） | 本线落点 |
|---|---|
| [Amdahl，1967](https://www.cs.cmu.edu/~18742/papers/Amdahl1967.pdf)：整体提升受未优化部分限制 | 先算端到端收益上限；读盘若仅占 1%，即使完全消除也最多节省约 1% 时间，不能只报局部加速 |
| [Denning，1968 工作集](https://denninginstitute.com/pjd/PUBS/Workingsets.html)：保护活跃数据以避免颠簸 | 关注“压掉→重查→再压掉”，保护活跃约束和错误证据；测重取／重复压缩，摘要不是无损换页 |
| [System R，1979](https://research.ibm.com/publications/access-path-selection-in-a-relational-database-management-system)：逻辑需求与执行路径选择分离 | 固定依赖、权限和验收契约，再在合法路径中选择缓存／并行／批量；先简单规则，不直接上学习型调度 |
| [端到端原则，1984](https://web.mit.edu/Saltzer/www/publications/endtoend/endtoend.pdf)：底层保证不能替代应用最终验证 | 工具成功、schema 合法、证据可引用均不能替代最终产物测试与需求覆盖 |
| [The Tail at Scale，2013](https://research.google/pubs/the-tail-at-scale/)：尾延迟与资源竞争 | 同时报关键路径、排队、p95／p99、取消响应和后台干扰，不以平均速度掩盖卡顿 |
| [Spectre，2018](https://arxiv.org/abs/1801.01203)：丢弃投机结果不代表无可观察影响 | 预执行先授权；外部请求、费用、敏感数据访问和日志均受约束，不以“只读”免除安全门 |

每个候选先回答：

1. 能否在输入输出契约不变时确定性化？若改变执行后端，等价性如何证明？
2. 当前瓶颈在哪里，局部收益对端到端的上限多大？
3. 需要 A／B／C 哪种证据，能否通过构造任务而不是等用户流量验证？
4. 哪些证据属于当前工作集，压缩／缓存／融合后怎样取回并验证？
5. 是否真的需要换模型、后台化或共享前缀，各自额外成本是什么？
6. 如何停止、回退、恢复，最终任务验收是否仍然独立存在？

## 8. 新 3.0 与旧壳层线的适用关系及发布门

**2026-08-27 衔接修订**：本线替代旧 [PRETENDER-PLAN v4](../PRETENDER-PLAN.md) 作为新引擎版 3.0 的范围规划，但不重写旧壳层的历史交付与未完成门。

- 旧 v4 的“换容器、不换引擎”、壳层六目标、旧波次／工期是原壳层项目范围，不作为本线新增引擎工作的禁令或排期依据；既有执行资产仍优先复用，不为版本号做大重写。
- P1–P3 工程成果保留；正式外部人因验证仍未执行，不能改记 Product Ready。第101／102波与默认切壳仍搁置；恢复默认切壳时，必须重新评估并通过相关人因与切换前置，不能以引擎基准替代。
- 安全终审、权限／数据契约、恢复、离线升级／回滚与涉及 UI 的双语／主题／a11y 等通用门继续有效。
- 品牌与版本冻结继续有效：正式发布批准前不把 Pretender／3.0 混入用户界面、下载名或兼容承诺；本次修订不 bump 版本、不解冻品牌。
- **双壳退出时钟改绑实际默认切壳**：首次默认启用新壳的公开 Release 为起点；之后第 1 个公开 Release 保留经典，最迟第 2 个公开 Release 且不晚于该起点后 6 个月进入强制退出评审。仅发布引擎版 3.0 不触发时钟；仍有 P0／P1 时不按日历强删安全退路。这是对旧 v4 C2 的显式触发点修订，非静默豁免。

新引擎版 3.0 发布前必须有一页 Release Brief 冻结：

1. 服务的任务族／模型／provider，哪些项目属于必交、可选和暂缓；首批候选不是“全部必交”，15 项也不是发布计数要求。
2. 相对当前版本的目标、验证集／统计方法、实际结果和限制；明确哪些优化在适用范围内默认生效，哪些仅为实验。全部默认关闭不能冒充已经交付的用户收益。
3. 默认启用范围、未知场景回退、开关／配置迁移与回滚操作，以及发布后扩围条件。
4. 通用发布门与未完成项；是否同时恢复旧壳层线必须单独拍板。

当前尚未冻结上述默认启用清单与具体版本收益阈值，不宣告 Release Ready；无需以长期用户数据或全部研究项完成作为范围冻结的统一前置。
