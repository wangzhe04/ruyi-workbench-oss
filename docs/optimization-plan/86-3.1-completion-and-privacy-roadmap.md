## 2. 产品目标与必须分开的保证

三件事使用不同开关和说明：

1. **发送前隐私保护**：降低已识别敏感内容误发给模型/第三方的风险，维持 off/basic/enhanced/strict 与技术信息独立选项。`strict` 仍代表更多识别类别，不偷偷改成操作系统安全等级。
2. **工作数据加密**：保护工作台自有数据的落盘副本、索引和备份。凭据加密、工作数据加密分别选择；开启发送保护所需的代号库仍依赖凭据加密。
3. **托管隔离执行**：对需要强控制的 CLI/扩展，约束文件、子进程、网络和原值使用。它是执行能力，不是识别档位。应用不能把勾选脱敏等同于启用一个不存在的沙箱。

默认开关沿用当前用户选择，不因升级偷偷迁移数据或开启扫描。按三轴分别验收：发送保护 off 时数据通路不扫描正文、不创建隐私映射并保持原参数语义；凭据与工作数据加密均关闭且不存在需恢复的旧引用时，不创建存储密钥；工作数据加密独立开启时，其必要的加密读写照常发生，不能被“off 零开销”错误禁止。配置校验与恢复故障处理不等于正文扫描。

保护对象包括凭据、明确个人资料、用户保密规则及可选技术信息；规则检测仍可能误报/漏报。上下文身份推断、同账户恶意程序/管理员、任意语义编码、侧信道及已经外发的历史不在“绝对防泄漏”承诺内。未来采用本地 NER 只能提高特定语料上的召回，不成为最终授权判据，更不能把原始敏感文本送云端做脱敏。

## 3. 当前实现最值得优化的地方

当前实现的作用域、原始/模型/显示副本、持久化后才外发、晚到结果隔离、真实参数权限检查值得保留。[83](83-privacy-rule-catalog.md) 已记录脚本对原值取首字符可以输出的边界，这证明“匹配更多编码”不能替代执行隔离。

具体代码观察（基线行号）：

- `03a-privacy-gateway.js:1146–1204` 以真实工具注册表作为通用参数还原依据，包含凭据嵌入。这证明工具存在且经过原权限，但没有在本层表达最终接收方、用途和是否二次外发。下一步补披露决策，不能把 `registered` 直接解释成“任何原值都能发给任何目的地”。这属于已声明能力范围的扩展，不把现有通用传输契约误报为权限绕过漏洞。
- `03a-privacy-gateway.js:1206–1209` 用 `native/cli/media/tool_channel` 拒绝未知链路。应演进为有版本、有载荷类型、有测试证据的能力记录；不靠不断新增布尔开关维护几十种组合。
- Gateway 同时承担检测调度、来源证明、历史修复、本地显示和工具还原（1214 行）；拆分以职责为界，保留一个兼容 facade，避免所有调用方一次迁移。模块数增加本身不算简化，需减少重复状态和重复入口。
- 工具结果写入历史的相同隐私序列化在主/子运行路径重复；最终模型发送前也有多处 `prepare → assert → fetch`。收敛这些组合可以减少漏接新出口的风险。详见 [代码规模与精简审计](87-code-size-and-simplification-audit.md)。

优化顺序：先立清楚的边界合同，再抽取重复实现，最后按性能证据优化扫描。不能先删除异常检查再靠全量测试侥幸通过。

## 4. 一条完整的数据通路

```mermaid
flowchart LR
  A[原始输入或授权数据源] --> B[来源快照与本地检测]
  B --> C[带作用域的模型副本]
  C --> D[统一外发策略与协议编码]
  D --> E[模型或指定外部接收方]
  E --> F[代号或受限数据句柄]
  F --> G[用途与接收方校验]
  G --> H[还原执行副本并检查真实权限]
  H --> I[本地工具或受控服务适配器]
  I --> B
  I --> J[本地显示与加密存储]
```

### 4.1 单一事实来源与五个职责

复用现有 core/vault/gateway，按下面职责收敛，不平行建一套“隐私系统”：

| 职责 | 唯一负责的事实 | 不应承担 |
|---|---|---|
| 规则与来源投影 | 规则版本、原始坐标、已识别范围、来源版本与有界扫描 | 授权发送、判断任务成功 |
| 作用域与加密映射 | 代号签发、来源归属、有效期、撤销、持久化 | 让模型枚举所有秘密 |
| 披露策略 | 接收方/用途/类别/载荷是否允许，数据句柄授权 | 取代文件权限或平台账号权限 |
| 通道适配 | provider、搜索、机器人、MCP、CLI、媒体的协议转换与实际出口 | 自行定义第二套规则或宽松回退 |
| 存储与本地显示 | 原始记录、加密持久化、受限显示/导出 | 把本地还原结果自动放回模型历史 |

`BoundaryContext` 的最小字段：`policyRevision、scopeId、sourceRevision、executionId、recipient、purpose、payloadKind、deadline/cancellation`。由宿主构造，模型只能提供业务参数。策略切换使未发送的旧快照失效；不能发一半才发现前后档位不同。

能力记录至少包括：`adapterId、versionRange、transport、contentKinds、directions、isolationLevel、evidenceId`。静态声明用于发现，运行时探测用于确认；没有证据不显示“已保护”。状态用“可用/缺组件/未适配/策略阻止/需重新验证”，不靠一盏绿灯覆盖所有通道。

### 4.2 原值什么时候可以还原

保持普通本地任务易用，区别三种用途：

- **本地确定性处理**：已授权的读写、比较、格式转换通过结构化参数还原；结果重新投影。不得拼入任意语言代码字面量后假设自动转义正确。
- **指定服务认证/业务操作**：凭据由宿主适配器注入到绑定的认证槽；个人资料可按用户任务要求发往明确服务。确认对象是“这个数据类别用于这个服务/操作”，已有清楚授权可复用，不逐条重复弹窗。
- **自由脚本/未知插件/任意 URL**：注册为工具不足以证明披露用途。在托管保护模式，优先让它只见脱敏数据；确需原值时转为无任意外网能力的受限执行任务，或使用明确的目的地适配。无法约束的原值处理不能标为全链路保护。

授权记录绑定接收方身份、操作、类别、任务/会话与失效条件。URL 重定向、域名解析、租户/机器人更换、MCP 重连或权限变化均重验；受信任域名也不等于任意路径可接收原值。代理端不能成为任意转发/open proxy。

对高价值凭据逐步引入随机数据句柄：模型只拿句柄；宿主将原值用于指定参数或认证槽，返回状态/必要业务结果。句柄与现有代号共用映射和撤销机制，不新增另一份秘密库。脚本若仍能直接读原文件，句柄不能宣称形成隔离；必须同时约束读权限与出口。

### 4.3 出口清单和失效语义

第一片先盘点所有 `fetch/http/https/WebSocket`、MCP stdio/HTTP、CLI spawn、外部文件导出及媒体上传的生产调用点。每项标注属于模型数据、认证、业务披露、仅本地、还是管理元数据；不把所有网络调用强塞入一个不理解协议的全局 fetch monkey patch。

模型 provider 的最后一跳统一经过“准备模型副本 → 预算/载荷检查 → 持久化新映射 → 检查策略仍有效 → 编码与发送”。重试/故障切换重新核对接收方；重用稳定映射。请求体、工具定义描述/示例、文件名、URL、错误、分页、资源名称、摘要、压缩、系统辅助补全与遥测都在清单内。

搜索 query 和网页 fetch 是外部披露：脱敏 query 影响检索时显示明确限制；不能偷偷把原值搜索出去。用户明确要求查询自己的订单等可授予针对该服务的业务披露。机器人回发、导出/分享永远不继承“本机显示允许还原”的许可。

副作用已发生而结果不能安全外发：保留真实执行回执，向模型发可恢复的“已执行/结果未披露”结构，禁止自动重做。

流式处理分两种合同：本机显示现有固定格式代号/诊断标记，可按已知最大边界增量缓冲和还原；**对外披露不能把此实现当作任意规则的流式检测**。自定义正则或结构化字段无法证明有限窗口时，按完整逻辑消息有界缓冲、扫描后才发送；超限拒绝或改用已验证的分段协议，不能先发前缀。只有声明并证明最大观察窗口的规则才能走增量出口，验收加入跨 chunk、跨长间隔、流中断与取消反例。首字延迟是这一策略的真实成本，需要单独展示和测量。

## 5. CLI：已暂缓的高风险技术路线与恢复合同

本节保留原设计和失败证据，作为未来恢复研究的验收合同。按 [91](91-independent-namespace-cost-decision.md) 的用户裁决，当前不继续建设独立命名空间或严格托管 CLI；以下完整支持条件不再阻塞 3.1。当前发布仍须验证未支持路径的明确提示、拒绝与无静默降级。

只改 `BASE_URL` 或加 hook 不能称为全链路。CLI 的自带工具、MCP、hooks、插件、子进程、摘要、遥测与持久缓存都可能产生独立通路。官方文档目前明确：Claude 的 Bash 沙箱只覆盖 shell 及其子进程，文件工具/MCP/hooks 在其外，原生 Windows 命令不受该内置沙箱保护。[官方沙箱说明](https://code.claude.com/docs/en/sandboxing)

### 5.1 保留的候选设计：托管 CLI + 私有 API 网关 + 受控工具

1. 每次受保护会话启动独立配置/home/cache；不加载用户全局或项目注入的插件、MCP、hooks、扩展。允许项来自宿主冻结清单；扩展可逐项适配，不能默默继承。恢复绑定 CLI 版本与策略版本。
2. CLI 的模型 API 指向宿主私有网关，使用短期会话令牌。上游真实 API key 由宿主保管；采用官方支持的 API 接入方式，订阅/OAuth 和不透明协议单列兼容性，不截取或改造用户登录令牌。Claude 网关协议与版本约束需按 [官方兼容入口](https://code.claude.com/docs/en/llm-gateway) 实测。
3. 网络与文件约束必须覆盖**整个托管进程树**，不能只有 Bash：先原型验证 Windows AppContainer/受限 helper 的实际可行性、命名管道/本地网关访问、子进程继承和逃逸失败。Job Object 用于归属与回收，不把它当隔离边界。必要时评估受管 WSL2，但不得静默安装或改变用户环境。
4. 独立隔离 helper 是可选离线组件，保留现有 Node 后端零 npm 运行时依赖约束。宿主 broker 暴露窄 RPC，不给隔离进程通用宿主命令入口。网络直连、DNS/UDP/IPv6、代理变量覆盖、重定向、私网及 loopback 访问均需实际负例。
5. 模型与 CLI 内部历史保留代号。优先关闭/替换无法安全回填的内置执行工具，使用工作台受控 MCP 工具进行执行副本还原。不能在整个模型流中全局字符串还原，尤其不能改写签名思考/不透明控制块。
6. 原始项目按允许范围投影或由文件 broker 读取；CLI 只能拿到模型副本，文件、搜索、编译诊断、命令输出与受控 MCP 返回均在进入 CLI 前保护。原值处理留在宿主执行侧；若某模式必须让 CLI 自身看到原文，它不能沿用“内部历史只有代号”的保证，须另建经过验收的存储/出口合同。受保护操作写回真实工作区仍经过现有权限。要验证编辑语义、路径、定位、编译与测试，不把只能聊天的 CLI 演示当完整支持。
7. CLI 更新默认触发兼容重验；未验证版本不自动继承支持标签。网关死亡/组件缺失/恢复失败停止外发，不回落官方直连。

AppContainer 文档证明的是操作系统提供资源隔离机制，并不能证明现有 Claude/Kimi 在本项目内可直接运行；Windows helper 的功能与分发是原型的待证内容。[Microsoft 隔离说明](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation)

### 5.2 原型出门条件

Claude 与 Kimi 各冻结一个实测版本及 API 协议。完成“读取含合成秘密的文件 → 修改并验证真实文件 → 子进程/子任务 → 压缩 → 重启续办”的闭环；捕获所有允许出口并用独立目标验证未授权直连失败。检查 CLI transcript/cache、临时文件和恢复历史，确认保护会话不落原值、重启不从旧缓存重新引入原值。测试项目级 MCP/插件注入、环境污染、恢复旧缓存、手动改网关、并发任务串 scope。

Kimi 的用户级/项目级 MCP 配置以及动态增删的行为会影响隔离，必须纳入托管配置清单。[官方 MCP 说明](https://moonshotai.github.io/kimi-code/en/customization/mcp.html)

2026-10-21 续验见 [90](90-claude-and-filesystem-feasibility.md)：LPAC 父子进程可读写投影外 ARAP 授权的合成资源，当前实现不满足严格宿主文件视图；额外随机 restricting SID 的 primary token 虽建立成功，Node 在 JS 前即因访问受限退出。下一条技术路线先验证独立资源命名空间或其他 OS 强制机制，再接完整 CLI 工具链；不在已失败的基础上堆文件 API 包装来宣称隔离通过。Claude 的预加载/管道与实际模型完成仍须分开验收。

2026-10-21 成本裁决见 [91](91-independent-namespace-cost-decision.md)：按用户“复杂则暂缓”的指示，独立命名空间及依赖它的严格托管 CLI 支持暂缓，不再要求为 3.1 引入完整 VM 部署。上述验收合同作为恢复研究的条件保留；3.1 不得宣称该能力已支持，仍须验证不支持路径的明确限制与禁止静默降级。普通宿主 Claude 的有限 HTTP 文本轮已跑通，不改变这一边界，其余范围继续执行。

**恢复研究的停止条件**：若官方可用接入不能维持协议与工具能力，或 Windows 全进程边界原型失败，记录阻断并重新裁决；不能将“仍然禁用”描述为完整支持完成。当前已经按 91 暂缓，不要求继续原型来关闭本轮发布门。

## 6. MCP 与外部服务

### 6.1 受管服务与独立消费者分别设计

受管 MCP：请求先按工具用途授权，必要的原值仅发给明确的本地服务/远端接收方；结果、错误、资源与日志重新投影。本地 stdio 服务不是天然可信本地计算，它也可联网/读盘；无隔离或接收方约束不能宣称其内部外发已受控。

独立消费者连接如意 MCP：建立宿主认证的连接级隐私 scope，不信任客户端给的任意 scopeId；绑定令牌/调用主体/授权工作区。支持 tools、resources/read、资源模板、分页、错误、订阅通知；prompts、sampling、elicitation 等若提供也必须接入能力表。二进制资源使用媒体通路。MCP 资源可以返回文本或二进制，不能只测工具返回。[MCP 资源规范](https://modelcontextprotocol.io/specification/2025-11-25/server/resources)

消费者得到受保护视图；只对其获授权的执行调用还原，不能调用“查询代号原文”。此能力保证如意返回的内容；消费者自行读其他文件/连其他服务属于其自身边界，不因连了如意 MCP 变得全面受保护。

### 6.2 外部发送与认证

认证头注入和正文披露分别处理；将 API key 用作该服务的认证不是泄漏给模型。远端搜索、机器人、上传、通知、HTTP 工具复用同一个接收方合同，维护原幂等键、回执与取消语义。不得用隐私失败触发已完成业务的重新执行。

## 8. 工作数据加密与全文索引一起建设

### 8.0 用户体验约束（用户补充）

工作数据加密须建立在用户主动选择、日常使用基本无感的基础上；默认不改变已有选择。正常本机登录后由既有密钥封装机制自动解锁，不为每次启动、聊天、搜索、附件读取或备份反复索要口令。恢复口令用于用户明确发起的跨机/故障恢复，不能成为日常操作的额外步骤；自动解锁不承诺抵御同账户恶意程序。

聊天、搜索、任务接续与文件操作沿用既有入口和语义，内部自动完成加解密、索引及受管备份。首次迁移在后台分批准备，支持取消/中断后恢复；只在安全空闲边界做短暂活动数据切换，不中止正在执行的任务。若当前写入所有权无法支持继续操作，先等待空闲并说明状态，不让用户承担目录搬运或修复步骤。切换耗时、首次迁移耗时和正常操作延迟分开记录，不能用后台运行掩盖卡顿。

仅在需要用户行动的异常或披露变化时提示，例如磁盘不足、密钥不可用、恢复目标冲突或明文导出；沿用已明确的授权，不为同类日常操作重复确认。错误时保留数据、提供明确恢复动作，不静默退回明文或显示加密成功。尚存旧明文副本的状态如实显示，不能为了无感隐瞒保护范围。

实施前冻结日常聊天首响应、追加写入、搜索、附件首读、启动/恢复的基线，比较冷/热场景下 p50/p95、峰值内存、磁盘占用与 UI 响应；沿用第10节性能判定，并在具体存储方案确定后给出可验收预算。正常路径不得增加交互步骤；首次启用和异常恢复单独做用户旅程验收。准确性能与可用性未知前，不作“零开销”承诺。

### 8.1 加密范围

列出存储清册：消息 NDJSON、provider history、管家/记忆、待决原话、外部收发箱、上传附件、媒体派生件、搜索索引、缓存、恢复日志和应用创建的备份。状态、时间和计数等允许明文的最小元数据逐字段说明；标题、路径、URL可能敏感，不默认当无害元数据。浏览器 IndexedDB/localStorage/WebView 缓存、崩溃日志、临时目录也在清册内。

复用现有 AEAD/密钥封装，凭据与工作数据使用不同用途/派生键，不复用 nonce。追加日志按独立认证记录保存序号、版本、记录 ID 与作用域；通过既有事务日志/提交边界区分中断尾写和已提交记录被篡改，不能仅依赖一个最后序号就宣称抗任意回滚。大附件采用有界分块及经过认证的块清单，范围读取与最终完整性均验证。

应用内查看优先内存解密和已认证的本机接口。外部编辑器需要明文时使用受限临时租约、用户可见说明和崩溃清理；不承诺外部应用缓存/系统交换文件绝无明文，也不自动改写用户工作区原文件。

### 8.2 迁移、恢复与关闭

迁移顺序：清册与空间预检 → 完整可恢复备份 → 影子加密目录 → 每项校验 → 原子切换活动 manifest → 重启复验。有可靠快照和增量追平机制时允许后台准备、继续日常使用；最终增量追平、校验与切换在安全空闲边界完成。缺少这些一致性机制时等待空闲再迁移，不能边复制活动目录边宣称一致。准备期旧目录仍是唯一权威，只允许既有 owner 写入，影子目录不对外服务；切换提交后所有缓存、异步写、备份与索引统一服从新 manifest，迟到旧写拒绝或按新权威重新调度，不得继续写旧目录。切换前取消保留旧权威并自动回收影子；提交后不能直接退回陈旧快照，须走已验证恢复流程。每步可恢复，写入所有者只有一个。迁移 journal/临时目录执行相同加密政策；应用管理的保留备份须已加密并验证可恢复，才可显示“活动数据与管理备份已保护”。

旧明文目录在迁移验证前保留；之后按用户选择退休，或明确显示“仍有迁移前明文副本”及其受管位置，不能只显示一个笼统的“全部加密完成”。已导出的用户副本无法追溯处理，单列边界。不能为消除提示直接删除唯一备份，也不把普通删除称为 SSD 物理擦除。

口令恢复包区分“凭据恢复”与“完整工作数据恢复”，后者覆盖版本、key envelopes、全部加密记录和一致性 manifest。错口令零数据修改，丢主密钥保留原数据并向新目录恢复。凭据与工作数据使用独立 key purpose 和生命周期；关闭凭据加密不能撤销仍被工作数据引用的包装密钥，轮换/恢复须验证全部存活引用。关闭工作数据加密需明确选择明文迁移并同样可恢复；不能把关闭扫描等同于解密存储。

已有 3.0.1 数据升级、连续重启、旧版读取及回退必须使用完整升级前备份；旧版不能直接读新加密格式。记录可恢复范围，不把 overlay 回退当数据降级器。

### 8.3 全量分片索引

以 `sessionId + turnSeq + messageId + contentRevision + chunkOrdinal` 标识片段，保留原文坐标与来源；不再用每会话 8192 字符采样声称搜全。构建可暂停/续跑，覆盖旧会话、长消息和附件可提取文字；删除、编辑、回退、归档、权限变化与索引更新保持一致，未完成索引明确显示覆盖率。

密文数据不能旁路生成明文词条、片段缓存或 embedding。第一版优先本机词法检索；持久化索引整体加密、内存查询，不引入会泄露词频/模式的“可搜索加密”承诺。大数据集做分段解密和预算控制；索引结果取回原始版本后才投影到调用方 scope。跨线程接力显式转交获准材料，由宿主在目的 scope 重新签发，不能直接拼接来源代号。

## 9. 其余新增交付

### 9.1 QQ/飞书

沿用 [66](66-external-bots-and-steward-channels.md)–[68](68-external-bot-identity-discovery.md) 的本机授权与回执系统。补 B/C：原消息关联、投递查看/取消/人工重试、明确保留期、分页与归档、发送窗口和限流、可撤销的一次性远程待决动作。接受/执行/发送三个状态仍分开，未知结果先核对，不重新跑任务。

真实联调需要专用账号/应用、平台权限和可用接入方式，这些是实施时的外部依赖。本轮规划不需要用户贴密钥，不向真实联系人发测试消息。实施时通过现有专用凭据入口配置并明确指定测试会话。

进度通知以平台实际许可为准。若 QQ 当前政策不允许任意主动推送，交付定义是合法回复窗口内的进度、用户主动查询和本地待发状态；不能承诺绕过平台限制。冻结前重新核对官方协议与账号能力。机器人回复按目标接收方投影，群内“同一机主”不代表群里所有人获授权见原文。

### 9.2 已有线程接力

沿用工作流依赖与租约；用户选择 A/B 及要交付的材料，记录来源回合和产物版本；B 空闲且前置验收成立才启动。忙碌、待决、失败、停止、来源修改、权限改变、重启 unknown 均有明确分支；不凭同名猜线程、不轮询最后一条助手文本当完成信号。先做有界顺序链，任意 DAG 编辑器不作为隐含新增承诺。

### 9.3 定时模板

从认可 Playbook 选择变量、时间/时区、目标和验收，保存前预览未来触发时间。复用现有 scheduler occurrence ID、预算、权限和幂等机制；暂停/取消/改模板不重复执行，升级和休眠后显示错过/等待状态。权限待决走现有清单，不因为定时触发自动扩大授权。失败和有意义变化才通知，避免固定无事播报。

## 10. 识别效果与性能优化

不以添加规则数量衡量质量。固定一套合成正例、邻近公开负例、编码边界与真实任务风格语料，每个规则单独记录漏报、误报、完整区间覆盖、可逆还原与业务任务成功率。训练/调参语料和冻结验收语料分开；改变规则需证明收益，不只展示成功样本。

可实施优化：

1. 规则配置在版本变化时编译；公共规则不可变，scope 私有已知值分开，避免每次构建全量配置。规则/密钥变化立即失效，跨 scope 不共享秘密结果。
2. 来源只读快照一次识别后按原坐标投影；缓存键包含内容哈希、来源版本、策略/规则版本、scope及已知值 revision。证明丢失时重新计算或拒绝，不能复用旧片段。
3. 小数据维持直接扫描，已知值数量达到实测阈值再比较 trie/多模式匹配；不先引入复杂索引。候选一层解码沿用有界政策，披露保证与“编码预算耗尽”分开显示。
4. 合并重复 JSON 遍历/词法扫描前列出差异，保留原始字节、转义、长整数、重复键、字段范围与跨切片语义；不能直接改成 `JSON.parse/stringify` 丢失编辑坐标。
5. 将显示流、来源投影与执行还原从 Gateway 拆成内部模块，共用同一 scope/版本事实；关闭快路径在入口一次判定，最终出口仍独立验证策略，避免把必要的最后检查消除。

性能基准按 off、basic、enhanced、strict；3KiB/100KiB/1MiB 文字；0/100/10000 个已知值；无 regex/正常 regex/超时；冷/热 scope；10/100/1000 会话索引；媒体各语言和大小分组。分别报告 CPU、p50/p95、峰值内存、加密写次数与总任务耗时，不能用网络等待掩盖本地成本。

发布阈值在每片基线测量后、实施前冻结：发送保护 off 不引入正文扫描或隐私映射，密钥创建按第2节三轴合同判断；相同机器中位和p95变化超过约10%先查明，不能靠波动百分比机械判退。现有硬性能预算继续有效，新增媒体/索引预算另定并展示耗时/取消，不凭空承诺所有机器几十毫秒。

## 12. 发布验收矩阵

- **原文不应外发**：合成秘密同时放在输入、工具输出、文件名/标题、摘要、历史、分页边缘、错误、资源、媒体元数据和重试。观察实际发送字节，不以模型自报或源码字符串证明。
- **原值应该执行正确**：授权的本地写入/编辑、服务认证、业务传参逐字正确；混合中文、引号、换行、长数字与嵌套结构；无新增权限。敏感值正确执行和未披露两个断言都成立。
- **不应错误隐藏**：订单号、计数、普通代码/公开URL/公开哈希维持可用；脱敏后的真实任务完成率、修订次数与人工处理次数记录。
- **失效与并发**：策略变化、scope更换、回合停止、过期/撤销、重启、映射损坏、跨线程、晚到结果；拒绝/隔离后下一回合可恢复，不重复副作用。
- **CLI与扩展出口**：当前发布验证已声明支持的行为与保护限制，未支持路径不得静默直连或冒充受保护。严格托管 CLI 的模型、压缩、插件、hooks、MCP、子进程、遥测、恢复及独立接收端负例，保留为恢复研究的完整矩阵；完整支持不可由单次 gateway 捕获推导。
- **持久数据**：磁盘搜索、日志、备份、索引、浏览器缓存和临时文件按声明范围检查；迁移每个切换点注入故障，重启后仅一个权威数据集。明文外部编辑租约和系统边界明示。
- **产品体验**：原生/CLI、管家/普通任务/子任务/定时/机器人、双语/双主题、键盘/窄屏；用户能看懂实际处理件、被阻原因、恢复动作与当前保护范围。
- **候选身份**：每份结果绑定提交、应用/组件哈希、规则版本、CLI版本及数据迁移版本。保留首次失败、flaky、skip，定向复验不改写原始全量结果；真实平台和离线夹具证据分别列明。

## 13. 精简原则与治理

代码规模和具体候选见 [87](87-code-size-and-simplification-audit.md)。优先统一事实所有者和重复组合，不以代码行数百分比作裁员式目标。持久化、幂等、未知结果、真实权限、源快照、策略失效和有界资源这些检查保留；控制字段的同一检查只在已验证的内部边界不再重复解析。

维护三个入口：本篇负责方向和排期；83/84负责当前实现合同与覆盖；87负责规模和精简证据。历史逐波日志进入归档，新增已完成证据采用独立记录，不无限追加当前规划。一次性脚本与报告按用途归位；生产/测试固定入口先查消费者再移动，生成件由生成器更新，真实用户数据和ignored验收副本不混入源码仓库。

当前不改版本号、不发布；后续按本文逐片实现。**M1 出口清册和托管 CLI/媒体原型已有记录**，首轮证据见 [88](88-privacy-m1-prototypes.md)，音频生产修复、LPAC 续验及 ASR 取舍见 [89](89-audio-and-cli-isolation-followup.md)，Claude、严格文件反例与进程回收调查见 [90](90-claude-and-filesystem-feasibility.md)。图片限定原型已验证；LPAC 下 Kimi 0.42.0 的受保护模型请求经专用命名管道已跑通，Claude 的 LPAC 模型路径尚未打通（普通宿主有限 HTTP 基线见 91），严格文件视图存在明确反例。按 91 成本裁决暂缓完整 VM 与严格托管 CLI 支持；注册表与完整工具/恢复矩阵未通过作为历史事实保留，不再充当当前 M1 关闭条件。本地 ASR 暂不实施；当前 M1 仍需按第11节补齐发布范围内的证据，不得据暂缓决定提前开放其余发布门或把剩余工作铺成长期分支。
