## 真实模型实验

用户明确授权使用本地已配置密钥和端点。`dev-harness/privacy-31/live-core-probe.js --live` 只读配置，采用当前活动服务商，不启动或修改真实如意服务，不传递真实工作材料，不将密钥写入临时配置或命令参数。

实验使用实际核心和现有协议编码／解码，模型只得到两个夹具工具：读取一个临时合成联系人文件、按邮箱查询固定合成订单。所有模型请求正文在发出前检查合成邮箱、手机号、密钥和真实认证密钥未出现；真实认证仅进入原配置服务商的认证头。返回工具结果先经过核心脱敏，下一次模型调用必须携带签发的邮箱代号，经主机策略检查后还原到原合成邮箱。

2026-10-19 最终结果：`deepseek-flash`、Responses 协议、3 次请求、输入 1627 token、输出 99 token、实测 2819 ms；四条断言全部通过。只保存这些聚合证据，不保存配置、请求头、真实端点或响应原文。初次实验在请求编码阶段因夹具未绑定配对修复钩子失败；补齐夹具的无修复 hook 后重跑通过，首跑失败不冒充一次全绿。

该实验验证“工具读取 → 代号返回 → 模型带代号调用 → 本地还原 → 最终回答”的语义可行性；夹具自己保证消息配对，因此不覆盖生产历史修复、HTTP gateway、持久化或权限审批。请求数／时延／用量不推广为一般性能数据。

### 恢复事务与应用内入口

- `01l-credential-recovery.js`：先验证密码和加密包、校验引用，再发有效期两分钟的预览票据；票据容量预留，最多四个、同时解锁最多两个；失败预览不写目标配置或 vault。
- 提交通过配置写队列比较预览时的配置／vault 戳；配置变化、忙碌、过期或重放均拒绝。按 ID 合并服务商与连接器，同 ID 替换，未列出的保留；不导入工作区、会话、权限设置或隐私映射。
- 导入将已验证凭据重新加密为本机 vault 的不可变新记录。旧主密钥、旧记录与历史引用保留；不采用替换整库后冒险同步配置的方式。导出只含当前配置引用的凭据记录，避免无关历史记录挤占恢复包容量。
- 配置切换前，使用本机主密钥认证加密回滚日志。进程中断后的第一次配置读取先回退日志，再提供配置；无法认证日志则拒绝。失败不删除唯一回退依据。
- 同时读配置会等待正在进行的恢复；恢复自身使用独立异步上下文以免自锁。配置变更事件延迟到日志成功移除后发布，失败恢复不发布暂存配置，防止调度器提前使用尚未提交的凭据。
- 设置 → 权限与安全：脱敏档位、技术信息开关、自定义规则；独立密码的恢复包导出、文件导入解锁、目标预览与确认合并。显示服务商／搜索／CLI 目标、连接器启动命令，说明启动参数也会恢复；密码在请求后清空，票据只保留于面板内存。
- 管理 API 全部要求 workbench token，包括本机客户端；请求体上限 2MiB，响应 no-store，不把密码或解密错误明细输出到日志。自定义规则值本身加密保存，普通配置投影不返回值。

- `03a-privacy-gateway.js` 用 AsyncLocalStorage 绑定主回合、子任务与辅助补全的作用域。宿主存储经注入，未扩大既有依赖环。

- 工具返回先变成模型副本中的代号，界面本地观察仍可使用原结果。执行副本在并行预执行与权限判断之前还原；模型历史保留代号。权限、工作区、敏感文件、SSRF 等原有闸继续判断真实参数。
- 仅已登记本地工具及相应字段允许还原；凭据引用、未知／跨作用域引用、命令和远程接收方不能借引用获得授权。独立 MCP 进程每次无作用域调用重查持久配置，避免旧进程继续按关闭状态返回明文。
