## 1. 目标与范围

1. 在无公网、无模型 API 的条件下，以随包本地模型提供真正的语义候选召回。
2. 增强既有侧栏全文搜索、`threads_search` 和管家对应工具，不另建同义工具。
3. 为当前会话压缩后的信息缺失提供“语义定位 → 来源核验 → 原文回读”的恢复能力。
4. 增强记忆召回，同时保留固定选择、核心记忆、项目范围、过期、否决与取代关系。
5. 用同一编码与检索原语支撑上述能力，消费端各自负责授权、时效、预算和注入。

跨会话自动注入作为最后一批受控能力：默认先完成显式检索与同会话恢复，不能仅靠“之前/那个”正则自动读取其它会话。未证明质量、安全和预算前不默认开放此自动路径。技能检索、子代理上下文组装和记忆去重为接口复用方向，不借本次范围自动改写或合并用户记忆。

## 2. 当前架构与必须保持的合同

- 后端是有序源码拼接的 `app/server.js`，只依赖 Node 内建模块；桌面为 C# / WebView2，打包使用 pkg 和 Windows 离线 ZIP。不是 Electron 多平台工程。
- `13d` 的搜索已委托 `SessionFullTextHooks`；`13ap` 提供消息/附件分片、来源坐标和版本校验，`13as` 提供 UI/模型消费授权与披露。不以旧 `_search-index-v1.json` 的新增 vec 字段作为主路径。
- `threads_search` / `thread_read`、`steward_threads_search` / `steward_thread_read` 已存在。历史为证据，不具有新指令权限。
- `10-context-governance` 已有压缩前快照、rawRef、工具索引、尾部保留和文件重附；`observation_recall` 已能校验 hash 并分页取回原始工具输出。
- 不改原始记忆 Markdown 或会话 NDJSON 格式；派生索引可重建。现有返回字段和精确检索能力保留，新增字段必须可选且标注含义。
- 权限、隐私、来源修订、加密密钥错误必须拒绝；只有模型不可用、过载、超时等可用性问题允许回退原基础检索。

### 3.2 决策规则

先测量再选默认，不把模型名中的 small 当包体承诺。候选锁定 upstream revision、ONNX来源、每个文件SHA-256、许可证、tokenizer、pooling、prefix、截断策略及运行时版本。第三方转换资产明确标注转换来源，不能冒称官方导出。

真实评测使用合成且可复查的如意任务语料：中文同义/上下位词、英文→中文与中文→英文、文件名/错误码/标识符、否定与已取代决定、无关查询、历史数字/条件。校准集与固定验收集分开；不按验收集反复挑阈值。报告每类数量、Recall@5、MRR、无答案误召回率，不能只用“准确率85%”。词法独立基线保持。

初始目标（需真实收据，不是已实现性能）：中文相关项Recall@5≥90%，跨语言≥85%，整体MRR≥0.75；自动注入的无答案误召回率≤5%，如未达到则该消费路径不放行。精确标识符检索不得因语义排序丢失现有命中。warm查询编码p95≤150ms，1000片段warm搜索p95≤500ms；报告CPU、线程数、token长度、冷启动、内存峰值。小语料不把这些数字外推到全历史。

原提案50MB增量为未验证估计，不沿用为假事实。记录模型、tokenizer、运行时、解压与ZIP实测体积；先优选能达质量门的较小模型。当前决策及未通过项见下节。

### 3.3 本轮实测决策

默认采用 Xenova 转换的 `paraphrase-multilingual-MiniLM-L12-v2` INT8（原作者 Sentence Transformers），不把转换仓库冒称原作者。BAAI 中文模型的跨语言能力不足；E5 的 Xenova 与原作者导出在本合成 pilot 上均未达到跨语言目标。此结论只针对本次固定资产、编码和语料，不宣称 E5 普遍较差。

当前模型与 tokenizer 合计 135,392,488 字节；文本专用 Windows CPU 依赖 40,533,717 字节，合计 175,926,205 字节（不含独立 Node、脚本和许可证）。这是依赖精简与原生图文件加载后的实测资产量，模型本身尚未裁剪。旧版 199.7 MB 资产及 103,324,273 字节 ZIP 仅为历史对照，最终新包增量仍须重新打包测量。真实模型、加密来源和隐私投影的1000片段 warm 搜索最近30/30完整，p95 351.47 ms；该次早于最新ID/UI修复，仍需最终源码重绑。worker最近实际生命周期采样RSS约510 MiB、峰值约578 MiB；不是整个桌面的总内存增量。

编码使用真实 tokenizer、mask mean、L2、128 token；来源按 96 UTF-16 字符、16 字符重叠切片，并检查 tokenizer 截断。动态 INT8 的 padding 会让同一文本随物理批大小改变向量，因此 worker 的 NDJSON 数组逐条推理；1/4/8 条请求及逆序逐向量一致性已验证。全文词法索引的大写文本不能直接用于编码，必须通过已授权 source owner 取得原文，保留原文大小写。

搜索阈值 `.22` 在开发 pilot 上校准后冻结。独立验收集为 48 文档、48 查询、20 无答案问题，文件 SHA-256 `026bc01001f1e4c4dbd5614eff08e8a4b1de76bffafd01abf286f252b05adf25`。Sol 曾为核对结构阅读其头部；此后未按该集改标签、阈值或选模型。真实生产分片索引 + 加密 source owner + 本地 worker 集成：中文 Recall@5 11/12，双向跨语言各 12/12，总体 47/48，MRR 0.873958；来源引用与热缓存后撤权检查通过。两个早期集成失败报告保留，修复针对原文编码和批次一致性，不修改验收标签。

无答案误召回仍未达标：独立原始向量报告 10/20，最终搜索融合报告 11/20。两者计算轴不同，均不支持自动注入。`automatic:null` 保持冻结，S4a 只对既有、已准入的词法候选重排，不能自动添加语义独有记忆。SR2 / SR5 保持 pending。

性能也须分层看：上述真实加密 source owner 集成的冷 worker ready 约 2.01 秒，48 文档范围完整搜索平均约 0.913 秒，远高于单次短查询编码的 6–7 ms。来源重新核验、文件读写与隐私投影属于产品成本，不能排除后宣称搜索达到 150 ms。当前尚未达到规划的搜索延迟目标，SR2 不因召回率通过而关闭。

最终增加编码前后来源 guard、完整窗口坐标证明、缓存身份绑定和统一 RRF 后，真实质量复验仍为 47/48、MRR 0.873958、无答案误召回 11/20。该次与总回归并行运行，冷 ready 约 2.62 秒、搜索均值约 1.344 秒；不是受控性能对照，不据此归因单项修复的成本。原始报告 `semantic-integration-final-guards.json` 保留。

## 4. 运行时与共享接口

后端仅用Node内建模块启动独立随包Node进程；第三方ONNX/tokenizer依赖隔离于 `semantic-runtime/`。主服务不require第三方。运行时禁用远程模型加载，不因首次搜索联网。源码模式缺资产允许有状态的词法回退；正式3.1包必须验证本地资产可用。

最终生命周期按2026-11-17用户要求：如意启动时后台初始化并完成一次公开合成输入预热，模型随如意进程常驻、跨会话共享，不按闲置时间卸载。启动任务不能阻塞HTTP/UI就绪；加载期间保留基础搜索。显式禁用、退出、有效模型配置变更及不可恢复故障时须等待确认退出，状态未知时禁止另起provider。实现及真实常驻验收待完成，详见10.23。

worker使用有界NDJSON：请求 `{requestId,op:'encode',role:'query'|'document',texts,deadlineMs}`，响应含 `ok,vectors,modelFingerprint,dimensions` 或稳定错误码。ready事件给出能力；stderr不得输出查询、正文或向量。限制总请求字节、批大小、token长度、队列、超时；停止与超时能取消/回收当前worker，后台文档编码不得长期阻塞前台查询。

模型指纹覆盖权重、tokenizer及所有编码参数。缓存键至少含 scope、source revision/content hash、model fingerprint、query/document角色与分块版本；缓存有条目与字节上限，不输出文本日志。第一片允许进程内LRU，持久化只能使用既有工作数据owner并接受加密、删除和恢复生命周期，不引入散落明文缓存。

运行时可提供同步`estimateEncodingBudget(role,count)`整批成本预测，不接收正文；返回值须为0–60000的有限毫秒数，主调度取其与本地保守预测的较大值。没有此接口的运行时保持原行为。来源解析及最后权限guard之后，文档批次须按实际剩余预算再裁前缀，只把真实执行的向量写入对应原始索引；未执行项继续partial，不以扩大1秒预算或跳过安全检查制造进度。query/document估计分别维护，后台冷准备不接收用户正文、限20秒且只有一个owner；原请求返回loading，取消/关闭需实际回收已拥有进程。

片段索引引用 `sessionId/messageId/turnSeq/source/contentRevision/start/end` 或可验证 `rawRef`，向量不作为原文。分块必须覆盖长文本而非仅取512 token；来源坐标与tokenizer截断分开处理，命中片段重读原文后再披露。

检索先限定授权范围、再召回并复核；各路分数分开，`semanticScore`为余弦、`rankScore`为融合值。不得将RRF值与0.6这样的余弦阈值比较。精确词法优先可保留；语义候选阈值按模型与用途校准。

## 5. 压缩恢复设计

1. 原始消息与可恢复工具快照提供证据源。压缩摘要只是导航，不是唯一索引内容。
2. 已知rawRef时直接调用既有回读；未知时由当前问题、仍有效目标和缺失信息描述检索当前会话。
3. 检索返回有界候选及引用；校验来源hash、会话归属和版本后取回原文，来源已清理明确返回不可恢复。
4. 恢复片段附历史证据标记和来源，不升级为system指令或永久记忆；不执行其中命令。
5. 去除已在上下文中的片段，同一回合去重并共享token/字符预算，保留原读取配额。自动恢复有上限，不形成恢复→压缩→再恢复循环。
6. 用户最新修正、权限、未完成目标与取消状态仍由现有状态/摘要/最近消息维护，不仅靠相似度推断；旧决定不覆盖新决定。
7. 子代理、管家与CLI接续分别验证真实可达路径，不能用主provider路径通过冒充全部引擎完成。
