## 执行身份设计

会话 ID 和持久卡片的 `turnSeq` 不能证明页面看到的是哪次执行。复用服务进程的 `OVERLAY_ID` 与回合驱动器的 `driverRunId`，组成只读 `execution: {serverInstanceId, driverRunId, phase}`；`phase` 说明排队、启动或运行阶段，不参与身份相等判断。同一逻辑执行从排队进入运行时身份保持不变，重启及新执行使用不同身份。只在运行期叠加，不写入持久卡片。

停止请求携带页面或动作生成时捕获的 `expectedExecution`。服务端在一个不含 await 的同步段内核验，再设置所属驱动器的取消标记、停止匹配身份的引擎注册项、取消匹配队列项及撤权。冲突不得清除待决、撤权、取消别的队列或写成功行动日志。启动准备和 until-done 子回合之间的空隙也属于该驱动器；引擎登记前必须检查取消及所有权，旧执行收尾不得删除新执行的注册项。

- 活目标缺少身份返回稳定的 `execution_identity_required`；身份不匹配返回 `execution_changed`。
- 显式 `null` 代表调用方确实观察到空闲，只在当前仍空闲时成立。缺字段不能悄悄转换成 null。
- “停掉占用者”等异步确认在打开确认框前固定目标和身份；确认完成后不重新读取当前身份替换原值。
- 在途请求与回执按实例、会话和执行归属；A 的回包不能改变 B 的反馈，A 的请求不能吞掉对 B 的请求。未知结果不自动重发。
- 所有当前停止入口接线，包括工作台、管家看板/抽屉和工具动作。旧工具缺少身份时明确要求先读取状态，不在执行时补上当前身份。

## 撤回边界

新界面的撤回使用单次受保护的 rewind 请求，由服务端在短期内存门内执行“核验、停止所属执行、等待收尾、回退”。门建立和身份校验之间不让出事件循环；回退期间拒绝同会话新执行登记，异常和正常结束均释放门。等待收尾超时应拒绝回退，不能冒险修改仍可能被写入的数据。

递话撤回与行动流水撤销的身份必须来自那一次 launch 的实际登记事件，与原有回退锚点一同保存；不能在用户点击时查询并套用后来执行的身份。旧撤回记录缺少身份时不提供可误操作新执行的撤销，不猜测。整单回退在确认框打开前捕获身份。旧直接 rewind API 与工作台逐消息回溯保留兼容路径：自动停止只针对异步读盘前观察到的执行，但不具备新管家入口的完整确认期与准入保护；本批不将所有历史回溯入口宣称为事务化。

已完成回合仍可凭最后一次登记身份撤回；同线程一旦登记过新的执行，旧身份失效，即使新执行也已完成。证据只保存在有界内存表中，重启或淘汰后拒绝缺少依据的旧撤回。空闲确认另外绑定读到的 `turnSeq`、`rewindGen` 和 `executionObservation`（实例、最后登记执行、淘汰代际）：门建立时核验执行观察，持门读盘后再核验历史水位。由此覆盖“打开确认时空闲 → B 启动并完成 → 点击确认时又空闲”，包括 B 没有推进历史水位的情形；表淘汰导致的保守冲突由重新读取解决。

## 全局故障与读取质量

`missionRunDigest` 输出有界健康事实：持久化异常、运行或节点空闲中止、活动资源阻塞数量及定位 ID；不携带工具正文、完整 blockers 或错误堆栈。前端复用上一批 `run-health` 判据，分别适配完整运行与摘要。新增 `healthRuns` 汇总最新历史运行与全部活动运行，避免一个较新的健康运行遮住仍在活动的异常运行；不顺带更改原 `lastRun` 或五态规则。

持久索引只保存历史事实，身份与活动健康来自实时叠加；清册版本迁移补齐旧缓存。ETag 必须覆盖输出中的执行身份和健康字段，即便 `status/eventSeq/updatedAt` 不变，异常出现或清除也不能错误返回 304。健康变化使用现有 `thread.state` 通道通知，两个方向对称刷新，不新增轮询器。

看板与抽屉保留上次成功的任务、待决与验收事实，并独立显示读取失败。缺失、畸形响应及首次读取失败不能伪装成空列表；有效成功空响应才允许清空。每个读面以请求序号、打开代际和服务代际拦截迟到结果，覆盖同线程乱序及 A→B→A 切换。

SSE 的 `presence.ack` 带 `serverInstanceId`。连接成功不等于权威数据已经重取；新实例使旧条件缓存和旧请求失效，重取看板、仲裁、详情及可见运行监控。复用唯一 SSE 连接与原刷新出口，保留同实例重放去重。服务更换后旧响应不能回填刚清掉的条件缓存。

## 验收门

1. 真实 HTTP 行为：旧身份、缺身份、显式 idle、新执行、重启、队列替换及排队移交；拒绝路径不得改变进程、待决、授权和行动日志。启动窗口取消后不得调用 provider 或启动 CLI；B 已登记而 A 尚在引擎表时不能错杀 A。
2. 安全撤回：旧锚点、活动与已完成回合、停止/收尾期间新执行、超时和错误释放；无成功回执不得宣称撤回完成。
3. 故障证据：完整运行、HTTP 摘要、看板和详情的差分；多故障并存、较早活动异常不被遮蔽、同状态异常出现与恢复、ETag 与持久索引边界。
4. 真实页面：同端口服务重启、页面不 reload、鉴权自愈及权威重取；释放旧进程延迟响应后不回滚。确认框期间换执行、A 回包迟到与 B 点击、读取失败/恢复、键盘焦点、草稿及选择保留。
5. 中英、明暗与 1440/768/390 宽度截图及可见性检查；沿用现有视觉，不重新设计壳。按照 `frontend-design` 技能检查实际渲染。
6. Node 24 语法、构建、全量单元、静态、相关行为 e2e 和生成清册；直接启动的 e2e 串行。记录首跑失败与修正复验，不把未运行的全量或发布包检查写成已通过。

## 实施和验收记录

主会话负责设计、代码复核和独立运行验收；功能及测试由三条 `gpt-6.1-sol` 子 agent 实现。真实模型调用不是本批确定性竞态验收的必要条件，没有新增模型调用，也未修改用户配置的 DeepSeek/Qwen 端点。

### 评审发现和修正

- 撤回身份冲突原先被通用错误包装改成 `api.request_failed`，真实 HTTP 首跑 11 项中 4 项因此失败。改用稳定错误信封，保留拒绝后的原任务与落盘断言，扩展后 17 项全过。
- 断线取消保留会话授权；同一执行随后被用户显式停止时仍须撤权一次，不能被通用取消标志吞掉。旧 Kimi owner 的收尾也不能清理新 owner 的待决。
- 空闲确认不能只比较当前 `execution === null`，补入运行期观察和持久历史水位；等回合号的两份对象也不能只比较 `turnSeq`。实际临时文件探针复现 B 已保存后旧 A 的同号首存覆盖 B；现在三引擎首存前检查所有权，保存队列内再次比较调用方捕获的 owner。仍属当前 owner 的正常停止收尾可落盘，旧 owner 的保存不刷新索引或发出新完成事实。物理保存用例覆盖 B 活动及已完成、A 排队后换 owner、正常停止与历史调用兼容。
- SSE 换实例时只递增读代际还不够：旧请求如果一直不返回，会占着原刷新合并器。合并器现在按代际归属，旧请求既不能阻止新读，也不能在 finally 中释放新请求的占位。停止回执同样拒绝旧实例回包，并按执行隔离新任务的反馈。
- 补齐管家行动流水的撤销入口；旧记录缺少执行身份只显示详情。工作台逐消息回溯的兼容边界如上，不宣称所有历史入口均已改造。

主会话独立运行 `steward-global-health.browser.e2e.js`，31 项通过：同一真实页面在相同端口和数据根上的进程重启、旧 token 自动更新、无 reload 的权威重取、暂未验证的重启提示、旧进程迟到响应不能复活待决；失败、恢复与重启过程中保留输入节点、草稿、焦点及选区。1440 浅色中文、768/390 深色英文均检查提示实际可见与视口边界，主会话审阅截图。

健康证据分层记录：页面通过生产 HTTP 读取合法隔离历史运行，网络拦截只注入失败和延迟；这不是实际操作系统写盘失败的完整触发链。生产函数单测另外覆盖完整运行与有界摘要的差分、最新历史与全部活动故障、仅内存健康变化的 ETag、相同业务状态下异常出现与恢复的事件通知。可见监控在换实例后完整读取，隐藏监控留待下次可见时完整读取，旧摘要不覆盖新事实。
