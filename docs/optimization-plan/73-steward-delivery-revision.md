## 交付行为

- 管家原文卡和收件箱都在明确的 `sessionId + turnSeq` 内挑选正文。找不到该轮时不取最后一条助手话代替；只有文件没有叙述的回合也能显示产物入口。卡头反映任务当前状态，交付正文保持原轮身份。
- 「打开产物」展开本轮文件，再点文件名打开预览，最多两次操作。文件取现有 `artifacts/filesChanged` 并按绝对路径去重；同名文件展示完整路径。文本、图片、HTML 沿用现有预览器和沙箱；PDF／Office 等文档通过现有本机打开接口，带来源任务身份。未知文件类型不直接交给系统执行。
- 「查看检查」使用既有验收投影，区分机器通过、机器失败、本人确认、模型自报、尚未完成和未记录。机器或人工证据还须在本轮产生、文件指纹未变、当前没有执行且尚未进入新一轮，才适用于该轮文件。旧检查可查，不能替代新要求的验证。
- 「继续修改」只准备目标和草稿，不自动发送，也不覆盖已有草稿、附件、目标或录音。发送仍用已有递话、权限、回执、去重及重试路径；原话逐字保存。消息 `meta.revisionOf` 保存任务、回合、来源戳和文件引用，交给执行模型作为来源资料。
- 修订只进入原任务的新回合；忙碌、排队和待决时整次拒绝。工具入口及驱动启动边界均核对来源、工作区、文件和期望回合；来源消失或版本变化时拒绝并保留原话。成功后当前页面立即提示旧交付，刷新也能看到同样关系。

## 数据与兼容边界

旧回合摘要只有路径和变更计数，不能证明交付时的文件字节或当时检查。因此在既有 `turnSummary` 内增加可选的 `deliveryEvidence`，保存文件 SHA-256 和已有验收投影快照；不新建成果平台、验收账本或独立修订身份。修订目标取任务身份、明确回合、来源内容戳和期望当前回合，未使用 `updatedAt` 冒充版本。

- 每轮最多 20 个文件、每文件 8 MiB、合计读取 32 MiB、50 条检查。超限标记未核验／截断，不颁发指纹；预览保留既有限额。捕获失败不阻断正常回合，也不能获得通过章。关闭管家时跳过新增捕获。
- provider 与 CLI 回合收尾调用同一个迟绑定入口；新模块在既有依赖环外。只读 API 必须有工作台 token，禁止缓存，复用工作区、UNC、敏感内部路径和硬链接保护。读取时检查文件前后状态，预览使用已核验的同一份有界字节。
- 旧数据、导入数据和捕获失败不补造历史证据，也不借当前事项检查充数。「刷新文件状态」只重新核对字节，不重新执行机器验收。卡片保存收尾时的证据；交付后在其他入口补做的确认不会重写原轮快照，可到原任务核对或在新回合重新验证。没有检查的修订仍显示未验证。
- 新字段随原会话保存，可选读取，未迁移存量数据；回退旧源码会忽略这些元数据。修订去重仍受 70 号进程内有界回执期限约束，未增加服务重启后持久去重承诺。
