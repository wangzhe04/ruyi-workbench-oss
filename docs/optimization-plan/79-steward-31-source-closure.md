## 路由修正及模型证据

稳定提示原有两条规则冲突：用户明确授权应直接办，另一条又要求没调工具时一律只给 `acts` 按钮。现要求参数齐全、权限允许时实际调用或列入 `actions`；只有真实回执才能报告完成，缺权限、确认及 `propose_required` 仍给提议。明确新任务由执行线程先读后改，不凭相似标题接旧任务。递话和新任务的 `brief.userText` 要保留整条原话，含前缀、路径、数字与换行。

没有修改执行、授权或污染门。中文稳定层 1162 token、英文 1248 token，原门限 1250 不变；普通包文本没改，版本仍为 `2026-w138-2`。`steward-read-routing.e2e.js` 经生产 HTTP 和工具循环验证直接读取、真实开任务、缺参数、英文、SSRF 和读后写提议；编辑任务新增前缀及换行的真实落盘保真断言。

本机 `deepseek-flash`、chat 协议、43 工具、temperature=0，固定五类题各两轮、旧新配对次序交替，每批 20 次、每次输出上限 768 token、60 秒、无重试，只评首响应、不执行工具：

| 批次 | 冻结基线 256f0cc3 | 候选 | 决策 |
|---|---:|---:|---|
| 初版冲突与保真措辞 | 6/10 | 6/10 | 没有收益，不据此宣称改善 |
| 补齐新任务路由规则 | 6/10 | 8/10 | 编辑题两次直接开任务并保留整条原话；采用该规则 |

两批 unknown 均为零。报告题两个首响应仍先读取材料/查状态，未改善；首响应不能判定整段报告任务成功或失败。这里的 8/10 也不代表普遍语义质量。64 号历史模型、42 工具、10 请求批次独立保留，不混算。

`steward-routing-live.js` 可按需复验；只读原配置，密钥仅驻内存和请求头，不写隔离配置，不保存 reasoning。提前认证/模型不可用也保留失败样本并停止后续调用，统一保存中止状态、摘要及原配置 hash。

## 主动记忆工具的范围和失效

发现旧 `list/read` 没有复用会话启用选择。现与入口预检共用 `eligibleMemoryEntries`，同时遵守显式关闭、固定集合、排除、项目锁、有效期和作用域；不改变主动 list 原有词法排序。被用户确认取代的旧记忆标为历史参考，固定集合外的取代者不展开正文或泄漏身份。面板管理仍可读取过期条目用于编辑。

异步读取优先绑定当前活回合的会话，返回前复核选择、工作区、回合、停止、文件版本、自然到期和确认取代关系。版本随元数据读取时固定保存，不从可变缓存追认。没有活回合的独立读取回读磁盘会话；工作台启动的 MCP 子进程通过原 `/api/tools` 回到父进程，以原会话和回合绑定，并要求父回合仍存活。模型参数不能替换这些身份。

普通 provider 循环在预算前及每次真实发送前检查原注入条目的版本和关系，发送构造时再同步核对选择与到期。选择、删除、修订或关系变化后，丢弃整份入口旧快照；回执标为当前 disabled 或未完成预检（`checked=false`），旧匹配计数清零，不冒充做过新检索。没有入口记忆时不增加目录检索。只在新请求副本中失效，不改写已发送请求或持久历史，不追加新主题、不伪造用户或工具消息。

## P2 采用决策

先完成基线 16 个旅程并落证据，再冻结采用门：同一个正例两轮均改善、反例错误不增、无任务/采用退步，平均调用数和输入 token 不超过基线 1.5 倍。A 仅试验条件补查提示；B 只在 A 仍有可重复用户插话遗漏时考虑，C 留后续专项。

通过生产 `runSessionTurn`，四类各两份材料、每组两轮，共 32 个旅程：材料读完出现统计口径、日志出现具体组件、读完材料后真正用户插话改环境、无关同词与工具文本诱导。基线与 A 使用相同工作区记忆库、模型配置和任务；插话按对应 `file_read` 的 call/result 配对后经原 steering 入口接纳。

| 读数 | 现状 | A 条件提示 |
|---|---:|---:|
| 数值任务通过 | 16/16 | 16/16 |
| 反例错误 | 0/4 | 0/4 |
| 模型调用总数 | 74 | 74 |
| 输入 token（含缓存） | 1,333,697 | 1,360,691 |
| 其中缓存 token | 1,280,640 | 1,316,736 |
| 单旅程 p50 / p95 | 7,940 / 10,608 ms | 8,194 / 16,676 ms |

所有正例均实际读到对应记忆正文，人工核对最终依据的项目/环境/组件与公式；反例均没有套用错误公式。A 的一条蓝杉答案附带了无关 1.08 税率描述，虽使用正确 1.2 规则，仍保留为依据表述瑕疵，不能把数值正确等同普遍语义准确。该固定合成样本有显式“核对已确认经验”的任务要求，不能代表所有自然任务，也没有跨模型或盲测结论。p95 使用 nearest-rank，样本仅 16。

结论：没有重复遗漏或纠正的稳定改善；调用数相同，输入约增加 2.02%，不采用新增 A 提示。现有主动工具在本批用户插话样本没有遗漏，无需建设 B；不建设 C。普通包记忆指南未改，关闭本切片的机制扩展，同时保留上述正确性修复。

首次试验完成一个基线后，第二题模型调用 Decimal 脚本等待 exec 权限，已终止并清除隔离凭据，不把这批当成完整对照。完整 32 旅程在隔离目录允许本地计算后重新独立运行，原配置逐字节不变；最后发送边界修复由离线竞态测试验证，没有为它重复付费语义批次。可复验脚本为 `memory-adoption-live.js`，无 reasoning 落证据；两份隔离配置均已移除 provider。

脱敏汇总、原始证据文件 SHA-256 与采用决定见 [本机固定样本证据](evidence/steward-31-local-evaluation.json)。原始响应保留本机临时产物，汇总不包含配置、凭据或真实用户材料。

## 独立复核与验证

两名独立 agent 分别复核路由与记忆。路由发现英文预算越界、只读题允许附加写动作的评分漏洞、提前失败丢证据，均已修复，最终无阻断。记忆复核推动修复会话副本、usage await 后失效、关系版本、旧核心快照、错误计数、可变缓存版本与最后发送边界，最终无阻断。

全量截图复查还发现共享侧栏的真实缺口：直接进入工作台只取事项行，仲裁读取状态永远停在 loading。现每个服务代际只初始化一次，沿原读取函数保留序号、失败及旧响应保护，换进程仍走原在场回执；不新增轮询。显式关闭管家时不请求被禁用的仲裁接口，也不投影不适用的故障。真实浏览器保存经典偏好后重载，验证零进入管家即可完成一次仲裁读取；关闭后重载验证零仲裁请求，原故障保留、重启与旧响应验收继续保留。

`memory-active-scope.e2e.js` 的 39 条行为断言通过，包括真正的 HTTP、独立 MCP 进程、生产 provider 请求、工具配对和 hook 等待期间关闭。路由生产链、原核心记忆、provider/CLI 注入和本次要求优先回归通过。语法 1037 文件及构建新鲜度通过；79 模块、573 边、1 SCC，166 路由判定、152 鉴权项，无新告警。

首次 Windows 全量预检因 `steward-read-routing.test.js` 一条旧逐字措辞断言失败而拒跑 e2e。同步双语语义断言，并保留独立调查、按工作而非字数/文件数分流、污染/权限与预算门后，该文件 4/4 通过；重新全量预检 2056 项中 2030 通过、26 跳过、0 失败。第二轮 e2e 的 `prompt-snapshot.static` 两条声明锁仍要求 `const`，现精确改为可失效更新的 `let`，完整预算表达式和压缩/估算调用锁保留，独立复核及单件复验通过。单件 facts 检查另发现英文 README 总数未同步，已修正并复验。

Windows 全量 `run-all.js --parallel 4` 实跑 527 件：509 通过、18 失败、0 known-fail，其中 2 件首跑失败后通过（`permission-plain.browser` 的界面读取、`subagent` 的资源串行时序），收工残留测试浏览器为 0。仓库共 534 件 e2e、7 件 opt-in live 跳过、253 个 unit 文件；README 原默认数重复扣除 live，现按 runner 口径修正。没有把首跑写成全绿。

逐项复查使用原 runner 的 `runOne`，保留隔离目录、超时及浏览器清理，显式串行运行失败清单，每次一发、不隐藏重试。发现并修订的旧测试契约如下，生产安全门和原行为断言保持：

- 工具清单随 `steward_bot_setup` 为 120；两条预算声明现为可失效更新的 `let`。进程清理归属最终仍为 326：新增 MCP 行为测试加一，截图件收编到现有浏览器夹具减一；精确清册通过。
