## 6. M3：无感加密与完整索引的实施设计

### 6.1 先立存储接口，再做迁移

入口为 `01-config.js` 的 `DurableJsonStore` / `runKeyedChain` 现有用法，`01j-local-crypto.js`、`01k-credential-vault.js`、`01l-credential-recovery.js`，以及 `02-session-store.js` 的 load/save/delete、NDJSON提交恢复、写序号及侧栏索引。现有恢复模块仅能借鉴事务方法，**不是完整工作数据迁移器**。

新增受管存储适配边界，按数据族登记读、写、追加、范围读、删除、重建、备份的唯一所有者；不全局包装fs。M3-2是总里程碑，内部按会话→记忆/队列→附件/缓存→备份拆小提交，不要求一提交覆盖全部数据族。第一批对一个会话数据族验证新旧读写，再接记忆、管家、待决、机器人收发箱、任务模板、附件/派生件、索引、journal/缓存和受管备份。浏览器localStorage/IndexedDB/WebView缓存及日志也要列清册；清单未闭合前不得显示“工作数据已全部加密”。

小JSON可整体认证加密；追加日志采用独立认证记录，绑定数据实例、用途、schema、记录ID、作用域和序号；大附件使用有界分块与认证清单，范围读取和整件完整性均验证。沿用成熟AEAD与随机nonce，不自造密码算法。nonce不可复用；格式损坏、错用途/记录、缺块不得吞成空数据。提交标记/日志决定尾写是否可恢复；没有可信外部锚点就不宣称抵抗任意完整旧快照回滚。

存储文件名、标题、路径、URL也可能敏感。持久化最小明文元数据逐字段列白名单，业务内容和可推断原值的缓存不得漏出。对应用内查看优先内存解密；外部编辑器需要明文时使用受限临时租约和可见说明，记录崩溃清理与外部应用/系统缓存边界。不得修改用户工作区原文件来冒充受管数据加密。

### 6.2 密钥与体验合同

当前 `sealLocal/openLocal` 的 purpose 用于AAD校验，仍共用主密钥，不能称已有独立派生密钥。M3-1须先定义版本化envelope及用途隔离：工作数据独立数据密钥/派生域，与凭据密钥有独立引用和生命周期；Windows账户封装用于日常自动解锁，恢复包封装用于明确恢复。选定方案要测试错用途、轮换、旧引用、恢复及关闭组合，不能简单改全局master使已有映射失效。

默认保留用户选择；用户主动开启后，正常启动、聊天、搜索、附件和备份不新增步骤、不每次询问口令。关闭发送保护不解密存储；关闭凭据加密不销毁仍被工作数据引用的包装密钥。未启用且无旧引用时不创建密钥。真实Windows DPAPI验收单列，普通加密fixture不能取代系统封装。

密钥不可用、空间不足、恢复目标冲突及明文导出才需要明确处理；保留原数据且不静默降级明文。不要为“无感”隐瞒旧明文副本或迁移未完成。口令恢复包区分“凭据恢复”和“完整工作数据恢复”，前者现有功能不能被改写成后者。

### 6.3 迁移状态和唯一权威

建议状态：`plain → preparing → ready-to-switch → encrypted`；暂停/失败停留在可恢复准备状态。关闭加密采用反向影子迁移，同样认证校验和切换；不在原文件上逐字节覆盖。状态名称可按现有schema统一，但提交点必须唯一。

准备期旧根是唯一权威；有可靠快照和写入/删除增量追踪时，后台分批生成影子目录，用户继续工作。每个checkpoint绑定源revision，变化的条目重做，删除有tombstone，不能仅复制启动时清单。若尚无可靠追平机制，等空闲再准备并说明，不边复制活动目录边声称一致。

当前只有各数据族的写链、进程所有权和缓存/去抖索引，没有现成的全数据根迁移锁。须新增覆盖全部受管数据族的切换屏障，并复用各自写链与进程所有权：安全空闲边界暂停新写准入，排空inflight、去抖/缓存落盘和后台任务，追平新增/编辑/删除、验证影子与备份后原子提交活动manifest。所有异步writer都校验generation，不能只锁会话链。提交后所有缓存、异步写、索引与备份跟随新generation，迟到旧写拒绝或按新权威重新调度。不开双写权威，不把read cache当切换完成证据。

提交前取消保留旧根并回收自有影子；提交后不能直接退回陈旧旧根，走正式恢复合同。每个切点注入中断、进程死亡、磁盘满、损坏、文件占用和重复启动。错口令不得修改数据；丢key保留原数据并在新根恢复。旧明文备份退休遵循用户选择，保留时显示受管位置，普通删除不称SSD物理擦除。

### 6.4 完整索引与性能门

`06h-retrieval-index.js` 当前 `RETRIEVAL_TEXT_CAP=8192`；侧栏 `02/index` 与 `13e-pretender-index.js` 也是不同用途，不能直接改标签叫全文检索。以 `sessionId + turnSeq + messageId + contentRevision + chunkOrdinal` 建消息分片，保存原坐标和来源，复用本地词法检索；第一版不引入embedding或声称“可搜索加密”。

索引与派生缓存通过同一加密存储接口持久化；分段解密、有界内存查询。删除、回退、编辑、权限变化与源version一致失效；检索命中先读取真实版本、再向目标scope投影。旧会话可分批重建/暂停/恢复，UI显示覆盖率，不把未建部分当没有结果。测试8192之后的尾部、跨分片短语/重叠去重、长消息、附件提取文字和重建期间更新。

在M3-1先测同机明文基线：聊天首响应、追加写、启动、搜索、附件首读、恢复；记录冷/热p50/p95、峰值内存和磁盘。正常路径交互步骤新增数必须为0；持续卡顿不可接受。沿用86的约10%回归调查阈值，具体绝对预算由实测后在实现前冻结；不得把网络等待混入本地延迟掩盖成本。后台迁移限速/可暂停，单独报告准备总耗时与最终切换停顿，不承诺零开销。
