## 5. M2 后续：披露合同与适配器

### 5.1 宿主掌握的最小合同

2026-10-21 M2-3：宿主异步规划先私下核路径接收方，再逐引用授权还原；主/子权限、代理解壳、改参、真实派发及文件提交路径均接复验。22个首批本地适配器范围见[84](84-privacy-tool-transport-and-profiles-31.md)，外部搜索/HTTP/机器人/MCP仍按后续批次适配，Git/任意脚本/网络盘等不继承本地原值许可；普通无引用与off沿用原路径，无新增日常交互。独立审查修复绑定丢失、原子临时文件、junction搜索、移动回滚、探针生命周期及批量排队等问题。单次I/O内去重后仍有必要保护成本：合成100小文件带代号搜索最终源码单次约1.35秒，普通无代号约0.20秒，非DPAPI/统计性能承诺。本批最终源码已独立审查：2532单测中2506过、26条件跳过、0失败，80静态全过；新增三档主/子6场景连续两遍及真实三协议483断言通过，另9件相关E2E402断言通过、1条符号链接条件跳过。最终字节、首次失败、测试及未覆盖项统一见[证据](evidence/privacy-m2-disclosure-contract.json)。

复用现有 scope、策略 signature、任务权限和待决机制。宿主构造 `policyRevision/signature、scopeId、sourceRevision、executionId、recipient、purpose、payloadKind、deadline/cancellation`；字段是语义合同，具体内部类型按现有风格落地。模型只提供业务参数，不能指定已获授权的接收方、scope或原值权限。

接收方包含稳定适配器身份、配置修订、目标服务/账户/租户/会话及用途；具体 URL/参数再由适配器检查。凭据仅注入绑定的认证槽；正文、query、文件名、错误、资源名各有类别。原值恢复只对明确允许的字段和业务操作执行，普通工具注册不等于任意披露授权。 授权裁决放在 `03a-privacy-gateway.js:prepareCall/restoreArgs` 释放原值之前；宿主可私下核真实参数，但不得先沿用registered广泛还原给脚本/服务，再靠HTTP出口或结果过滤补救。未适配脚本/MCP只取得模型副本或被拒；用户业务授权也不能被标成OS隔离。

决策收敛为 `project`（受保护视图）、`allow-bound-original`（特定接收方/用途/字段已授权）、`deny`（不能满足合同）。命名为设计建议，不强迫新增三套执行路径。已有清楚授权可复用；未知目标不能复用本机显示许可。授权变化、重连、重定向、凭据/机器人更换、源变化及取消在实际提交前重验。结果已提交而未知时保留投递状态，不能以脱敏错误触发业务重做。

不新增全局 fetch monkey patch。M2-1 的模型正文入口继续只管模型；认证、搜索、业务HTTP与机器人须理解各自协议。任意脚本或外部 MCP 服务仍可能自行读盘联网：在没有受控边界时不能向其释放原值并宣称内部外发受控。严格CLI已暂缓，这个限制不能靠更多正则消除。

M2-3 施工时沿用 `restoreArgs → scope.restoreForTool` 的逐引用同步授权钩子，在 `entry.value` 替换之前裁决，不再建秘密库。现有 `registered` 只说明工具存在，`paths`/工具 tier 也不能证明无外发；受管 MCP 的 `resolveBridge` 结果应保留宿主确定的 server/tool/配置身份，而非只传布尔值。明确本地结构化适配器继续支持授权字段的精确还原；代号路径须先由宿主私下解析并核实真实目的地，不能先还原整个参数树交给 handler 再问。UNC、网络盘、链接以及文档外部资源不能仅按“文件工具”归为本地。

可分为合同/纯决策及首批适配器两片审查，但未接强制裁决的通路保持未完成；不新增长期 `legacy=true` 原值放行兜底，也不提交无人使用的平行授权接口。首批覆盖确定性本地文件操作和未知脚本/MCP拒绝负例；后续搜索、HTTP、机器人和MCP按各批接线。权限等待结束、实际派发前重验策略及适配器/接收方版本；模型提供的 `registered/recipient/permission` 不能构造宿主授权。现行83/84与transport单测中的“全注册工具任意字段还原”须按86新合同同步更新，保留嵌套/key碰撞、跨scope、代理、权限与不重放断言，不能只删除旧正例。

## 6. M3：无感加密与完整索引的实施设计

### 6.1 先立存储接口，再做迁移

入口为 `01-config.js` 的 `DurableJsonStore` / `runKeyedChain` 现有用法，`01j-local-crypto.js`、`01k-credential-vault.js`、`01l-credential-recovery.js`，以及 `02-session-store.js` 的 load/save/delete、NDJSON提交恢复、写序号及侧栏索引。现有恢复模块仅能借鉴事务方法，**不是完整工作数据迁移器**。

新增受管存储适配边界，按数据族登记读、写、追加、范围读、删除、重建、备份的唯一所有者；不全局包装fs。M3-2是总里程碑，内部按会话→记忆/队列→附件/缓存→备份拆小提交，不要求一提交覆盖全部数据族。第一批对一个会话数据族验证新旧读写，再接记忆、管家、待决、机器人收发箱、任务模板、附件/派生件、索引、journal/缓存和受管备份。浏览器localStorage/IndexedDB/WebView缓存及日志也要列清册；清单未闭合前不得显示“工作数据已全部加密”。

小JSON可整体认证加密；追加日志采用独立认证记录，绑定数据实例、用途、schema、记录ID、作用域和序号；大附件使用有界分块与认证清单，范围读取和整件完整性均验证。沿用成熟AEAD与随机nonce，不自造密码算法。nonce不可复用；格式损坏、错用途/记录、缺块不得吞成空数据。提交标记/日志决定尾写是否可恢复；没有可信外部锚点就不宣称抵抗任意完整旧快照回滚。

存储文件名、标题、路径、URL也可能敏感。持久化最小明文元数据逐字段列白名单，业务内容和可推断原值的缓存不得漏出。对应用内查看优先内存解密；外部编辑器需要明文时使用受限临时租约和可见说明，记录崩溃清理与外部应用/系统缓存边界。不得修改用户工作区原文件来冒充受管数据加密。

### 6.2 密钥与体验合同

当前 `sealLocal/openLocal` 的 purpose 用于AAD校验，仍共用主密钥，不能称已有独立派生密钥。M3-1须先定义版本化envelope及用途隔离：工作数据独立数据密钥/派生域，与凭据密钥有独立引用和生命周期；Windows账户封装用于日常自动解锁，恢复包封装用于明确恢复。选定方案要测试错用途、轮换、旧引用、恢复及关闭组合，不能简单改全局master使已有映射失效。

默认保留用户选择；用户主动开启后，正常启动、聊天、搜索、附件和备份不新增步骤、不每次询问口令。关闭发送保护不解密存储；关闭凭据加密不销毁仍被工作数据引用的包装密钥。未启用且无旧引用时不创建密钥。真实Windows DPAPI验收单列，普通加密fixture不能取代系统封装。

密钥不可用、空间不足、恢复目标冲突及明文导出才需要明确处理；保留原数据且不静默降级明文。不要为“无感”隐瞒旧明文副本或迁移未完成。口令恢复包区分“凭据恢复”和“完整工作数据恢复”，前者现有功能不能被改写成后者。

### 6.3 迁移状态和唯一权威

建议状态：`plain → preparing → ready-to-switch → encrypted`；暂停/失败停留在可恢复准备状态。关闭加密采用反向影子迁移，同样认证校验和切换；不在原文件上逐字节覆盖。状态名称可按现有schema统一，但提交点必须唯一。

准备期旧根是唯一权威；有可靠快照和写入/删除增量追踪时，后台分批生成影子目录，用户继续工作。每个checkpoint绑定源revision，变化的条目重做，删除有tombstone，不能仅复制启动时清单。若尚无可靠追平机制，等空闲再准备并说明，不边复制活动目录边声称一致。

当前只有各数据族的写链、进程所有权和缓存/去抖索引，没有现成的全数据根迁移锁。须新增覆盖全部受管数据族的切换屏障，并复用各自写链与进程所有权：安全空闲边界暂停新写准入，排空inflight、去抖/缓存落盘和后台任务，追平新增/编辑/删除、验证影子与备份后原子提交活动manifest。所有异步writer都校验generation，不能只锁会话链。提交后所有缓存、异步写、索引与备份跟随新generation，迟到旧写拒绝或按新权威重新调度。不开双写权威，不把read cache当切换完成证据。

提交前取消保留旧根并回收自有影子；提交后不能直接退回陈旧旧根，走正式恢复合同。每个切点注入中断、进程死亡、磁盘满、损坏、文件占用和重复启动。错口令不得修改数据；丢key保留原数据并在新根恢复。旧明文备份退休遵循用户选择，保留时显示受管位置，普通删除不称SSD物理擦除。

### 6.4 完整索引与性能门

`06h-retrieval-index.js` 当前 `RETRIEVAL_TEXT_CAP=8192`；侧栏 `02/index` 与 `13e-pretender-index.js` 也是不同用途，不能直接改标签叫全文检索。以 `sessionId + turnSeq + messageId + contentRevision + chunkOrdinal` 建消息分片，保存原坐标和来源，复用本地词法检索；第一版不引入embedding或声称“可搜索加密”。

索引与派生缓存通过同一加密存储接口持久化；分段解密、有界内存查询。删除、回退、编辑、权限变化与源version一致失效；检索命中先读取真实版本、再向目标scope投影。旧会话可分批重建/暂停/恢复，UI显示覆盖率，不把未建部分当没有结果。测试8192之后的尾部、跨分片短语/重叠去重、长消息、附件提取文字和重建期间更新。

在M3-1先测同机明文基线：聊天首响应、追加写、启动、搜索、附件首读、恢复；记录冷/热p50/p95、峰值内存和磁盘。正常路径交互步骤新增数必须为0；持续卡顿不可接受。沿用86的约10%回归调查阈值，具体绝对预算由实测后在实现前冻结；不得把网络等待混入本地延迟掩盖成本。后台迁移限速/可暂停，单独报告准备总耗时与最终切换停顿，不承诺零开销。

## 7. M4：媒体按实际发送字节交付

现有图片原型在 `dev-harness/privacy-m1/media/`，Full Python3.12/Pillow/WinSDK OCR只是限定实证。生产入口包括 `13b-api-domain-routes.js:maybeOcrImageAttachment/maybeCompressImageAttachment` 与附件上传，`11d-media-inspection.js` 的FFmpeg/ffprobe/Python探测只是依赖基础。不要把OCR文字替换等同于图片像素已处理。

M4-0列每个组件的版本、离线来源、可分发许可、hash、语言/格式支持及资源预算；Full/Slim缺组件时均明确显示能力，不能临时下载或云端原文兜底。文档渲染与视频提取依赖尚需实测冻结，遇到复杂成本回报方案，不自行删除范围。

| 批次 | 生产合同与验收 |
|---|---|
| 图片 | 原件只本地存储；OCR坐标变换、显式区域和识别范围覆盖实际像素；重新编码并去EXIF/XMP/缩略图及敏感文件名；预览就是待发送派生件，网络捕获原件零次、派生hash一致 |
| PDF/Office | 先提取文字/批注/修订/隐藏层/嵌入物/元数据；默认提供受保护文字；需要视觉则渲染并遮盖后生成新载荷，不直接传原容器或只画黑框留底层文字 |
| 视频 | 本地画面信息转受保护文字或已处理静帧；明确静帧覆盖范围，稀疏抽帧不等于整个视频已匿名化；原视频及音轨不发，ASR不实施 |

派生件绑定源hash、源revision、策略/规则版本、处理器版本、载荷hash与有效期；源/规则/区域变化作废，缓存不串scope。提交前再次核当前策略和派生来源；取消/超时/源替换/损坏/超限不得回退原件。压缩、旋转、缩放、多语言、动画多帧和边缘文本逐项验；二维码/条码须本地解码后按内容判断，头像/手写签名保留显式区域处理，不能借支持矩阵把86中的这两项整体删掉。PDF/Office加入压缩包内关系、附件/嵌入物、批注修订与字体渲染失败负例；视频加入时间轴、字幕、元数据和短暂敏感帧，确认实际交付静帧与文字全部经过保护，同时说明未采样画面不在结论内。OCR未命中不称安全。

自动可验证结果按既有选择发送，不要求每张图都确认；低置信度或扩大披露时才请求处理。主要测试复用 `media/mapping.test.js`、`media/media.e2e.js`、`privacy-channels.e2e.js`、`native-media-boundaries.e2e.js`，再增加生产接线与真实本机接收端证据。
