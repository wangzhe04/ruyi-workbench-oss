# 事项待决清单与逐项处理

日期：2026-10-18。基线 `17785587`，实施分支 `codex/steward-3x-implementation`。承接 [62 号方案](62-steward-3x-iterations.md) 第五轮前两片，源码尚未发布。

## 用户旅程

管家头部的「事项待决」打开一张清单，按现有 `missionId` 归组。未挂事项的任务以自身身份分组；事项同名时保留不同组，问题同文时保留不同条目。折叠行显示待决类型、摘要、来源任务和身份尾段；展开后显示具体影响、原任务入口及当前可用的逐项操作。

- 权限：显示本次工具参数，只允许或拒绝这一条，不设置长期工具豁免。
- 提问：按原问题与选项 ID 填答，所有问题都要有答案，不预选、不把不同待决合并成一个回答。
- 计划：显示完整计划，批准或拒绝这一条。计划全文保留在已有运行时登记项，不新增持久化账本。
- 任务池／重规划提议：有完整运行时资料时展示原提议供逐项决定；完整资料缺失或超过展示限额时，不在这里提供批准，可打开原任务进一步核对。
- 已处理项保留自己的回执。网络或回包未知不说成功，不自动重发；「核对回执」只读原日志，不发决定。其他入口已经拒绝、回答、批准或过期的项都不再提供旧操作。

清单使用现有模态原语处理关闭、键盘和焦点；关清单只是收起，不算决定。在同页刷新清单、切换语言或短暂读取失败时，已填写的回答保持。读取失败或索引不完整时保留旧快照并禁用决定，成功刷新后才恢复。失败和未确认回执在折叠行也直接可见。每次只展开一项；其来源接入现有 viewing 信号，仍受页面可见、窗口焦点与用户活动判定以及既有最多 8 条的上限约束；被模态遮住的小窗与焦点栏不挤占这条来源。

## 权威与恢复

继续使用 `GET /api/interventions` 的现有投影及分页；仅 `view=steward` 补充事项标题和有界具体资料，普通读取形状保持兼容，ETag 区分视图。每次最多装入 500 项，超出明确提示；历史回执最多另留 100 项。完整资料展示上限 32000 字符，超限不提供批准。接收决定的消费者不可用时不宣称可送达。

每条决定直接调用现有 `POST /api/missions/:sourceSessionId/interventions/:interventionId/decision`，携带读取到的 `expectedVersion` 和这次提交独有的 `idempotencyKey`。事项归组只用于展示；命令仍作用于该待决的来源任务，复用已有类型校验、CAS、先写 applying 再投递、终态记录与审计。没有增加通用决定平台或服务器回执账本。

提交前在浏览器 sessionStorage 缓存至多 100 条、24 小时内的回执定位信息，只含来源、动作、版本、请求身份和时间，不保存答案或工具参数。处理中整页刷新后，以这些定位信息读取原待决日志，恢复原状态；不会重投。权威日志仍为 pending 或 applying 时保留「未确认」，不能据此静默恢复相反操作。缓存不可用时只能保证当页核对；清空浏览器数据或超过缓存限额后，可从原任务查看记录。

服务换进程会立即使旧清单不可操作，并推进读取代数，丢弃迟到旧响应后重取新快照。清单仅在打开时订阅相关事件触发重读，没有新增定时轮询。原有通知、在场门、审批超时和已有小窗队列继续由原实现管理。
