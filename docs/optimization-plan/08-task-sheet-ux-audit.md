## 0. 一句话结论

任务单的**数据基础是好的**（五态权威派生、速报不猜文本、收工/停工卡、回来摘要可溯源），问题集中在**组织与呈现**：低频控制区占据首屏黄金位、默认镜头与任务状态脱钩、同一数据三四处重复计数、页脚最强调的按钮是「离开交办台」；状态反馈侧，**最高频的单 agent 回合恰恰反馈最稀薄**（全程只有「工作中」三个字），进度「3/7」不可解释，「已停工」一桶装三种原因。用户感受的「不满意」是结构性的，**建议第100波走重构方案（方案 B），不只是重排**。

## 1. 现状结构（走查事实）

任务单 DOM 序（`ensureTaskSheet`，preview-shell.js:2364-2513）：

```
① 头部        五态 pill + 标题 + 目标 + 现场速报(一句话) + 进度细行(x/y) + metrics(回合/tokens/成本/Run)
② 控制台      常驻工具条:暂停/继续/接管 + 停止/重试 + 遥测 chips(autoMode/回合/活Run)   ← renderMissionControl:2213
③ 回来摘要    条件出现(有未读变化且非 done)                                          ← renderReturnSummary:2917
④ 停工卡      条件出现(result.status=stopped)                                       ← renderStopCard:2622
⑤ 收工卡      条件出现(result.status=complete,含报告/facts/产物/历史轮次/操作)          ← renderFinishCard:2664
⑥ 过程详情    <details open> 默认展开:镜头切换(现场纪要|班组工序|原始记录) + 台账       ← 2453-2457
⑦ 底部        续办工作区 + 页脚按钮(回首页 / 在经典模式打开[primary] / 刷新)
```

镜头机制（`renderLensSwitch`:2176-2211）：三镜头互斥 tab，默认固定 `narrative`（:193，进单重置 :881）；班组镜头无 run 时禁用；**台账不在 tab 内**，挂在过程详情底部；intake 侧栏（待决/成果/台账面板）只在原始镜头内存在（:2442-2447）。

状态派生（mission-state.js）：五态 + 速问逃生舱，全部从权威字段派生，优先级 `needs_you > done > running > dispatching > stopped`（:51-61）。现场速报（`activityBrief`:2522-2540）：待决 > 班组当前工序 > 活回合 > 五态兜底词。

## 2. 问题清单 A：任务单信息架构

|---|---|---|---|
| A1 | **P0** | 首屏黄金位被低频控制区占据：「暂停/继续/接管/停止/重试」是低频动作，却常驻头部与结果卡之间；用户打开任务单第一眼看到的是操作台而非「这单现在怎样了」 | :2399-2401 固定 section；:2510 DOM 序 |

## 4. 每条的建议修法与验收标准（第100波候选范围）

### B1｜现场速报 v2（P0，两方案共有）
- **修法**：速报数据源扩展到权威事件流——单 agent 回合显示「当前动作（最近 tool_use 人话化）+ 本回合已耗时」；有班组时维持队员工序句；待决优先不变。仍不读 assistant 文本。
- **验收**：构造无 run 的单 agent 任务，回合中速报呈动作级文案且每分钟刷新耗时；e2e 断言速报内容来自事件流字段而非 assistant 文本。

### B2｜可解释进度（P0，两方案共有）
- **修法**：进度细行可展开为里程碑/验收项清单（每项 done/pending + 描述），当前进行中项高亮；数据源统一为 snapshot.acceptance（卡片态兜底保留）。
- **验收**：展开清单与 `mission_update` 账本逐项一致；e2e 覆盖 0 项/部分/全完三态。

### A1+A5｜控制区收敛 + 页脚去「逃离」（P0/P1）
- **修法**：控制台从常驻 section 收敛为头部内联紧凑行（图标钮 + 状态色），或折入「管理此单」二级；页脚「在经典模式打开」降为非 primary，主按钮按状态派生（running→续办输入聚焦，done→回首页/归档）。
- **验收**：首屏（1280×800）无需滚动可见：五态+速报+进度+结果卡；经典入口仍一键可达（R7 专家迁移不退化）。

### A2+A6｜默认呈现按状态派生（P0/P1）
- **修法**：进单默认镜头与过程区开合按五态派生——needs_you→待决入口前置；running→过程展开+现场镜头；done→过程收起+收工卡置顶；stopped→停工卡+恢复引导前置。
- **验收**：五态各构造一单，首屏结构快照断言（DOM 冒烟）；默认镜头派生表成文。

### A3｜镜头体系（P0，方案 A/B 分叉点）
- 方案 A（渐进）：台账升入 tab 体系成第四镜头；intake 面板抽为常驻侧栏。
- 方案 B（重构）：现场镜头 = 纪要+班组融合单时间线（班组工序作为时间线上的段落），原始记录保持独立，台账入原始记录侧。
- **验收**（共有）：关键信息两击内可达；切镜头不丢阅读位置。

### A4｜同源计数去重（P1）
- **修法**：每类数字保留一个权威呈现位（验收进度→进度展开清单；产物→收工卡/intake 一处；tokens/成本→头部 metrics），其余位置删除或改为跳转锚。
- **验收**：同屏同数字出现 ≤2 处；数字口径单一来源。

### B3/B4/B5｜状态细分与耗时（P1）
- **修法**：stopped 附加原因副文案（budgetExhausted/用户停/supervised 待命，sources 已有）；dispatching 显示「正在立项…」活指示；metrics 增加已运行时长（自首回合起）；遥测 chips 加 title 解释。
- **验收**：三种 stopped 原因各有专属文案的 e2e；时长每秒刷新且不计入渲染防抖问题。

### B6/B7/A7｜角标与汇聚（P2）
- 坞 seal 加待决角标（pending>0 时计数）；警示统一汇入头部速报区色调；intake 常驻化随 A3 解决。

## 5. preview-shell.js 架构摸底（走查附带，第100波前置）
