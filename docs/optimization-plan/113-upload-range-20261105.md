# 113 · 附件下载 Range 支持（2026-11-05）

本片让现有附件下载路由支持单区间 Range（206/416），这是 107 设计里“密封附件范围读取”的前置 HTTP 语义。
OFF 模式的用户立刻受益（大附件可续传），ON 模式接 `01ag` 时可以直接复用这套响应头。版本仍 **3.0.1**。

## 行为

- `GET /api/upload/content?id&name`：无 `Range` 时与以前一致返回 200 全量，新增 `accept-ranges: bytes`。
- 单区间：
  - `bytes=10-19` → 206 + `content-range: bytes 10-19/1000`，只返回该区间；
  - `bytes=990-` → 末端按文件大小夹紧；
  - `bytes=-5` → 返回尾部 5 字节；
  - `bytes=2000-`（起点越界）、`bytes=5-1`（反向）→ **416** + `content-range: bytes */size`；
  - 多区间/未知单位不悄悄返回整文件，同样按 416 处理（RFC 9110 的 range-unit 大小写不敏感，
    这里刻意按“无法安全满足就拒绝”处理，浏览器实际发送小写 `bytes=）。
- token 门、basename 校验、词法 + realpath 包含校验全部保持不变；只有通过后才读字节。

## 验证

- 新增 `dev-harness/upload-range.e2e.js`（真实 HTTP，临时 HOME/数据根，独立端口）：13 项断言全 PASS
  —— bootstrap 取 token、上传 1000 字节、全量下载、显式区间（含 content-length）、尾部区间、末端夹紧、
  越界 416、反向 416、**0 字节附件任何 Range 都 416（`bytes */0`）**、未知单位 416、无 token 403。
- 既有相关 e2e 未改动；`build` 114611 行，`--check` 新鲜。
- 生成物：`facts` 629 e2e / 453 unit，两份 README 的 e2e 计数与默认回归数同步（622 + 7 live）。

## 边界与下一步

- 本片只改 HTTP 语义，没有任何密封读写接线；ON 模式的上传/下载仍走旧路径。
- 下一步：上传路由 ON 模式改用 `01ak` 门面封存；下载路由在 catalog 命中 `sealed` 时用 `01ag.readRange`
  复用本片的 206/416 语义；随后工具图片与迁移 codec。
