# 平台架构与实现纪律

P0 已完成路线验证；具体字段、默认值与开放项以 [P0 决策与平台接口契约 v1](11-P0-DECISIONS.md) 为准。以下接口仍需 P1–P5 接入产品。

## 1. 保留与替换的边界

保留 Provider 协议、会话与检查点格式、管家与工作流领域模型、MCP 协议、权限档和审计链、Web UI。新增平台接口承接系统命令、进程、路径、密钥、宿主和桌面控制；Windows 实现继续保留。后端仍只使用 Node 内建模块，原生能力可由独立、可审计的辅助进程通过结构化 IPC 提供。

建议布局（尚未创建）：后端适配接口放入 `ruyi-workbench/app/src/` 的独立模块，编号和 manifest 顺序按现有规范确定；Mac 宿主及原生 helper 放入 `ruyi-workbench/desktop-macos/`；ACC 内区分共享文件/文档/浏览器工具与 Windows/macOS 桌面后端。不要把新模块拼接顺序交给文件名排序。

| 接口组 | 职责 | 必须保留的语义 |
|---|---|---|
| PlatformCapabilities | OS、架构、依赖、授权与功能状态 | `supported`、`installed`、`authorization`、`ready` 分开，不因文件存在就报可用 |
| ProcessRuntime | 启动命令、运行脚本、常驻 shell、停止自有进程树 | 参数数组、输出上限、超时、中断、子孙清理、工作目录权限 |
| PathPolicy | 工作区、系统路径、链接、卷与大小写判定 | 按真实文件系统身份判断，不能把所有 Mac 路径一律转小写 |
| DesktopIntegration | URL/文件打开、Finder 定位、选择器、编辑器 | 保留危险文件类型限制与工作区边界，不把“打开文件”变成执行任意代码 |
| SecretProtector | protect/unprotect、支持状态、恢复错误 | 密钥不进 argv/日志；失败时不能悄悄落回明文 |
| HostBridge | 通知、窗口、麦克风授权状态、应用退出 | 验证消息类型和来源，仅对本地受信页面开放，不给远程网页通用执行能力 |
| DesktopAutomation | 观察、截图、元素树、鼠标键盘、窗口、OCR | 统一坐标与结果结构，授权缺失时明确不可用，失败不报告动作完成 |

能力状态影响模型工具目录、schema、提示词、Playbook `requires`、前端入口与体检；不能只在执行时返回“仅支持 Windows”。工具名称变化同时检查别名、不可逆动作表、检查点覆盖、权限分级、按需加载与历史回放。

## 2. 几个需要明确的设计决定

**Shell。** 首期提供受控的非登录 shell 和常驻命令会话，统一定义 cwd、env、输出和停止语义；P0 已选择 `/bin/bash --noprofile --norc`，P1 实现并验证协议。不要隐式执行用户 profile 获取环境。完整终端仿真、TTY 交互式全屏程序不在首期范围；遇到依赖 TTY 的程序给出明确错误。PowerShell 仅作为 Windows 默认或用户另装 pwsh 的可选能力，不把 `bash` 指向 PowerShell。

**进程。** 创建时登记自有进程/进程组与生命周期。Mac 无 `/proc`，需原生或系统进程信息验证，覆盖超时、中断、父进程先退、子孙派生和 PID 复用。进程组只是治理手段，不是操作系统沙箱；未解决逃逸子进程场景前，不得承诺“任意程序都能完整停止”。

**数据。** 首期继续沿用 `~/.ruyi-workbench` / `RUYI_HOME`，避免同时移动数据根造成额外迁移。宿主缓存可用自己的 Application Support 子目录。Windows 路径需要显式映射，旧 DPAPI 密文不能在 Mac 直接解密；不得自动覆盖旧目录或删除旧包。新平台能力配置应兼容旧配置，回退版本读取规则先写测试。

**Keychain。** 建议在 Keychain 中保存用户级封装密钥，复用 Node 加密记录结构或通过 helper 完成受控加解密；具体方案经 P2 验证后冻结。helper 以受限 stdin/stdout 协议收发，限制输入长度、并发、超时和错误暴露。不要通过 `security ... -w <secret>` 这类含密钥参数的调用代替保护器。开发辅助程序与签名 App 的身份不同，发行签名后必须重新验证访问授权与升级稳定性。

**宿主。** 优先 Swift/AppKit + WKWebView，P0 验证 SSE、上传、Markdown/Mermaid、麦克风、录音格式和本地鉴权。如果验证显示维护成本超出预算，记录证据后改选 Electron/Tauri并重估；不预先并行维护三种宿主。不同宿主不能绕开项目后端零依赖约束。

**TCC。** 系统辅助功能、屏幕录制、麦克风及使用 Apple Events 时的自动化授权，由操作系统和用户决定。实现权限探测、说明与拒绝后的恢复流程；不能靠关闭系统保护绕过。常规 App、helper、Python 进程分别可能涉及权限归属，P0 仅读取当前探针身份下的状态；拟发行身份在 P4/P5 另行验证。

**调度。** 应用内调度保留，首期不承诺电脑睡眠时执行任务。定义唤醒后的错过任务策略、去重和重启恢复；关闭窗口与退出应用语义分开，登录启动应可选。后台服务注册不在未经定义的情况下悄悄启用。

## 3. 工程执行要求

沿用 [CONTRIBUTING.md](../CONTRIBUTING.md)、[CLAUDE.md](../CLAUDE.md) 和 [工程规范](../docs/ENGINEERING-SPEC.md)。用户已提出新增 Mac 支持，因此应更新平台目标说明，而非删除 Windows 约束。

1. 改 `app/src`，由 `node ruyi-workbench/app/build.js` 重建 `server.js`，不手改生成物；符号/路由契约变化后按仓库说明重算相关清单。
2. 一个工作包可以分多个小 PR；新增行为带对应 e2e。静态断言验证结构，真实进程/浏览器/权限行为必须另有运行证据。
3. 不改弱旧安全断言来让 Mac 测试通过；Windows 特有用例按平台分流并加 Mac 对等用例，写清 skip 原因。
4. 所有服务/CLI 测试用仓库 fixture-home 隔离真实家目录和 CLI 配置；真桌面测试使用专用账号/受控应用，避免误触用户工作。
5. [CLAUDE.md](../CLAUDE.md) 明确要求“功能实现后必须安排独立 agent 做 code review”。后续实现交付须记录独立复核的范围、发现、修复与复测。P0 探针已完成独立复核及针对性修复，见 [复核记录](evidence/P0/review.json)。
6. 每个阶段提交前验证构建新鲜度、相关单测/e2e及 Windows 回归；大型全量测试在阶段合并和候选发行时运行，不对纯文档变更重复跑全套。

## 4. 本计划不包含的扩张

不重写模型引擎，不更换整个前端框架，不复制第二套管家逻辑，不承诺 108 个 ACC 工具逐个语义等价，不支持运行任意 Windows 程序，不做远程 Windows 网关、Mac App Store 沙箱发行、完整终端模拟器、通用 Office 宏兼容或外部 toolbox 组件的全面移植。新增这些需求时单独列工单和估算。
