## 3. 命令与测试隔离

以下从仓库根目录执行，使用 Node 24。它们是后续实施者的操作指引，不表示本次已经重跑：

```bash
node dev-harness/syntax-gate.js
node ruyi-workbench/app/build.js --check
node --require ./dev-harness/lib/self-isolate-home.js --test "dev-harness/unit/*.test.js"
node dev-harness/run-all.js --fast
node --require ./dev-harness/lib/self-isolate-home.js dev-harness/<相关用例>.e2e.js
```

直跑 e2e 按仓库约定串行；全量运行用 `run-all.js` 管理并发与隔离。启动 Mac 浏览器前核对 fixture 与 Chrome profile 隔离；更新测试进程回收器后再放开大批进程测试。实弹模型用例需要可用端点/密钥；未具备条件的记录未验收，不打印密钥。

候选发行要运行适用的全量 Node 单测/e2e和 ACC smoke，并单列所有 skip；`539 e2e / 278 unit 文件 / 25 ACC smoke` 只是审计基线数量，实施后以实际清单为准。桌面授权不适合仅用无界面 CI 验收，需有人机交互的 Mac 真机证据。

## 4. 发行阻断条件

以下任意一项存在则不能发布相应能力：任务停止后残留可执行写操作的自有子进程；工作区/系统路径绕过；凭据暴露或无声明文回退；数据迁移损坏；操作错误窗口；权限拒绝时崩溃/假报成功；无 Mac 实现却广告可用；Full 离线包首次运行仍强制联网下载依赖。

允许暂不支持的功能必须从能力目录、界面与发行说明一致标注，不能仅把测试标记 skip。发行签名账户未就绪时可以保存可复核候选包，但不能宣称已完成签名公证正式发行。

## 5. 证据格式

每条记录包含：工作包 ID、提交 SHA、OS/架构/Node/Python/CLI/浏览器版本、命令、退出码、通过/失败/skip 数、隔离根目录、异常归因、日志路径、复核者及时间。日志不得包含真实凭据。失败后的临时数据按仓库策略保留用于定位；通过后清理自有进程和夹具。
