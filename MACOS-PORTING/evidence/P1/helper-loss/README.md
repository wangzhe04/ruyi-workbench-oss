# P1 单 helper 故障恢复

2026-11-02，macOS 27.0.1 arm64、Node 24.15.0。基线 `0a430880`，工作树未提交，P1 保持进行中。

## 缺陷与修复

隔离探针强制终止旧 supervisor 后，150ms 内目标 heartbeat 从 1 增长到 14。运行时已报告 incomplete，但目标仍执行。探针目标在 1.5 秒自退出并清理，记录见 `probe.txt`。

新版采用两层原生监督，每个受管执行增加一个守护进程。外层 guardian 在 fork 前建立 session/group 并持续持有组身份，内层 primary 沿用目标启动、私有控制通道和身份观察。两层复用同一个身份冻结、终止与退出确认实现，收集时排除自身与 guardian 锚点。

- primary 消失时，guardian 回收其持有的进程组和自身已观察到的后代。组锚点先于目标执行建立，避免首次扫描前 parent 消失导致同组目标遗漏。
- guardian 消失时，Node 关闭控制通道写侧，仍存活的 primary 读取 EOF 后执行原清理逻辑。故障结果继续标记 incomplete。
- 正常执行等待 primary 退出、guardian 清理和最终 `guardian-cleanup` 帧。两层计数分开保存在结果内，避免重复统计共同观察的身份。guardian 关闭标准流及私有 shell FD4，保留 FD3 至清理结束，目标始终关闭 FD3。
- 协议升至 v2，能力报告要求 `guardian:true`，运行时使用版本化 v2 入口。旧监督入口保留给兼容测试和已有直接调用。
- Node 的 exit 事件可能早于缓冲控制消息到达。退出时立即关闭写侧，最终完整性等待读侧结束后判断。最终 guardian 消息后任何额外帧均拒绝。
